## 二、数据库选型分析

### 2.1 结构化 vs 非结构化数据库对比

| 维度 | 结构化 (PostgreSQL) | 非结构化 (MongoDB) |
|------|---------------------|---------------------|
| **题目内容存储** | JSONB字段存储富文本内容块，支持索引查询 | 文档直接存储，更灵活 |
| **关系复杂性** | 试卷-部分-题目-选项有明确层级关系，适合关系模型 | 可内嵌文档，但查询复杂关系较麻烦 |
| **查询需求** | 需要按标签、年份、题型等多维度筛选 | 灵活查询，但复杂聚合性能较低 |
| **事务需求** | 答题记录需要强一致性 | 最终一致性即可 |
| **团队熟悉度** | 通常更熟悉 | 可能需要额外学习 |
| **MVP阶段** | **推荐** ✅ | 可选 |

### 2.2 推荐方案：PostgreSQL + JSONB

**选择理由：**

1. **混合存储模式**：试卷的元信息（标题、年份、状态）用结构化字段存储，便于查询和索引；题目内容用JSONB存储，保留灵活性
2. **关系完整性**：试卷-部分-题目的层级关系通过外键维护，数据一致性有保障
3. **查询灵活性**：PostgreSQL的JSONB支持复杂查询和索引，如按题目标签筛选
4. **成熟稳定**：MVP阶段选择成熟技术，减少不确定性

**JSONB字段设计：**
```sql
-- 题目内容存储为JSONB，支持富文本块
CREATE TABLE questions (
    id UUID PRIMARY KEY,
    part_id UUID REFERENCES paper_parts(id),
    number INTEGER NOT NULL,
    content JSONB NOT NULL,  -- 富文本内容块数组
    options JSONB NOT NULL,  -- 选项数组
    correct_answer VARCHAR(10),
    explanation TEXT,
    marks INTEGER DEFAULT 1,
    tags JSONB DEFAULT '[]', -- 标签数组
    created_at TIMESTAMP DEFAULT NOW()
);

-- 为JSONB字段创建GIN索引，支持标签查询
CREATE INDEX idx_questions_tags ON questions USING GIN (tags);
```

### 3.2 内容块(Content Block)类型定义

| 类型 | 用途 | 示例 |
|------|------|------|
| `text` | 普通文本 | "The surface area of..." |
| `formula` | 数学/化学公式 | LaTeX字符串 |
| `image` | 图片（几何图、电路图等） | 图片URL + 尺寸 |
| `svg` | SVG矢量图形 | SVG字符串 |
| `break` | 换行 | - |
| `table` | 表格数据 | 行列结构 |

## 七、核心组件设计

### 7.1 题目渲染组件 (Vue 3)

```vue
<!-- QuestionRenderer.vue -->
<template>
  <div class="question-container">
    <!-- 题号 -->
    <div class="question-number">{{ number }}.</div>
    
    <!-- 题目内容 -->
    <div class="question-content">
      <template v-for="(block, index) in content" :key="index">
        <TextBlock v-if="block.type === 'text'" :content="block.value" />
        <FormulaBlock v-else-if="block.type === 'formula'" :latex="block.metadata?.latex" />
        <ImageBlock v-else-if="block.type === 'image'" :src="block.metadata?.imageUrl" />
        <br v-else-if="block.type === 'break" />
      </template>
    </div>
    
    <!-- 选项 -->
    <OptionList 
      :options="options" 
      :selected="selectedAnswer"
      @select="handleSelect"
    />
  </div>
</template>

<script setup lang="ts">
import { computed } from 'vue';
import type { QuestionContent, Option } from '@/types';

interface Props {
  number: number;
  content: QuestionContent[];
  options: Option[];
  selectedAnswer?: string;
}

const props = defineProps<Props>();
const emit = defineEmits<{
  (e: 'select', option: string): void;
}>();

const handleSelect = (label: string) => {
  emit('select', label);
};
</script>
```

### 7.2 公式渲染组件

```vue
<!-- FormulaBlock.vue -->
<template>
  <span class="formula-block" v-html="renderedFormula"></span>
</template>

<script setup lang="ts">
import { computed } from 'vue';
import katex from 'katex';
import 'katex/dist/katex.min.css';

interface Props {
  latex: string;
  displayMode?: boolean;
}

const props = withDefaults(defineProps<Props>(), {
  displayMode: false
});

const renderedFormula = computed(() => {
  try {
    return katex.renderToString(props.latex, {
      throwOnError: false,
      displayMode: props.displayMode
    });
  } catch (e) {
    return `<span class="formula-error">${props.latex}</span>`;
  }
});
</script>
```

## 总结

本方案采用**PostgreSQL+JSONB**的混合存储模式，既保留了关系数据库的结构化优势，又通过JSONB字段提供了存储富文本内容的灵活性。

- **Vue 3**前端配合**KaTeX**实现高质量的公式渲染
- **Node.js**后端提供简洁的API服务
- **Python**解析服务专注PDF处理

三者分工明确，便于快速开发和迭代。
