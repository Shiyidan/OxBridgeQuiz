# 数据库构建方案

> 基于 `api/prisma/schema.prisma` 的实际结构，后续所有数据库结构变更需要更新此文档。

---

## 一、表关系总览

```
Paper ──1:N── Question
Paper ──1:N── ParseTask
Paper ──1:N── ExamRecord ──1:N── AnswerRecord ──N:1── Question
                                                   │
User ──1:N── ExamRecord                            │
User ──1:N── DiagnosticSession                     │
                                                   │
SyllabusNode（平表自引用，parentCode 关联）           │
RevenueCost（独立表，无外键）  ←────────────────────┘
```

**关系要点**：

| 关系 | 说明 |
|------|------|
| Paper 1:N Question | `Question.paperId` → `Paper.id`，cascade delete |
| Paper 1:N ParseTask | 每次上传解析创建一个任务 |
| Paper 1:N ExamRecord | 一份试卷可被多次练习 |
| User 1:N ExamRecord | 一个用户可参与多次考试 |
| ExamRecord 1:N AnswerRecord | 一次答题含逐题明细 |
| AnswerRecord N:1 Question | `AnswerRecord.questionId` → `Question.id`，FK 直接关联 |
| User 1:N DiagnosticSession | 诊断测试记录，支持匿名（userId 可空） |
| SyllabusNode 自引用 | `parentCode` 指向同表另一行的 `code` |

## 二、Paper（试卷）

试卷元信息。题目数据已拆分到 Question 表，`questions` JSON 列为历史遗留，不再使用。

```prisma
model Paper {
  id             String   @id @default(uuid())
  title          String
  code           String?
  year           Int
  duration       Int
  totalQuestions Int      @default(0)
  paperType      String   @default("past")
  pdfUrl         String?
  status         String   @default("draft")
  questions      String   @default("[]")   // 遗留，不再写入
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt

  parseTasks   ParseTask[]
  examRecords  ExamRecord[]
  questionsRel Question[]
}
```

| 字段 | 说明 |
|------|------|
| `paperType` | past=真题套卷 / practice=题库练习卷 / diagnostic=诊断题包 |
| `status` | draft=草稿 / published=已发布 |
| `questions` | 历史 JSON 快照，新写入走 Question 表 |

## 三、Question（试题）

题目独立存储。一道题属于一张试卷（1:N），通过 `paperId` 关联。核心查询字段（`knowledgePoints`、`syllabusPoints`）为独立 JSON 列，展示层字段（`content_blocks`、`images` 等）归入 `meta`。

```prisma
model Question {
  id              String   @id @default(uuid())
  paperId         String
  number          Int
  title           String
  options         String   @default("[]")   // JSON: [{label, text}]
  answer          String   @default("[]")   // JSON: ["A"]
  subject         String?
  subjectCode     String?
  questionType    String?
  difficulty      String?                   // 字符串 或 JSON: {level, score}
  topic           String?
  topicCode       String?
  knowledgePoints String   @default("[]")   // JSON: 知识体系码（如 M5.15）
  syllabusPoints  String   @default("[]")   // JSON: 考纲码（如 113002）
  meta            String   @default("{}")   // JSON: content_blocks, images, skills 等
  createdAt       DateTime @default(now())

  paper         Paper          @relation(fields: [paperId], references: [id], onDelete: Cascade)
  answerRecords AnswerRecord[]
}
```

| 字段 | 说明 |
|------|------|
| `paperId` | FK → Paper，cascade delete |
| `number` | 题号，同一试卷内唯一 |
| `options` / `answer` | JSON 字符串，格式固定 |
| `subjectCode` / `topicCode` | 考纲编码，可用于筛选 |
| `knowledgePoints` | 知识体系码，与 syllabusPoints 属不同编码系统 |
| `syllabusPoints` | 考纲码，试题库按 code 筛选时匹配此字段 |
| `meta` | 展示层数据：content_blocks / images / skills / learning_analysis / generation_profile |

## 四、ParseTask（解析任务）

```prisma
model ParseTask {
  id        String   @id @default(uuid())
  paperId   String
  status    String   @default("pending")
  progress  Int      @default(0)
  error     String?
  result    String?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  paper Paper @relation(fields: [paperId], references: [id], onDelete: Cascade)
}
```

| 字段 | 说明 |
|------|------|
| `status` | pending / processing / completed / failed |
| `progress` | 0-100 |
| `result` | 完成时摘要 JSON：`{"questionsFound": N}` |

## 五、SyllabusNode（考纲节点）

平表存储，前端请求时由 API 组装为树。`examType` + `code` 联合唯一。

```prisma
model SyllabusNode {
  id         String   @id @default(uuid())
  code       String
  label      String
  examType   String                    // ESAT | TMUA
  parentCode String?
  order      Int      @default(0)
  createdAt  DateTime @default(now())

  @@unique([examType, code])
  @@index([examType])
  @@index([parentCode])
}
```

## 七、DiagnosticSession（诊断测试）

```prisma
model DiagnosticSession {
  id             String   @id @default(uuid())
  userId         String?
  answers        String                  // JSON: 用户提交的答案
  totalQuestions Int
  correctCount   Int
  status         String   @default("anonymous")
  createdAt      DateTime @default(now())

  user User? @relation(fields: [userId], references: [id])

  @@index([userId])
}
```

| 字段 | 说明 |
|------|------|
| `userId` | 可空，匿名测试时无关联 |
| `status` | anonymous=游客 / linked=已绑定用户 |

```prisma
model ExamRecord {

```

| 字段 | 说明 |
|------|------|

## 九、AnswerRecord（逐题答题明细）

```prisma
model AnswerRecord {
  id              String   @id @default(uuid())
  examRecordId    String
  questionId      String                   // FK → Question.id
  selectedAnswer  String?
  isCorrect       Boolean  @default(false)
  durationSeconds Int      @default(0)
  answeredAt      DateTime?

  examRecord ExamRecord @relation(fields: [examRecordId], references: [id], onDelete: Cascade)
  question   Question  @relation(fields: [questionId], references: [id])
}
```

`questionId` 是 `Question.id` 的外键，查询时可通过该外键关联完整题目数据。

### 9.1 错题本数据规则

错题本当前不单独建表，数据来源于历史逐题答题明细：

- `AnswerRecord.isCorrect = false` 的记录视为错题来源。
- `AnswerRecord.selectedAnswer` 记录学生本次提交的答案。
- `AnswerRecord.durationSeconds` 记录本题作答耗时。
- 错题本中的最近错误时间统一使用所属 `ExamRecord.submittedAt`，不使用逐题 `AnswerRecord.answeredAt` 作为排序和筛选口径。

### 9.2 错题聚合规则

错题本首页以 `questionId` 为聚合键，不直接展示每一条错误作答明细：

- 同一个 `questionId` 下的多次错误记录合并为一条错题。
- `wrongCount` 由该 `questionId` 下错误记录数量计算得到。
- `selectedAnswers` 由历史错误答案去重得到，用于展示“曾选 A、B”等信息。
- 最近一次错误记录按所属 `ExamRecord.submittedAt` 判定，用于列表排序，并作为进入解析页时的代表记录。

## 十一、全部表一览

| 表名 | 用途 | 核心外键 |
|------|------|---------|
| `Paper` | 试卷元信息 | — |
| `Question` | 单道试题 | paperId → Paper (cascade) |
| `ParseTask` | PDF 解析任务 | paperId → Paper (cascade) |
| `SyllabusNode` | 考纲树节点 | parentCode → SyllabusNode.code (自引用) |
| `User` | 用户账号 | — |
| `DiagnosticSession` | 诊断测试记录 | userId → User (可空) |
| `ExamRecord` | 一次答题会话 | userId → User, paperId → Paper |
| `AnswerRecord` | 逐题答题明细 | examRecordId → ExamRecord (cascade), questionId → Question |
| `RevenueCost` | 营收成本管理 | — |
| `MembershipPlan` | 会员套餐配置 | — |
| `UserMembership` | 用户按考试类型购买的会员记录 | userId → User (cascade) |
| `EntitlementConfig` | 各考试类型免费权益配置 | — |

## 十二、迁移记录补充

### 2026-06-22：Question.syllabusPoints

- `Question.syllabusPoints` 是试题库和错题本按考纲 code 筛选的核心字段。
- 该字段必须通过 Prisma migration 写入生产库，禁止使用 `db push` 临时同步。
- 对应迁移：`20260622000000_add_question_syllabus_points`。

### 2026-06-22：会员权益基础表

- `Paper`、`Question`、`DiagnosticSession`、`ExamRecord` 增加 `examType` 字段，用于按考试类型归属内容与权益。
- 新增 `MembershipPlan`，用于配置不同考试类型下的月度/年度套餐。
- 新增 `UserMembership`，用于记录用户在某个考试类型下购买的会员。
- 新增 `EntitlementConfig`，用于配置每个考试类型的免费诊断次数和试题库免费题数。
- 对应迁移：`20260622000001_add_membership_entitlements`。

### 2026-06-22：Paper.questions 历史数据回填规则

- `Question` 表是单道试题的唯一正式数据源，试题库、在线答题、报告解析、错题本都必须读取 `Question`。
- `Paper.questions` 仅保留为历史兼容字段，不允许新业务继续写入或读取。
- 历史 `Paper.questions` JSON 需要通过 `api/scripts/backfill-paper-questions.ts` 回填到 `Question` 表。
- 回填前先在 `api` 目录执行 `npm run backfill:questions -- --dry-run` 检查数量和异常 JSON。
- 确认无误后执行 `npm run backfill:questions`；只有确认不再需要旧 JSON 时，才追加 `-- --clear-legacy` 清空历史字段。
- 若目标试卷下已经存在 `Question`，脚本默认跳过；确需覆盖时才追加 `-- --force`。
