# 输入架构设计

**任务**：esat-module-positioning  
**设计日期**：2026-08-03

## 任务分解

整体评价从现有“模块综合分析”调用中拆出，形成独立、可重试、可降级的生成链路。

### 子任务列表

1. **确定性证据准备**：后端计算所有不可由模型改写的分数、正确率、百分位、难度表现和样本提示。
2. **整体评价批量生成**：一次向 DeepSeek 提供当前报告的全部模块，只生成 `moduleId + positioningInsight`，利用横向数据提升模块区分度。
3. **缺失模块补偿生成**：批量调用成功但个别模块缺失或评价无效时，仅携带缺失模块重新请求一次。
4. **逐字段验收与动态降级**：每个 AI 字段独立校验；无效字段只替换自身，不丢弃同模块其他有效字段。
5. **其他模块诊断生成**：风险、总结、优势、关键问题和提升重点保留为独立链路，并使用同样的字段级降级规则。

## 调用拓扑

```text
确定性模块数据
  ├─ 整体评价专用批量调用
  │    ├─ 有效模块 → deepseek
  │    └─ 缺失/无效模块 → 单次补偿调用 → deepseek 或动态 fallback
  └─ 其他诊断字段调用 → 每字段独立接受 → 缺失字段由规则结果补齐
```

## 信息资产清单

### 主数据

- `moduleId`：模块稳定标识，必需，来源为后端模块映射。
- `moduleLabel`：模块中文名称，必需。
- `score`：后端确定的 1.0–9.0 模块预估分，必需。
- `scoreRange`：后端确定的估分参考区间，增强项。
- `correct`、`total`、`accuracyPercent`：模块正确数、题量和已计算正确率，必需。
- `scoringBasis`、`equivalentRawScore`：标准题量或归一化口径，增强项。
- `performanceLevel`：平台固定分档结果，必需；模型只能解释，不可修改。
- `percentileLabel`：官方历史分布上的确定性近似结果，增强项；模型只能引用，不可重算。
- `difficultyMastery`：低、中、高难度的正确数、总数、正确率与样本提示，必需。

### 上下文数据

- `assessmentPurpose`：说明输出用于“科目整体评价”，不是详细学习计划。
- `crossModuleContext`：同一调用中的其他模块数据，用于避免三个模块生成相同套话。
- `dataBoundaries`：禁止推断知识点、错误类型、心理、能力成因和院校录取结论。

### 参考数据

- 一个低分且中难度为主要瓶颈的合格示例。
- 一个中高分且存在相对优势、同时保留改进优先级的合格示例。
- 一个低样本场景示例，要求使用“不足以证明稳定优势”等审慎表达。

### 元数据

- 输出格式：严格 JSON 对象。
- 目标受众：ESAT 学生与家长。
- 单条长度：55–120 个中文字符。
- 单次模块数：通常 3 个，最大不超过 ESAT 实际组合模块数。
- 模型参数：JSON Output、低温度、非思考模式；专用调用建议 `max_tokens` 至少 700。

## 依赖矩阵

| 子任务 | 需要的信息 | 信息类型 | 压缩策略 |
|---|---|---|---|
| 确定性证据准备 | 原始模块统计、估分、难度统计、官方分布映射 | 必需 | 结构化提取；所有比例由代码预计算 |
| 整体评价批量生成 | 全部模块的精简证据包、边界、JSON 示例 | 必需 | 每模块仅保留诊断所需字段，不传题目全文 |
| 缺失模块补偿生成 | 缺失模块证据包、相同提示词 | 必需 | 只传缺失模块，避免重复全量请求 |
| 逐字段验收 | 允许的模块 ID、字段长度、禁用套话、来源 | 必需 | 无需压缩 |
| 动态降级 | 模块名、分数、正确率、最弱难度层、样本提示 | 必需 | 使用确定性模板，不调用模型 |
| 其他诊断生成 | 原有风险和难度诊断输入 | 独立 | 与整体评价结果解耦 |

## 输入模板

### 整体评价批量生成

**字段列表**：

1. **examType**（必需，固定值）：`ESAT`。
2. **task**（必需，≤40字）：`生成各科目的整体评价`。
3. **modules**（必需，每模块约 250–450 字）：
   - `moduleId`
   - `moduleLabel`
   - `score`
   - `scoreRange`
   - `performanceLevel`
   - `percentileLabel`
   - `correct`
   - `total`
   - `accuracyPercent`
   - `scoringBasis`
   - `equivalentRawScore`
   - `difficultyMastery[]`：`level`、`label`、`correct`、`total`、`accuracyPercent`、`sampleNote`

**JSON 输入样例**：

```json
{
  "examType": "ESAT",
  "task": "生成各科目的整体评价",
  "modules": [
    {
      "moduleId": "mathematics-1",
      "moduleLabel": "数学1",
      "score": 1.0,
      "scoreRange": [1.0, 2.4],
      "performanceLevel": "Below Average",
      "percentileLabel": "约第1百分位",
      "correct": 2,
      "total": 19,
      "accuracyPercent": 10.5,
      "scoringBasis": "normalized",
      "equivalentRawScore": 2.8,
      "difficultyMastery": [
        { "level": "low", "label": "低难度", "correct": 0, "total": 0, "accuracyPercent": null, "sampleNote": "无题，不作判断" },
        { "level": "medium", "label": "中难度", "correct": 1, "total": 16, "accuracyPercent": 6.3, "sampleNote": "样本充分" },
        { "level": "high", "label": "高难度", "correct": 1, "total": 3, "accuracyPercent": 33.3, "sampleNote": "样本较少，不足以证明稳定优势" }
      ]
    }
  ]
}
```

**总大小预估**：

- 3 个模块输入约 900–1400 个中文字符。
- 系统提示词与示例约 1000–1600 个中文字符。
- 输出通常少于 500 个中文字符，建议 `max_tokens: 700–900`，避免现有 240 token 上限导致截断。

## 输出模板

```json
{
  "moduleAnalyses": [
    {
      "moduleId": "mathematics-1",
      "positioningInsight": "数学1预估分为1.0，本次答对2/19题；中难度1/16是整体得分率的主要瓶颈，高难度1/3因样本较少尚不足以证明稳定优势。应先提高中难度题的基础得分率，再评估高难度突破。"
    }
  ]
}
```

## 字段排列顺序

1. 系统角色与任务边界。
2. 判断步骤与必须覆盖的内容。
3. 禁止事项。
4. 目标 JSON 结构。
5. 合格与不合格示例。
6. 用户侧结构化模块数据。

## 压缩策略说明

1. **不传题目全文**：整体评价只依据模块汇总与难度分层，题目文本会引入不必要噪声和虚构知识点风险。
2. **比例由代码预计算**：模型不承担除法、百分比或百分位重算，降低数值错误。
3. **难度层固定三行**：即使某层无题也保留并标记“无题，不作判断”，避免模型把缺失误写成 0% 掌握。
4. **显式样本提示**：少量题目的高正确率不得直接写成稳定优势。
5. **输出最小化**：整体评价专用调用不再生成其他六个字段，降低截断与校验耦合。
6. **批量后局部补偿**：第一次保留模块横向对比，第二次仅补缺失模块，兼顾区分度、成本和可靠性。

## 字段级验收与降级规则

每个模块、每个字段独立执行校验，不因同模块或同批的其他字段失败而回退：

1. `moduleId` 必须属于本次输入集合。
2. `positioningInsight` 必须为非空字符串，建议 55–120 字，硬上限 160 字。
3. 不得等于或仅扩写“仍有提升空间”“加强练习”“继续努力”等套话。
4. 至少出现模块分数/等级与一项作答或难度证据。
5. 不得出现输入中不存在的百分位、知识点、错误类型或院校结论。
6. 通过者标记 `deepseek`；未通过者进入对应字段的补偿调用，仍失败才使用该字段的动态 `fallback`。

### 三级降级顺序

| 字段 | 一级：首次 AI 结果 | 二级：局部补偿 | 三级：确定性兜底 |
|---|---|---|---|
| `positioningInsight` | 接受合格整体评价 | 只重试缺失模块的整体评价 | 分数/等级 + 正确率 + 最弱难度层 + 首要方向 |
| `riskSignal` | 接受合格风险句 | 不阻塞定位评价，可选择不额外重试 | 根据最低正确率且有有效样本的难度层生成风险句 |
| `summary` | 接受合格总结 | 不阻塞其他字段 | 模块分数 + 正确数/总数 + 难度概览 |
| `strength` | 接受合格优势 | 不阻塞其他字段 | 有足够样本才描述相对优势，否则明确样本未显示稳定优势 |
| `keyIssue` | 接受合格关键问题 | 不阻塞其他字段 | 选择有题且正确率最低、样本量优先的难度层 |
| `focusSuggestion` | 接受合格提升重点 | 不阻塞其他字段 | 与兜底 `keyIssue` 对应的复盘与验证方向 |

### 来源标记

- 所需字段全部来自模型：`deepseek`。
- 部分字段来自模型、部分字段由规则补齐：`mixed`。
- 所需字段全部由规则生成：`fallback`。
- 前端整体评价使用自身的 `analysisSource`，不受诊断区其他字段来源影响。

### 关键原则

1. JSON 解析成功后先收集所有可用字段，再逐字段验证，禁止使用“七个字段全部有效才保存模块”的总开关。
2. 定位评价是本区域的核心字段，拥有独立补偿调用；其他辅助字段失败时直接使用字段级规则结果，避免为了润色重复消耗模型调用。
3. 只有请求级失败或 JSON 完全无法解析时，才会让本次调用内所有待生成字段进入降级；即使如此也必须生成动态规则文案，页面不得留空。
