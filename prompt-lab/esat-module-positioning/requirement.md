# 需求文档

**任务**：esat-module-positioning  
**整理日期**：2026-08-03

## 任务目标

修复 ESAT 诊断报告中“科目整体评价”的大模型生成链路，使每个模块的评价能够稳定调用 DeepSeek、独立通过校验并写入报告。评价不能再退化为“该模块仍有较大提升空间”等固定空话，而应根据本次模块作答证据说明当前水平、关键表现和首要提升方向。

## 当前问题

1. 最新 v3 报告的三个模块均记录为 `fallback`，整份报告为 `rules_only`。
2. 当前模型一次生成七个字段；某模块任一字段缺失或超长，整个模块分析都会被丢弃，包括本可用的整体评价。系统虽有整模块规则兜底，但没有字段级替换，降级粒度过粗。
3. 调用或解析失败只输出进程日志，报告中没有保留失败阶段和原因，事后难以诊断。
4. 固定兜底只按预估分档位返回一句话，没有引用正确率、难度层表现和最优先问题。
5. 模型提示词仅规定“引用数据”，没有明确整体评价的判断顺序、信息结构和合格示例，容易产生泛化总结。

## 输入描述

每个 ESAT 模块至少提供：

- 模块 ID 与中文名称
- 模块预估分与估分区间
- 正确数、总题数与正确率
- 标准题量或 `/27` 归一化标记
- 低、中、高难度的正确数、总数与正确率
- 平台表现等级与参考百分位（确定性计算结果，仅供解释，不允许模型改写数值）

## 输出要求

- **格式**：严格 JSON；每个模块拥有独立的 `positioningInsight`，并与其他诊断字段解耦校验。
- **内容**：1–2 句中文，建议 55–120 字。
- **结构**：当前水平判断 → 至少两项量化证据 → 最主要瓶颈或相对优势 → 下一步优先方向。
- **风格**：专业、客观、直接，面向学生和家长可读。
- **边界**：只解释输入事实，不新增分数、百分位、知识点、错误类型、心理原因或院校录取结论。

## 质量要求

1. **证据充分**：至少引用两类输入证据，其中必须包含正确数/正确率或难度层数据之一。
2. **结论有区分度**：不同模块应因数据差异产生不同结论，不能批量复用同一句话。
3. **整体评价完整**：既说明“当前处于什么状态”，也指出“最值得优先解决什么”。
4. **不重复明细**：不能只罗列所有数字，必须形成有优先级的判断。
5. **生成可靠**：所有 AI 文案字段都应独立接受；任一字段失败不得导致同模块其他合格字段被丢弃。
6. **降级仍有价值**：模型不可用时，规则兜底也必须引用真实模块数据动态生成。
7. **来源可追踪**：报告应明确保存 `deepseek` 或 `fallback` 来源；失败时应保留安全、可诊断的错误阶段。

## 参考信息

- [DeepSeek JSON Output 官方指南](https://api-docs.deepseek.com/guides/json_mode/)要求开启 `json_object`、在提示词中明确 JSON、提供期望 JSON 示例，并合理设置 `max_tokens`，以降低截断和解析失败。
- [DeepSeek Chat Completion 官方文档](https://api-docs.deepseek.com/api/create-chat-completion)说明 JSON 模式仍需在消息中明确要求 JSON；达到长度上限时内容可能被截断，因此应控制单次输出规模。
- 当前代码已使用 JSON 输出模式，但缺少目标 JSON 示例，并把多个独立文案字段绑定在一次严格验收中。

## 验收标准

- [ ] 模型配置正常时，三个模块的整体评价来源均为 `deepseek`，不再整份报告默认为 `rules_only`。
- [ ] 某模块其他诊断字段无效时，合格的 `positioningInsight` 仍可独立写入。
- [ ] 风险、总结、优势、关键问题、提升重点均采用字段级接受；缺失字段单独使用规则结果补齐，并将模块来源标记为 `mixed`。
- [ ] 每条整体评价引用至少两类真实证据，并指出唯一首要提升方向。
- [ ] 禁止出现单独的“该模块仍有较大提升空间”等无证据空话。
- [ ] 三个模块输入不同数据时，输出结论在瓶颈、优势或优先方向上具有可观察差异。
- [ ] 模型不可用或输出无效时，动态兜底仍包含模块名称、预估分、正确率和最弱难度层。
- [ ] 自动化测试覆盖成功、部分字段无效、请求失败、低样本和不同难度分布场景。
