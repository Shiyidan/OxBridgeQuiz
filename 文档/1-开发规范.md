# 开发规范

> 持续完善中，后续补充其他规范条目。

## 一、注释规范

### 1.1 路由注释

- 每个路由的说明注释**放在路由定义上方**（不要写行尾注释）
- 注释仅标注页面名称，**不写功能描述、不写装饰性分隔线**
- **层级关系通过嵌套 `children` 体现**，不需要在注释里用前缀标注归属

```ts
// ✅ 正确：层级通过代码缩进一目了然
{
  path: 'core-library',
  children: [
    // 首页
    { path: '', component: CoreLibraryView },
    // 试题库
    { path: 'questions', component: QuestionBankAdmin },
    {
      path: 'exams',
      children: [
        // 列表
        { path: '', component: ExamBankAdmin },
        // 上传解析
        { path: 'upload', component: PaperUpload },
        // 试卷预览
        { path: ':id', component: PaperPreview },
      ],
    },
  ],
}

// ❌ 错误（行尾注释）
{ path: '/question-bank', component: QuestionBankView }, // 试题库

// ❌ 错误（注释太长、装饰分隔线、用前缀模拟层级）
// -------------------- 试题库浏览页 --------------------
// 核心资料库 · 真题库 · 列表
{ path: 'core-library/exams', component: ExamBankAdmin },
```

### 1.2 代码注释

- 只写 **WHY**（为什么这样写），不写 **WHAT**（代码本身已经说明做了什么）
- 一行注释即可，不写多行块注释
- 不写 `// TODO` 无期限的占位注释；确需标记的，附带时间或条件

```ts
// ✅ 正确
// 模块级缓存：切题时同一公式会出现在多道题里，避免重复 renderToString
const renderCache = new Map<string, string>()

// ❌ 错误
// 创建缓存 Map
const renderCache = new Map<string, string>()
```

### 1.3 函数、计算属性与关键调用

以下自行定义的代码应在定义上方添加一行注释：

- 具名 `function` 和 `async function`。
- 赋值给变量的函数表达式或箭头函数。
- 页面业务事件处理函数，例如提交、发布、状态变更和关键导航。
- Vue `computed`，注释应说明业务派生规则及主要数据来源。

以下情况可以不写注释：

- `map`、`filter`、`find`、`sort` 等调用中的简单内联回调。
- 框架 API 的简单回调参数。
- 名称、类型和实现已经完整表达含义，且不包含业务规则的通用工具函数。

页面初始化、业务来源或上下文切换、数据持久化及关键流程导航属于重点注释场景。注释写在方法定义或关键调用的上一行，说明业务职责、数据来源、派生规则或该调用承接的业务流程，不要只翻译函数名。

```ts
// 根据当前会员和考试类型计算用户可使用的题库额度。
const questionBankLimit = computed(() => {
  // ...
})

// 根据路由来源切换数据源：paperId 为真题套卷，否则按考点和难度从题库取题。
async function loadQuestions(): Promise<void> {
  // ...
}

// 交卷后保留来源参数，结果页据此区分返回诊断测试或试题库。
router.push({ path: '/exam-result', query: { id, source } })

// ❌ 错误：只重复名称，没有说明业务规则。
// 计算题库额度。
const questionBankLimit = computed(() => {
  // ...
})

// ❌ 错误：简单内联回调不需要机械添加注释。
const activeItems = items.filter((item) => item.active)
```

共用页面应说明来源差异。例如诊断测试和试题库共用答题页或结果页时，应标注依赖的 `paperId`、`source`、`paperType` 等上下文字段。

### 1.4 文件头部

- 组件文件顶部用一行简述**用途和应用位置**
- 工具函数文件同样一行简述用途

```ts
// ✅ 正确
// 题目渲染卡片（试题库、练习页、试卷预览共用）
// KaTeX 公式缓存（模块级，跨组件复用）

// ❌ 错误
// 题目组件
// 缓存
```

## 二、数据库开发规范

> 数据库设计、变更和操作必须遵循 [3.2 数据库构建.md](./3.2%20数据库构建.md) 中定义的数据模型。

### 2.1 Schema 变更流程

1. 修改 `prisma/schema.prisma`
2. 执行 `npx prisma migrate dev --name <描述>` 生成迁移文件
3. **必须同步更新 `3.2 数据库构建.md`**：
   - 新增表 → 在文档对应模块章节追加模型定义 + 字段说明表
   - 新增/修改字段 → 更新 Prisma 代码块和字段说明表中的对应行
   - 删除表/字段 → 同步从文档中移除
4. 后续凡涉及数据库表变动或字段变动，都必须维护进 `3.2 数据库构建.md`
5. 有历史数据需迁移时，编写迁移脚本并验证完整性后再删除旧列

### 2.1.1 禁止跳过迁移直接同步（⭐）

> `prisma db push` 会绕过迁移历史直接改写数据库结构，导致 Schema、数据库、迁移文件三者不一致。之后换环境部署或他人接手时 `prisma migrate dev` 会因缺迁移而失败。

- **开发阶段一律使用 `prisma migrate dev`**，不得用 `prisma db push` 替代
- 若已误用 `db push` 导致迁移缺失：
  1. 运行 `npx prisma migrate diff --from-migrations --to-schema-datamodel --script` 查看差异
  2. 用 `npx prisma migrate dev --name <描述> --create-only` 生成迁移文件
  3. 执行 `npx prisma migrate resolve --applied <迁移名>` 标记为已应用
- 每次 Schema 变更后务必运行 `npx prisma migrate status` 确认迁移状态一致
- 禁止在 `migrations/` 目录下手动创建或删除迁移文件，避免破坏迁移链路

### 2.2 数据操作规范

- 所有数据库读写必须通过 **Prisma Client**（`@/services/prisma.ts`），禁止直接执行 SQL
- 查询结果需要排序时，优先用数据库 `orderBy`，前端仅做兜底排序
- JSON 字段（`options` / `answer` / `tags`）读写时用 `JSON.stringify` / `JSON.parse`，API 返回前必须 parse
- 关联查询用 `include` 而非多次单表查询
- 角色、状态、套餐、考试类型等字段值必须集中定义常量，不允许在业务代码中散落硬编码字符串。
- 不同语义不得混用同一字段：`role` 只表达身份；会员权益只以 `UserMembership` 和权益接口为准。

### 2.3 关联表命名

- 多对多关联表命名：`<表A><表B>`（如 `PaperQuestion`）
- 关联表必须包含排序字段 `order: Int`
- 关联表至少包含一个 `@@unique` 约束防止重复关联

### 2.4 试题数据规范

- `Question` 表是试题唯一正式数据源，业务查询、答题、解析报告、错题本都必须从 `Question` 读取。
- `Paper.questions` 仅作为历史兼容字段和回填输入，不允许新功能继续读取或写入。
- 上传解析、JSON/Markdown 导入、试卷编辑必须通过 `syncPaperQuestions` 写入 `Question` 表。
- 历史 `Paper.questions` 数据回填使用 `api` 目录下的 `npm run backfill:questions`，先执行 `-- --dry-run` 校验，再正式执行；确认不再需要旧 JSON 后才允许追加 `-- --clear-legacy`。
- 题干 `title` 中的段落分隔统一用 `\n\n`，前端 `white-space: pre-line` 渲染
- 图片优先存为 SVG（`QuestionImage.type = "svg"`），PNG 仅用于照片/复杂图
- 选项 JSON 格式固定为 `[{"label": "A", "text": "..."}]`
- 答案 JSON 格式固定为 `["A"]`（数组，支持多选）

## 三、API 接口响应规范

### 3.1 统一响应格式

所有后端接口**必须**按照以下统一结构返回数据：

```ts
interface ApiResponse<T = unknown> {
  success: boolean      // 接口是否返回成功
  code: number | string // 0=成功，1=通用失败，其他字符串为具体业务错误码
  errMsg: string        // 失败时返回的报错信息，成功时为空字符串
  data: T               // 返回的数据体
}
```

### 3.2 成功响应示例

```json
// 返回对象
{
  "success": true,
  "code": 0,
  "errMsg": "",
  "data": { "id": 1, "name": "张三" }
}

// 返回列表
{
  "success": true,
  "code": 0,
  "errMsg": "",
  "data": [{ "id": 1, "name": "张三" }, { "id": 2, "name": "李四" }]
}

// 无数据返回（如删除操作）
{
  "success": true,
  "code": 0,
  "errMsg": "",
  "data": null
}
```

### 3.3 失败响应示例

```json
// 通用失败（未指定 code 时默认为 1）
{
  "success": false,
  "code": 1,
  "errMsg": "用户名已存在",
  "data": null
}

// 具体业务错误（code 为可读字符串，前端可按需判断）
{
  "success": false,
  "code": "AUTH_INVALID_CREDENTIALS",
  "errMsg": "邮箱或密码错误",
  "data": null
}
```

### 3.4 错误码约定

| code | 含义 | 使用场景 |
|------|------|---------|
| `0` | 成功 | `success()` 固定返回 |
| `1` | 通用失败 | `fail(msg)` 默认值，无需前端区分错误类型的场景 |
| `AUTH_INVALID_CREDENTIALS` | 凭据错误 | 登录时用户名、邮箱或密码不匹配 |
| `AUTH_SESSION_EXPIRED` | 登录会话失效 | 访问令牌和刷新会话均无法恢复 |
| `STUDY_RESOURCE_FILE_REQUIRED` | 缺少资料文件 | 后台上传资料时未提交 PDF |
| `STUDY_RESOURCE_INVALID_FILE_TYPE` / `STUDY_RESOURCE_INVALID_PDF` | PDF 校验失败 | 扩展名不正确或文件签名不是 PDF |
| `STUDY_RESOURCE_INVALID_TITLE` / `STUDY_RESOURCE_INVALID_DESCRIPTION` | 资料文本不合法 | 标题为空、过长或说明超长 |
| `STUDY_RESOURCE_INVALID_EXAM_TYPE` / `STUDY_RESOURCE_INVALID_CATEGORY` | 资料归类不合法 | 考试类型或资料分类不在固定枚举中 |
| `STUDY_RESOURCE_INVALID_ACCESS_TIER` / `STUDY_RESOURCE_INVALID_STATUS` | 资料状态不合法 | 访问级别或发布状态不在固定枚举中 |
| `STUDY_RESOURCE_INVALID_YEAR` | 真题年份不合法 | 年份不是 1980 至下一考试周期之间的四位整数 |
| `STUDY_RESOURCE_FILE_ROLE_EXISTS` | 年度文件已存在 | 同一考试年份已存在试题或答案，需要先删除原资料后再替换 |
| `STUDY_RESOURCE_NOT_FOUND` | 资料不存在 | 资料记录不存在、处于草稿状态或已被删除 |
| `STUDY_RESOURCE_LOGIN_REQUIRED` | 资料下载需要登录 | 游客尝试下载会员资料 |
| `STUDY_RESOURCE_MEMBERSHIP_REQUIRED` | 缺少资料下载权益 | 登录用户没有对应考试的有效会员 |
| `STUDY_RESOURCE_FILE_UNAVAILABLE` | 资料文件不可用 | 已发布记录对应的 ECS 本地文件缺失或路径无效 |

> 新增业务错误码时直接追加到本表。`fail()` 第二个参数传 code，不传默认 `1`。

资料下载接口成功时返回 `application/pdf` 附件流，失败时仍返回统一 JSON 响应包；前端通过公共请求层的 Blob 错误还原逻辑读取业务错误码。

### 3.5 列表分页响应规范

所有需要分页的列表接口统一使用 `page` + `pageSize` 作为请求参数：

```txt
GET /api/example?page=1&pageSize=20
```

分页列表接口的 `data` 必须返回 `list + pagination`：

```ts
interface PageResult<T> {
  list: T[]
  pagination: {
    page: number
    pageSize: number
    total: number
    totalPages: number
    hasPrev: boolean
    hasNext: boolean
  }
}
```

示例：

```json
{
  "success": true,
  "code": 0,
  "errMsg": "",
  "data": {
    "list": [],
    "pagination": {
      "page": 1,
      "pageSize": 20,
      "total": 86,
      "totalPages": 5,
      "hasPrev": false,
      "hasNext": true
    }
  }
}
```

分页交互统一规则：

- 首次进入页面默认请求 `page=1&pageSize=20`。
- 点击搜索时，将表单中的草稿筛选条件提交为已应用筛选条件，并重置到 `page=1`。
- 点击分页器切换页码时，只使用已应用筛选条件继续查询，不使用尚未点击搜索的草稿条件。
- 切换 `pageSize` 时保留已应用筛选条件，并重置到 `page=1`。
- 点击重置时清空草稿筛选条件和已应用筛选条件，保留当前 `pageSize`，并重置到 `page=1`。
- 前端分页组件统一使用 `src/components/AppPagination.vue`，由公共组件内部对接 Element Plus `el-pagination`。
- 页面不得直接使用 `el-pagination` 或重复实现分页控件。
- 页面侧只维护 `pagination.page`、`pagination.pageSize`、`pagination.total`，通过 `v-model:page` 和 `v-model:page-size` 传给公共分页器。

## 四、前端组件复用规范

组件选择按以下优先级执行：

1. 优先复用 `quiz-web/src/components/` 中已有的项目组件，保持业务行为和视觉表现一致。
2. 没有合适的项目组件时，优先使用项目已安装的 Element Plus 组件。
3. 两者都不能满足需求时，先判断该能力是否会在多个页面复用；会复用时应封装到 `src/components/`，仅单一业务页面使用时可放在对应页面目录。
4. 原生 HTML/CSS 仅用于简单语义结构或 Element Plus 无法满足的必要定制场景，不要重复实现已有的通用交互组件。

项目组件可以在内部封装 Element Plus。页面应依赖项目组件提供的统一接口，不要绕过已有项目组件直接使用其底层 Element Plus 组件。

## 五、前端 API 层规范

### 5.1 架构

所有后端接口调用**必须**通过 `src/api/` 目录下的模块函数发起，**禁止**在 `.vue` / `.ts` 文件中直接使用 `request.get/post` 等底层方法。

```
src/api/
  questionBank.ts   ← 试题库相关
  auth.ts           ← 认证相关
  exam.ts           ← 考试 / 答卷 / 错题本
  papers.ts         ← 试卷管理
  upload.ts         ← 上传 / 解析 / 导入
  admin.ts          ← 管理后台
```

每个 API 模块文件包含：**类型定义**（`interface`）→ **API 函数**。

### 5.2 统一封装

`src/utils/request.ts` 提供 `callApi<T>(config)` 函数，所有 API 模块通过它发起请求。

```ts
import { callApi } from '@/utils/request'

interface ApiConfig {
  url: string                                   // 请求路径（不含 baseURL）
  method: 'GET' | 'POST' | 'PUT' | 'DELETE'     // 请求方式
  params?: Record<string, string | undefined>    // query 参数，自动拼接到 url
  body?: unknown                                 // POST/PUT 请求体
  timeout?: number                               // 仅在接口确需不同超时时间时指定
}
```

### 5.3 API 函数编写规范

每个 API 函数必须清晰声明 **method** 和 **url**，需要时再声明 **params**、**body** 或 **timeout**。`callApi<T>()` 始终返回统一响应包中的 `data`，调用方获得的类型为 `Promise<T>`，不得再增加决定是否返回 Axios 响应的布尔开关。

```ts
// ✅ 正确
export function getQuestionSummaryData(code: string) {
  return callApi<QuestionBankSummary>({
    url: '/papers/question-bank/summary',
    method: 'GET',
    params: { code },
  })
}

// ❌ 错误：直接暴露 request
export function getSomething() {
  return request.get('/papers/xxx').then(r => r.data)
}
```

业务代码不得依赖 Axios 的完整响应对象。未来如果确有下载文件、读取响应头或状态码的接口，应新增语义明确的独立请求函数及返回类型，不得让普通 `callApi<T>()` 同时承担两种返回结构。

统一错误处理规则：

- `src/utils/request.ts` 是 API 错误面向用户展示的唯一公共出口。收到标准响应中的 `success: false`，或者 HTTP 非成功响应携带标准响应体时，统一展示后端 `errMsg`。
- HTTP `401` 且业务码为 `AUTH_SESSION_EXPIRED` 时，清除前端访问令牌，展示 `errMsg`，随后自动返回首页。登录接口返回的 `AUTH_INVALID_CREDENTIALS` 虽然也是 HTTP `401`，但只展示 `errMsg`，不得退出或跳转。
- 除登录会话失效外，其他 API 错误只展示 `errMsg`，页面保持在当前路由，不得由公共请求层自动刷新或跳转。
- 页面和组件可以使用 `catch` 恢复 loading、回滚本地状态或阻止后续流程，但不得再次调用 `ElMessage.error` 展示同一个 API 错误。
- 请求层向业务代码抛出的错误统一为 `ApiError`。页面需要保留错误文案时调用 `getApiErrorMessage(error, fallback)`；需要按业务码分支时调用 `hasApiErrorCode(error, code)`。不得访问 `error.response`、`error.response.data.errMsg` 或 `error.response.data.code`。
- 文件读取、浏览器权限、二维码生成等非 API 异常不经过 Axios，仍由对应页面提供本地提示。
- 页面启动时调用 `/auth/refresh` 探测登录状态，未登录属于允许结果，不单独提示；受保护接口刷新会话失败时，仍按 `AUTH_SESSION_EXPIRED` 处理。

### 5.4 页面调用示例

```html
<script setup lang="ts">
import { getQuestionSummaryData } from '@/api/questionBank'

// 页面初始化时按试卷编码加载题库汇总数据。
async function loadData() {
  const data = await getQuestionSummaryData('112000')
  // data 类型已推断为 QuestionBankSummary，无需手动标注
}
</script>
```
