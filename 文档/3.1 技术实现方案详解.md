## 一、题目渲染链

题目从数据库到屏幕经过结构化内容块、资源解析和 LaTeX 渲染三层处理。题干与图片的先后关系由 `content_blocks` 决定，不应在页面中拼接两套渲染逻辑。

### 1.1 渲染流程

```text
Question 数据（content_blocks / images / options）
  → QuestionCard.vue       — 按顺序遍历题干块，image_ref 通过 image_id 解析资源
    → LatexText.vue         — 扫描混合文本，切为原文、行内公式和显示公式
      → FormulaBlock.vue    — KaTeX 渲染：调用 katex.renderToString()
```

新版上传文件使用 camelCase `contentBlocks`。`markdownValidator` 在上传边界校验后一次性归一化为 `content_blocks`；页面、API 和数据库读取链不同时兼容两套命名，避免各页面各自判断字段版本。

`paragraph` 可选字段 `align` 目前只接受 `"center"`。归一化时，居中段落被标记为独立内容块；`QuestionCard` 为该块设置居中样式，`LatexText` 仍按原规则处理纯文本和 LaTeX。未提供 `align` 的段落保持原有连续题干流。学生作答接口通过字段白名单保留合法的 `align`，因此上传预览、试卷预览和在线答题使用同一布局语义。

### 1.2 LatexText.vue 切分策略

使用定界符扫描器从左到右切分文本。先判断显示公式，再判断行内公式，避免 `$$...$$` 被当成两个 `$...$`。

| 片段类型 | 识别方式               | 渲染方式                                                 |
| -------- | ---------------------- | -------------------------------------------------------- |
| 显示公式 | `$$...$$` 或 `\[...\]` | `FormulaBlock` + `displayMode: true`                     |
| 行内公式 | `$...$` 或 `\(...\)`   | `FormulaBlock` + `displayMode: false`                    |
| 纯文本   | 未成对定界符与其他内容 | 原样输出，`white-space: pre-wrap` 保留 JSON 解析后的换行 |

`\$` 等已转义符号不会开启公式，未成对的定界符保留为纯文本。不对字符串再做 `.replace(/\\n/g, ...)`，因为这会破坏 `\neq`、`\nu` 等合法 LaTeX 命令。

### 1.3 FormulaBlock.vue 缓存

KaTeX 的 `renderToString()` 有性能开销。同一次答题中，相同 LaTeX 字符串可能出现在多道题中（如单位 `\text{m s}^{-1}`），因此使用模块级 `Map<string, string>` 缓存编译结果，避免重复渲染。

### 1.4 QuestionCard.vue 接口

```ts
// 传入单道题的数据和当前作答状态
props: {
  question: Question       // 题目数据（含 content_blocks、options、images）
  index: number            // 当前题号（0-based）
  selectedAnswer?: string  // 当前已选答案
  metaTags?: string[]      // 知识点标签（试题库模式下展示）
  variant?: 'default' | 'exam' // 普通展示或考试作答样式
  showAnswer?: boolean         // 由页面显式决定是否展示答案
  questionLabel?: string      // 模块卷可传入科目名与模块内题号
}

// 用户选择选项时向外 emit
emits: {
  select: (optionLabel: string) => void
}
```

### 1.5 图文资源与解析兼容

- `content_blocks` 是题干的唯一顺序来源；`paragraph` 交给 `LatexText`，`image_ref` 从当题 `images` 中按 `image_id` 查找。
- 新版 project JSON 可能把一句题干拆成连续的文字、公式和标点 `paragraph`。上传归一化会为这些块增加内部 `inline` 标记，`QuestionCard` 在同一阅读流中渲染；`image_ref` 仍保持独立图形位置。历史题目没有该标记时继续按段落展示。
- SVG 转为 `data:image/svg+xml` 后使用 `<img>` 渲染，不将上传内容直接注入 `v-html`。位图使用 `src`，两者都保留 `alt`。
- 新解析使用 `learning_analysis.correct_solution`；历史真题中的 `learning_analysis.solution` 在导入时归一化，前端报告仍保留回退读取。

## 二、诊断测试评分引擎

详见 [ESAT计分规则.md](../ESAT计分规则.md) 和 [api/src/services/scoring.ts](../api/src/services/scoring.ts)。

### 2.1 评分流程

```text
交卷 → 批改每题的 isCorrect → 优先按稳定模块代码分组 → 旧数据回退到 subject 映射
  → 每模块查 raw→scaled 转换表 → 插值出 1.0–9.0 标准分
  → 每个模块独立生成评估、分数区间与能力分析 → 写入报告
```

### 2.2 模块映射

上传规范中模块根节点使用稳定 `code`，归一化后的题目使用 `module_code`、`module_order`、`module_question_number`；数据库分别存为 `Question.moduleCode`、`moduleOrder`、`moduleQuestionNumber`。显示名称可以调整，不会改变分组。导入器继续兼容旧 `component_code` 和 `questions[].items`；仅对没有稳定代码的旧题，才通过 `Question.subject` 关键词回退映射：

| 模块          | subject 关键词                      |
| ------------- | ----------------------------------- |
| Mathematics 1 | `maths 1`、`mathematics 1`、`数学1` |
| Mathematics 2 | `maths 2`、`mathematics 2`、`数学2` |
| Physics       | `physics`、`物理`                   |
| Chemistry     | `chemistry`、`化学`                 |
| Biology       | `biology`、`生物`                   |

### 2.3 raw→scaled 转换

每个模块有独立的转换参考表（来自 UAT-UK 官方数据），通过分段线性插值将原始正确数映射到 1.0–9.0 标准分。不同模块的转换曲线不同：

- **Maths 1** 最苛刻：raw 22/27 ≈ 7.0
- **Maths 2** 最宽松：raw 20.5/27 ≈ 7.0
- **Physics / Chemistry** 中等：raw 21/27 ≈ 7.0

当等效诊断卷的模块题量不是 27 题时，先计算 `correct / total × 27` 的等效原始分，再查该模块曲线。例如 6 题短卷不能将“答对 4 题”直接当作官方 27 题量表中的 raw 4。报告同时标记 `scoringBasis: normalized` 并给出更宽的不确定性区间；这一结果是等效估算，不冒充官方分数。

### 2.4 分数段位

| 标准分  | 段位 | 约百分位 |
| :-----: | ---- | :------: |
| 8.0–9.0 | 顶尖 |  前 4%   |
| 7.0–7.9 | 优秀 |  前 10%  |
| 6.0–6.9 | 良好 |  前 20%  |
| 4.0–5.9 | 中等 |   ~55%   |
| 1.0–3.9 | 偏低 |   ~20%   |

### 2.5 评分结果结构

```ts
interface ModuleScore {
  module: 'maths1' | 'maths2' | 'physics' | 'chemistry' | 'biology'
  moduleLabel: string // "Mathematics 1"
  rawScore: number // 该模块正确数
  totalQuestions: number // 该模块总题数
  scaledScore: number // 1.0–9.0 标准分
  band: string // elite / excellent / good / average / below_avg
  approximatePercentile: number
}

interface ScoringResult {
  examType: string
  strategy: 'esat-module-equivalent' | 'tmua-equivalent' | 'generic'
  overallScore: number | null // ESAT 为 null；TMUA/通用策略可有总分
  modules: ModuleScore[]
}
```

ESAT 按模块报分，系统不计算也不返回“三科总分”；`ScoringResult.overallScore` 在 ESAT 策略下固定为 `null`。短模块先按正确率归一到 27 题后分别估分，并明确标记为等效估算。

### 2.6 分段诊断状态机

ESAT 诊断固定包含 3 个科目 section，各科独立计时，前两个科目后进入 180 秒休息：

```text
answering(module 1)
  → break(180s, skippable)
  → answering(module 2)
  → break(180s, skippable)
  → answering(module 3)
  → ready_to_submit
  → submitted
```

- 开始考试时将三个模块顺序、时长和题目 ID 写入 `structureSnapshot`。后续编辑试卷不会改变已开始的诊断。
- 服务端以 `phase`、`currentModuleIndex`、`phaseStartedAt` 和 `phaseExpiresAt` 作为权威状态，并只下发当前 `answering` 模块的无答案题目。完成的模块不可返回修改，未开始模块不可预读。
- 休息弹窗使用 `endsAt` 与 `serverNow` 计算时钟偏移；倒计时归零和用户点击“跳过休息”调用同一服务端迁移。刷新页面既不重置休息，也不延长作答时间。
- `activeDurationSeconds` 只累加 `answering` 阶段，休息不计入作答用时。模块到时与主动提前结束都先保存当前模块答案。
- 评分与诊断报告只读取该 `ExamRecord` 已创建的 `AnswerRecord.questionId` 范围，不再按 `paperId` 把同卷其他题目算成未答错题。

TMUA 固定包含 `paper1`、`paper2` 两个 section，每卷 20 题、75 分钟。Paper 1 完成后服务端直接切换到 Paper 2，不创建 `break` 阶段。外部上传的 `sections` 会归一化为现有分段字段并写入 `structureSnapshot`；前端只按服务端返回的阶段、当前分段和截止时间渲染，不自行推断考试规则。

## 三、PDF 试卷解析

浏览器端 pdf.js 将 PDF 逐页渲染为 JPEG，逐页上传后端，Qwen-VL-Max AI 从图片中识别题目结构，输出标准 JSON 格式。

```text
用户选择 PDF
  → 浏览器 pdf.js 逐页渲染为 JPEG Base64
  → 逐页 POST /api/parse-tasks/:id/pages
  → 后端调 Qwen-VL-Max（信号量限制 5 并发）
  → 协调器汇合多页结果，去重排序
  → 写入 Question 表
```

关键设计：

- **前端化渲染**：pdf.js 在浏览器端完成，服务器零 Python 依赖
- **占位符策略**：模型输出用 `[[BS]]` 等占位符替代 `\` 等 JSON 敏感字符，后端 decode 时还原
- **并发控制**：信号量限制最大 5 并发，避免 Qwen API 限流
- **SVG 防失控**：Prompt 限制 SVG ≤1500 字符，复杂图用 `[[FIG]]` 占位

详见 [3.4 试卷上传解析技术方案](3.4%20试卷上传解析技术方案.md)。

## 四、会员权益模型

### 4.1 三层权限判定

```text
身份认证层（JWT Token → userId）
  → 角色权限层（role = admin | student）
    → 会员权益层（examType × 会员状态 × 免费额度）
```

### 4.2 额度消耗规则

| 场景       | 消耗方式          | 统计口径                                                                       |
| ---------- | ----------------- | ------------------------------------------------------------------------------ |
| 诊断测试   | 每次提交消耗 1 次 | `DiagnosticSession(status=linked)` + `ExamRecord(status=submitted, realPaper)` |
| 试题库练习 | 按答题数量消耗    | `AnswerRecord` 中 `paperType=aiPaper` 的题目数                                 |

管理员不受限制。前端 store 做入口控制和 UI 提示，后端每个关键接口独立校验。

详见 [3.3 登录模块技术方案](3.3%20登录模块技术方案.md) 和 [4.2 会员权益](4-需求文档/4.2%20会员权益.md)。

## 五、关键数据约定

### 5.1 Question JSON 字段

| 字段                   | 格式                                                      | 示例                                                 |
| ---------------------- | --------------------------------------------------------- | ---------------------------------------------------- |
| `options`              | `[{"label": "A", "text": "..."}]`                         | 选项标签 + 文本（含内联 LaTeX）                      |
| `answer`               | `["A"]`                                                   | 正确答案标签数组，支持多选                           |
| `knowledgePoints`      | `[{"code": "112001", "label": "...", "role": "primary"}]` | 考纲知识点映射                                       |
| `meta`                 | `{"content_blocks": [...], "images": [...], ...}`         | 前端渲染所需的结构化数据                             |
| `moduleCode`           | `"maths1"`                                                | 题目所属稳定模块，由上传文档模块的 `code` 归一化得到 |
| `moduleOrder`          | `1`                                                       | 当次试卷中的模块顺序                                 |
| `moduleQuestionNumber` | `1`                                                       | 模块内题号，各模块可从 1 重新开始                    |

### 5.2 读写约定

- Prisma `Json` 字段直接写入结构化 JSON 值，不预先 `JSON.stringify`；只在读取历史字符串 JSON 时使用兼容解析工具
- 题干与选项字符串保留 JSON 解析后的真实换行，前端纯文本片段使用 `white-space: pre-wrap`
- 图片优先 SVG（`type: "svg"`），PNG 仅用于照片/复杂位图
