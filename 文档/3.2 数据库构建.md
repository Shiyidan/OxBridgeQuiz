# 数据库构建方案

> 基于 `api/prisma/schema.prisma` 的实际结构，后续所有数据库结构变更需要同步更新本文档。

---

## 一、数据库选型

当前开发环境数据库已切换为 MySQL。

- ORM：Prisma
- 数据库：MySQL 8.x
- 本地开发库：`quiztestdemo_dev`
- 主 schema：`api/prisma/schema.prisma`
- 当前迁移链：MySQL baseline migration
- 历史 SQLite 迁移：已在完成 MySQL 切换后清理，不再保留在主仓库

本次切换后，结构化字段不再使用“字符串里存 JSON”的方式。题目选项、答案、知识点、考纲源数据、用户备考偏好、诊断答案等字段均使用 MySQL `JSON` 列。


---

## 二、表关系总览

```text
Paper ──1:N── Question
Paper ──1:N── ParseTask
Paper ──1:N── ExamRecord ──1:N── AnswerRecord ──N:1── Question

User ──1:N── ExamRecord
User ──1:N── DiagnosticSession
User ──1:N── UserMembership

Syllabus ──同步启用── SyllabusNode

RevenueCost、MembershipPlan、EntitlementConfig 为独立配置/运营表
```

| 关系 | 说明 |
|------|------|
| `Paper` 1:N `Question` | 一份试卷包含多道题，删除试卷时级联删除题目 |
| `Paper` 1:N `ParseTask` | 一份试卷可有解析任务记录 |
| `Paper` 1:N `ExamRecord` | 一份试卷可被多次作答 |
| `User` 1:N `ExamRecord` | 一个用户可产生多次作答记录 |
| `ExamRecord` 1:N `AnswerRecord` | 一次作答包含逐题明细 |
| `AnswerRecord` N:1 `Question` | 逐题明细直接关联正式题目表 |
| `User` 1:N `DiagnosticSession` | 诊断测试记录支持绑定用户 |
| `Syllabus` 启用同步 `SyllabusNode` | 后台上传考纲 JSON，启用后同步为平表树节点 |

---

## 三、核心数据源规则

- `Question` 是唯一正式题目数据源。
- `Paper.questions` 仅作为历史兼容字段，不作为新业务查询来源。
- 上传 JSON / Markdown、解析导入、试卷编辑等写题目场景必须通过 `syncPaperQuestions` 写入 `Question`。
- 题目展示、在线答题、试题库、错题本、诊断报告均读取 `Question`。
- JSON 字段写入数据库时写入数组或对象，不再手动 `JSON.stringify`。
- API 返回前如遇历史字符串 JSON，可通过 `jsonField.ts` 做兼容解析。

## 四、主要模型

### 4.1 Paper（试卷）

```prisma
model Paper {
  id             String   @id @default(uuid()) @db.VarChar(191)
  title          String   @db.VarChar(255)
  code           String?  @db.VarChar(100)
  examType       String   @default("TMUA") @db.VarChar(32)
  year           Int
  duration       Int
  totalQuestions Int      @default(0)
  paperType      String   @default("realPaper") @db.VarChar(32)
  pdfUrl         String?  @db.Text
  status         String   @default("draft") @db.VarChar(32)
  questions      Json?
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt
}
```

| 字段 | 说明 |
|------|------|
| `paperType` | `realPaper` 真题卷 / `mockPaper` 模考卷 / `aiPaper` AI 生成卷 |
| `status` | `draft` 草稿 / `published` 已发布 |
| `questions` | 历史兼容 JSON，不再作为正式题目来源 |
| `pdfUrl` | PDF 地址或 OSS 地址，使用 `Text` 避免 URL 过长 |
| `id` | 新建试卷使用 `cuid()` 生成，不再使用带 `-` 的 UUID |

### 4.2 Question（试题）

```prisma
model Question {
  id              String   @id @default(uuid()) @db.VarChar(191)
  paperId         String   @db.VarChar(191)
  examType        String   @default("TMUA") @db.VarChar(32)
  number          Int
  title           String   @db.LongText
  options         Json
  answer          Json
  subject         String?  @db.VarChar(100)
  subjectCode     String?  @db.VarChar(64)
  questionType    String?  @db.VarChar(64)
  difficulty      String?  @db.VarChar(32)
  topic           String?  @db.VarChar(255)
  topicCode       String?  @db.VarChar(64)
  knowledgePoints Json
  syllabusPoints  Json
  meta            Json
  createdAt       DateTime @default(now())
}
```

| 字段 | 说明 |
|------|------|
| `title` | 题干正文，使用 `LongText`，避免长题干、段落、公式内容超出长度 |
| `options` | JSON 数组，格式为 `[{ label, text }]` |
| `answer` | JSON 数组，格式为 `["A"]`，支持后续多选 |
| `knowledgePoints` | JSON 数组，存知识点/考纲节点映射 |
| `syllabusPoints` | JSON 数组，历史考纲字段，保留用于兼容和后续清理 |
| `meta` | JSON 对象，存 `content_blocks`、`images`、`learning_analysis` 等展示/分析扩展信息 |

约束规则：

- `Question(paperId, number)` 唯一，同一张试卷内不允许出现重复题号。

### 4.3 ParseTask（解析任务）

```prisma
model ParseTask {
  id        String   @id @default(uuid()) @db.VarChar(191)
  paperId   String   @db.VarChar(191)
  status    String   @default("pending") @db.VarChar(32)
  progress  Int      @default(0)
  error     String?  @db.Text
  result    Json?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

| 字段 | 说明 |
|------|------|
| `status` | `pending` / `processing` / `completed` / `failed` |
| `progress` | 解析进度，0-100 |
| `error` | 错误信息，使用 `Text` |
| `result` | JSON 摘要，例如 `{ "questionsFound": 20 }` |

### 4.4 User（用户）

```prisma
model User {
  id              String   @id @default(uuid()) @db.VarChar(191)
  username        String   @unique @db.VarChar(191)
  email           String   @unique @db.VarChar(191)
  password        String   @db.VarChar(255)
  role            String   @default("student") @db.VarChar(32)
  paymentStatus   String   @default("free") @db.VarChar(32)
  diagnosticUsed  Boolean  @default(false)
  avatar          String?  @db.Text
  examPreferences Json?
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt
}
```

| 字段 | 说明 |
|------|------|
| `username` | 登录用户名，全局唯一 |
| `email` | 邮箱，全局唯一，用于联系、找回密码和后续验证 |
| `role` | 用户身份：`student` / `admin` |
| `examPreferences` | JSON 数组，备考偏好：`[{ examType, subjects }]` |

### 4.5 DiagnosticSession（诊断测试记录）

```prisma
model DiagnosticSession {
  id             String   @id @default(uuid()) @db.VarChar(191)
  userId         String?  @db.VarChar(191)
  examType       String   @default("TMUA") @db.VarChar(32)
  answers        Json
  totalQuestions Int
  correctCount   Int
  status         String   @default("anonymous") @db.VarChar(32)
  createdAt      DateTime @default(now())
}
```

| 字段 | 说明 |
|------|------|
| `answers` | JSON 数组，记录用户提交的诊断答案 |
| `status` | `anonymous` / `linked` |

### 4.6 Syllabus 与 SyllabusNode（考纲）

```prisma
model Syllabus {
  id         String   @id @default(uuid()) @db.VarChar(191)
  name       String   @db.VarChar(255)
  examType   String   @db.VarChar(32)
  sourceJson Json
  isActive   Boolean  @default(false)
  createdAt  DateTime @default(now())
  updatedAt  DateTime @updatedAt
}
```

```prisma
model SyllabusNode {
  id         String   @id @default(uuid()) @db.VarChar(191)
  code       String   @db.VarChar(100)
  label      String   @db.VarChar(512)
  examType   String   @db.VarChar(32)
  parentCode String?  @db.VarChar(100)
  order      Int      @default(0)
  createdAt  DateTime @default(now())
}
```

| 字段 | 说明 |
|------|------|
| `Syllabus.sourceJson` | 后台上传的原始考纲 JSON |
| `Syllabus.isActive` | 是否为当前考试类型启用版本 |
| `SyllabusNode` | 启用考纲后同步出的平表节点，用于前端树和试题筛选 |

### 4.7 ExamRecord 与 AnswerRecord（答题记录）

```prisma
model ExamRecord {
  id             String    @id @default(uuid()) @db.VarChar(191)
  userId         String    @db.VarChar(191)
  paperId        String    @db.VarChar(191)
  examType       String    @default("TMUA") @db.VarChar(32)
  totalQuestions Int       @default(0)
  correctCount   Int       @default(0)
  startedAt      DateTime
  submittedAt    DateTime?
  status         String    @default("in_progress") @db.VarChar(32)
}
```

```prisma
model AnswerRecord {
  id              String    @id @default(uuid()) @db.VarChar(191)
  examRecordId    String    @db.VarChar(191)
  questionId      String    @db.VarChar(191)
  selectedAnswer  String?   @db.VarChar(64)
  isCorrect       Boolean   @default(false)
  durationSeconds Int       @default(0)
  answeredAt      DateTime?
}
```

| 字段 | 说明 |
|------|------|
| `ExamRecord.status` | `in_progress` 答题中 / `submitted` 已交卷 |
| `AnswerRecord.questionId` | 外键关联 `Question.id` |
| `AnswerRecord.durationSeconds` | 单题作答耗时 |

### 4.8 运营与会员表

`RevenueCost` 用于营收成本管理；`MembershipPlan`、`UserMembership`、`EntitlementConfig` 用于会员套餐、用户权益和免费额度配置。

## 五、MySQL 字段类型规范

| 数据类型 | 使用场景 |
|---------|----------|
| `Json` | 选项、答案、知识点、考纲源 JSON、用户偏好、诊断答案、解析结果 |
| `@db.LongText` | 题干正文等可能很长的内容 |
| `@db.Text` | PDF 地址、头像地址、错误信息、备注 |
| `@db.VarChar(191)` | 主键、外键、唯一字段 |
| `@db.VarChar(32)` | 状态、角色、考试类型、试卷类型等枚举类字符串 |

## 六、迁移记录

### 2026-07-09：SQLite 切换 MySQL baseline

- 主 schema 从 SQLite 切换为 MySQL。
- 历史 SQLite migration 已在后续清理中移除，不再保留在主仓库。
- 新增 MySQL baseline migration：`20260709000000_mysql_baseline`。
- 当前本地 MySQL 开发库已通过 `migrate resolve --applied` 标记 baseline 已应用。
- `npx prisma migrate status --schema prisma/schema.prisma` 当前结果为 up to date。

### 2026-07-09：结构化字段改为 MySQL JSON

- `Question.options`、`Question.answer`、`Question.knowledgePoints`、`Question.syllabusPoints`、`Question.meta` 改为 `Json`。
- `User.examPreferences` 改为 `Json?`。
- `DiagnosticSession.answers` 改为 `Json`。
- `Syllabus.sourceJson` 改为 `Json`。
- `ParseTask.result` 改为 `Json?`。
- `Paper.questions` 改为 `Json?`，仅保留历史兼容用途。

### 2026-07-09：长文本字段调整

- `Question.title` 改为 `@db.LongText`，避免题干、段落、公式内容变长后超限。
- `Paper.pdfUrl`、`ParseTask.error`、`User.avatar`、`RevenueCost.remark` 改为 `@db.Text`。

### 2026-07-09：Paper ID 生成规则调整

- `Paper.id` 从 `uuid()` 调整为 `cuid()`。
- 该调整只影响后续新建试卷，历史试卷 ID 不自动改写。
- 新 ID 不再包含 `-`，更适合在后台管理页面中展示和识别。

### 2026-07-09：Question 题号唯一约束

- 新增唯一约束：`@@unique([paperId, number])`。
- 同一张试卷内不允许出现重复题号。
- 不同试卷之间允许存在相同题号。
- 对应迁移：`20260709000100_add_question_paper_number_unique`。

### 历史说明

- `Question` 表仍是正式题目数据源。
- `Paper.questions` 不再作为新功能读写来源。
- 错题本仍以 `AnswerRecord.isCorrect = false` 为来源，并按 `questionId` 聚合。
