# 数据库构建方案

> 基于 `api/prisma/schema.prisma` 的实际结构，后续所有数据库结构变更需要同步更新本文档。

---

## 一、数据库选型

当前开发环境数据库已切换为 MySQL。

- ORM：Prisma
- 数据库：MySQL 8.x
- 本地开发库：`quiztestdemo_dev`
- 主 schema：`api/prisma/schema.prisma`
- 当前迁移链：MySQL baseline migration
- 历史 SQLite 迁移：已在完成 MySQL 切换后清理，不再保留在主仓库

本次切换后，结构化字段不再使用“字符串里存 JSON”的方式。题目选项、答案、知识点、考纲源数据、用户备考偏好、诊断答案等字段均使用 MySQL `JSON` 列。

| 关系 | 说明 |
|------|------|
| `Paper` 1:N `Question` | 真题属于固定试卷；试题库独立题目的 `paperId` 为空 |
| `QuestionImportBatch` 1:N `Question` | standard2 的 metadata 在后台作为上传包展示与追溯，不参与学生端检索或组卷 |
| `Question` N:M `SyllabusNode` | 通过 `QuestionKnowledgePoint` 保存知识点关联和 primary/secondary 角色 |
| `MockPaperSet` 1:N `MockPaperModule` | 一个 Mock 编号保存固定候选 Module/Paper、自动编号、访问级别、可用单项数量和完整模考校验摘要 |
| `MockPaperModule` 1:0..1 `MockPaperModule` | `sourceModuleId` 记录套卷模块副本来源并使用唯一约束；同一独立单项最多只能被一个有效套卷采用 |
| `MockPaperModule` 1:N `MockPaperQuestion` N:1 `Question` | 按 Module/Paper 与位置保存题号引用并独立记录校验状态；缺题草稿允许 `questionId` 为空并保留来源题号和问题详情 |
| `MockPaperSet` 0..1:1 `Paper` | 至少一个 Module/Paper 可用并发布后关联唯一 `mockPaper` 运行载体；母卷负责固定内容，`Paper` 只承接现有答卷、报告与历史关系 |
| `Paper` 1:N `ParseTask` | 一份试卷可有解析任务记录 |
| `Paper` 1:N `ExamRecord` | 一份试卷可被多次作答 |
| `User` 1:N `ExamRecord` | 一个用户可产生多次作答记录 |
| `User` 1:N `AuthSession` | 一个用户可在多个设备保持可撤销登录会话 |
| `User` 1:N `EmailVerificationChallenge` | 验证码按用户、邮箱和用途绑定；注册前允许 `userId` 为空 |
| `User` 1:N `StudyResource` | 管理员可以上传多份学习资料；管理员删除后资料保留并将上传人关联置空 |
| `User` 1:N `PaymentOrder` | 用户每次发起支付生成独立支付订单，删除用户时限制删除以保留交易记录 |
| `User` 1:0..1 `InvitationCode` | 每个学生最多保存一个当前邀请码，同一邀请码可以建立多条直接邀请关系 |
| `InvitationRelation` N:1 `User` | 每个受邀用户最多绑定一位邀请人，关系记录注册或个人中心补填来源及首次有效支付 |
| `InvitationRelation` 1:N `InvitationReward` | 同一关系分别保存邀请人和受邀人的奖励资格、发放结果与退款状态 |
| `InvitationReward` 1:0..1 `UserMembership` | 奖励未启用时可以没有会员记录；实际启用后关联唯一七天权益周期 |
| `PaymentOrder` 1:N `UserMembership` | 新支付履约按订单和考试类型保存独立权益周期，退款按订单精确回收 |
| `PaymentReconciliationRun` 1:N `PaymentReconciliationItem` | 每个业务日保存一批对账结果和逐笔核对明细 |
| `PaymentOrder` 1:N `PaymentReconciliationItem` | 同一支付订单可在不同业务日或重跑批次中留下核对结果 |
| `ExamRecord` 1:N `AnswerRecord` | 一次作答包含逐题明细 |
| `AnswerRecord` N:1 `Question` | 逐题明细直接关联正式题目表 |
| `User + Question` 1:1 `WrongQuestionSummary` | 按用户与题目维护全历史错题次数和最近错误上下文 |
| `WrongQuestionSummary` 1:N `WrongQuestionAttempt` | 保存每次正式错误事件，支持来源和收录时间数据库筛选 |
| `ExamRecord` 1:0..1 `DiagnosticReportTask` | 一次已交卷诊断测试只创建一个分析任务 |
| `ExamRecord` 1:0..1 `DiagnosticReport` | 一次已交卷诊断测试最多关联一份独立正式报告 |
| `User + Paper` 1:N `DiagnosticReport` | 同一学生重复测试同一试卷时保留每次成功生成的报告 |
| `User` 1:N `DiagnosticSession` | 诊断测试记录支持绑定用户 |
| `Syllabus` 启用同步 `SyllabusNode` | 后台上传考纲 JSON，启用后同步为平表树节点 |

## 三、核心数据源规则

- `Question` 是唯一正式题目数据源。
- `Paper.questions` 仅作为历史兼容字段，不作为新业务查询来源。
- 真题 JSON / Markdown 导入和试卷编辑通过 `syncPaperQuestions` 写入 `Question`。
- 试题库只接受 `standard2.md` 的 `metadata + questions` 文档，由专用校验器在单个事务中写入批次、独立题目和知识点关联；不兼容旧 AI Paper 导入结构。
- 试题库按 `Question.status`、考试类型、难度、学科、主题和知识点关联在数据库内筛选，不把某考试的全部题目载入 Node.js 后处理。
- 题目展示、在线答题、试题库、错题本、诊断报告均读取 `Question`。
- 错题事实仍来源于已交卷的 `AnswerRecord`；列表查询读取交卷事务同步生成的 `WrongQuestionSummary` 和 `WrongQuestionAttempt`，在数据库内完成筛选、排序和分页。
- JSON 字段写入数据库时写入数组或对象，不再手动 `JSON.stringify`。
- API 返回前如遇历史字符串 JSON，可通过 `jsonField.ts` 做兼容解析。

## 四、主要模型

### 4.1 Paper（试卷）

```prisma
model Paper {
  id                   String   @id @db.VarChar(191)
  title                String   @db.VarChar(255)
  code                 String?  @db.VarChar(100)
  examType             String   @default("TMUA") @db.VarChar(32)
  year                 Int
  duration             Int
  totalQuestions       Int      @default(0)
  paperType            String   @default("realPaper") @db.VarChar(32)
  accessTier           String   @default("member") @db.VarChar(32)
  deliveryMode         String   @default("continuous") @db.VarChar(32)
  breakDurationSeconds Int      @default(0)
  moduleConfig         Json?
  assemblyType         String   @default("original") @db.VarChar(32)
  sourceExamTypes      Json?
  remarks              String?  @db.Text
  pdfUrl               String?  @db.Text
  status               String   @default("draft") @db.VarChar(32)
  questions            Json?
  createdAt            DateTime @default(now())
  updatedAt            DateTime @updatedAt
}
```

| 字段 | 说明 |
|------|------|
| `paperType` | `realPaper` 真题卷 / `mockPaper` 模考卷 / `aiPaper` AI 生成卷 |
| `accessTier` | `free` 免费卷 / `member` 会员卷；历史数据和未声明的新导入默认按 `member` 处理 |
| `deliveryMode` | `continuous` 整卷连续作答 / `module_sequence` 按模块依次作答 |
| `breakDurationSeconds` | 分段间休息秒数；ESAT 等效诊断卷固定为 180，TMUA 两卷固定为 0 |
| `moduleConfig` | 分段代码、展示名称、顺序、时长与题量配置；ESAT 表示科目模块，TMUA 表示 Paper 1/2；开始考试时会冻结到 attempt 快照 |
| `assemblyType` | `original` 原始整卷 / `legacy_equivalent` 历史真题等效组合卷 |
| `sourceExamTypes` | 原始考试来源列表，例如 `ENGAA`、`NSAA` |
| `remarks` | 等效卷声明、短卷可信度或其他发布说明 |
| `status` | `draft` 草稿 / `published` 已发布 |
| `questions` | 历史兼容 JSON，不再作为正式题目来源 |
| `pdfUrl` | PDF 地址或 OSS 地址，使用 `Text` 避免 URL 过长 |
| `id` | 新建试卷由服务层 `createNumericId()` 生成数字字符串，数据库不设置默认值 |

### 4.2 Question（试题）

```prisma
enum QuestionDifficulty {
  easy
  medium
  hard
}

model Question {
  id                   String    @id @default(uuid()) @db.VarChar(191)
  uniqueCode           String    @unique @db.VarChar(191)
  sourceQuestionCode   String?   @db.VarChar(191)
  paperId              String?   @db.VarChar(191)
  importBatchId        String?   @db.VarChar(191)
  examType             String    @default("TMUA") @db.VarChar(32)
  number               Int?
  moduleCode           String?  @db.VarChar(32)
  moduleOrder          Int?
  moduleQuestionNumber Int?
  title                String   @db.LongText
  options              Json
  answer               Json
  subject              String?  @db.VarChar(100)
  subjectCode          String?  @db.VarChar(64)
  questionType         String?  @db.VarChar(64)
  difficulty           QuestionDifficulty?
  qualityTier          String?  @db.VarChar(32)
  topic                String?  @db.VarChar(255)
  topicCode            String?  @db.VarChar(64)
  knowledgePoints      Json
  syllabusPoints       Json
  attemptPayload       Json?
  meta                 Json
  status               String    @default("draft") @db.VarChar(32)
  publishedAt          DateTime?
  archivedAt           DateTime?
  createdAt            DateTime  @default(now())
  updatedAt            DateTime  @default(now()) @updatedAt

  paper               Paper?                   @relation(fields: [paperId], references: [id], onDelete: Cascade)
  importBatch         QuestionImportBatch?     @relation(fields: [importBatchId], references: [id], onDelete: SetNull)
  knowledgePointLinks QuestionKnowledgePoint[]

  @@index([status, examType, difficulty])
  @@index([status, examType, subjectCode])
  @@index([status, examType, topicCode])
}
```

| 字段 | 说明 |
|------|------|
| `title` | 题干正文，使用 `LongText`，避免长题干、段落、公式内容超出长度 |
| `options` | JSON 数组，格式为 `[{ label, text }]` |
| `answer` | JSON 数组，格式为 `["A"]`，支持后续多选 |
| `difficulty` | `QuestionDifficulty` 枚举，仅允许 `easy`、`medium`、`hard`；历史 `composite` 迁移为 `hard`，其他非法值迁移为空 |
| `sourceQuestionCode` | 真题保存来源编码；试题库题目与 `uniqueCode` 同为 standard2 的稳定 code |
| `paperId` | 真题关联 Paper；试题库独立题目固定为空 |
| `importBatchId` | 可选导入追溯批次，不参与筛选和组卷 |
| `number` | 真题保存全卷题号；试题库题目为空，本次练习顺序保存在 `AnswerRecord.position` |
| `moduleCode` | 稳定模块代码；standard2 的 TMUA `part` 直接使用 `paper1` / `paper2` 并原样入库 |
| `moduleOrder` | 模块作答顺序 |
| `moduleQuestionNumber` | 原试卷的科目内题号，前端答题和报告优先展示该值 |
| `knowledgePoints` | JSON 数组，存知识点/考纲节点映射 |
| `syllabusPoints` | JSON 数组，历史考纲字段，保留用于兼容和后续清理 |
| `attemptPayload` | 学生作答态的唯一渲染载荷，存 `content_blocks`、`images` 等不含答案和解析的安全字段 |
| `meta` | 非作答态分析与管理扩展信息，只存 `learning_analysis`、`origin` 等字段，不重复保存题干和图片 |
| `status` | 单题状态：`draft` / `published` / `archived`；学生端只读取 `published` |
| `publishedAt` / `archivedAt` | 单题发布和归档时间 |

约束规则：

- `Question(paperId, number)` 对真题保持唯一；试题库题目的两个字段均为空。
- 试题库 `uniqueCode` 直接使用 standard2 的 code，全局唯一且导入后不可修改。
- 已有答题记录的独立题目不能物理删除，只能归档；影响判分的修改应使用新 code 新建题目。
- 模块卷上传时会把各科从 1 开始的题号归一为全卷连续 `number`，不会丢失 `moduleQuestionNumber`。
- 试卷已有 `ExamRecord` 后，不允许覆盖题目或模块结构；调整内容必须创建新版本。

#### 4.2.1 QuestionImportBatch 与 QuestionKnowledgePoint

```prisma
model QuestionImportBatch {
  id                    String   @id @default(uuid()) @db.VarChar(191)
  title                 String   @db.VarChar(255)
  fileName              String?  @db.VarChar(255)
  declaredQuestionCount Int
  actualQuestionCount   Int
  remarks               String?  @db.Text
  createdAt             DateTime @default(now())
  questions             Question[]
}

model QuestionKnowledgePoint {
  questionId     String @db.VarChar(191)
  syllabusNodeId String @db.VarChar(191)
  role           String @db.VarChar(32)

  question     Question     @relation(fields: [questionId], references: [id], onDelete: Cascade)
  syllabusNode SyllabusNode @relation(fields: [syllabusNodeId], references: [id], onDelete: Restrict)

  @@id([questionId, syllabusNodeId])
  @@index([syllabusNodeId, questionId])
}
```

- `QuestionImportBatch` 保存 standard2.metadata 和原始上传文件名，批次题量必须与实际创建题量一致。
- 后台试题库入口按 `QuestionImportBatch` 展示上传包，包内再分页管理独立题目；学生端查询和组卷仍只依赖 `Question` 的发布状态与分类字段。
- `QuestionKnowledgePoint` 通过 `SyllabusNode.id` 保证知识点真实存在，并支持父级考纲节点向下筛选题目。
- `Question.knowledgePoints` 继续作为展示快照；统计、筛选和组卷以关联表为准。

#### 4.2.2 MockPaperSet、MockPaperModule 与 MockPaperQuestion

`MockPaperSet` 是后台“模考试卷库”的套卷母版。`sequenceNo` 按 `examType` 分别从 1 递增，默认显示名称由服务层格式化为 `ESAT 模拟卷 No.001` 或 `TMUA 模拟卷 No.001`；数据库使用 `@@unique([examType, sequenceNo, version])` 防止同考试类型、同序号和同版本重复。

| 模型 | 关键字段与规则 |
|------|----------------|
| `MockPaperSet` | `code` 全局唯一；`accessTier` 为免费卷或会员卷；`status` 只表示完整套卷的 `draft / published / archived`；`readyModuleCount` 汇总校验通过的 Module/Paper 数量，`fullExamReady` 与 `validationStatus` 表示是否具备完整模考结构；`deletedAt` 用于草稿软删除并保留编号；`issueCount`、`questionCount` 和 `issues` 保存整组校验摘要；`sourceFileName` 追溯上传工作簿；`paperId` 关联轻量运行时 `Paper`，`publishedAt`、`archivedAt` 记录完整套卷发布和下线时间 |
| `MockPaperModule` | 通过 `mockPaperSetId` 归属 Mock；`sourceModuleId` 可选关联独立原始单项并保持全局唯一，防止同一单项重复组卷；`title` 保存管理员维护的单项展示名称并同步到已有套卷副本；`publicationStatus`、`publishedAt`、`archivedAt` 独立记录单项发布状态，不再复用套卷状态；`code`、`label`、`moduleOrder`、`durationSeconds` 和 `expectedQuestionCount` 固定正式结构；`validationStatus`、`issueCount` 和 `issues` 独立表示该单项能否使用；同一 Mock 的模块代码和顺序分别唯一 |
| `MockPaperQuestion` | 通过 `moduleId + position` 固定模块内顺序；`sourceCode` 永久保存管理员上传或替换的题号；匹配成功时 `questionId` 关联正式 `Question`，题目删除时置空并等待重新校验；`issues` 保存逐题错误 |

Excel 上传先按 Mock 编号解析 Module/Paper，再创建可修复草稿并逐项校验。题号不存在、匹配不唯一、未发布、跨考试、跨模块、Mock 内重复或不可自动判分时不会复制题目内容，只在组卷关系上标记问题。单题替换只更新目标位置的 `sourceCode` 和关联，随后刷新各单项与完整模考状态；只有草稿套卷中尚未发布的单项允许替换，已发布单项和已发布完整套卷保持锁定。

至少一个 Module/Paper 校验通过后即可发布单项；不满足完整结构时 `MockPaperSet.status` 仍保持 `draft`。只有 `fullExamReady` 的草稿在发布时才切换为完整套卷 `published`。发布只创建承接现有考试链路的轻量 `Paper`，题目仍通过 `MockPaperQuestion -> Question` 读取，不向历史兼容字段 `Paper.questions` 复制内容。运行时 `Paper` 只同步已发布且校验通过的单项；既有答卷继续使用创建时冻结的结构快照。完整套卷下线会同时归档母卷、模块和运行时 `Paper`，但不删除已有答卷、报告和错题记录。

#### 4.9.1 WrongQuestionSummary 与 WrongQuestionAttempt（错题查询投影）

```prisma

model WrongQuestionAttempt {
  id             String   @id @default(uuid()) @db.VarChar(191)
  summaryId      String   @db.VarChar(191)
  userId         String   @db.VarChar(191)
  questionId     String   @db.VarChar(191)
```

- `WrongQuestionSummary` 是可重建的查询投影，不替代 `AnswerRecord` 作为答题事实来源。
- 交卷事务在完成判题后同步写入摘要与事件；`answerRecordId @unique` 保证重复同步不会重复计数。
- 列表通过摘要表按最近错误时间排序并使用数据库 `skip/take` 分页；题目难度、学科和规范化知识点关联通过 `Question` 关系筛选。
- 日期和来源条件通过 `WrongQuestionAttempt` 的关系存在性筛选；卡片仍展示全历史错误次数、历史错选答案和全局最近一次错误上下文。
- 历史数据使用 `npm run backfill:wrong-questions -- --dry-run` 核对，再使用 `npm run backfill:wrong-questions` 幂等回填。

模块卷只向客户端下发当前 `answering` 模块题目。切页、锁屏或确认返回时，暂停接口原子保存当前模块；作答进入 `paused`，休息进入 `break_paused`，暂停期间均不消耗剩余时间。继续测试时由服务端根据冻结值生成新截止时间。完成模块后，服务端锁定该模块答案；前两个 ESAT 模块进入 180 秒 `break`，最后一个模块进入 `ready_to_submit`。跳过休息与倒计时自然结束共用幂等阶段切换，报告始终按 `AnswerRecord` 冻结的题目范围生成。

### 4.11 运营与会员表

`RevenueCost` 用于营收成本管理；`MembershipPlan`、`UserMembership`、`EntitlementConfig` 用于会员套餐、用户权益和题库免费额度配置；`InvitationCode`、`InvitationRelation`、`InvitationReward` 用于邀请码与双边七天会员奖励。

`RevenueCost.costCategory` 保存成本分类，`rechargeItem` 保存该分类下的具体成本项。分类与成本项使用稳定编码，中文名称由后台页面映射：

| 成本分类编码 | 中文分类 | 允许的成本项编码 |
|------|------|------|
| `technical_infrastructure` | 技术基础设施服务 | `server_rental`、`database_rental`、`domain_certificate`、`third_party_technical_service` |
| `development_tools` | 研发工具 | `deepseek`、`claude`、`codex` |
| `operations_marketing` | 运营推广 | `marketing_promotion`、`content_operations`、`administration_finance` |

历史成本记录默认归入 `development_tools`。成本项 `deepseek`、`claude`、`codex` 保留原值并继续作为研发工具的可选项。`reimbursementStatus` 的既有取值和“不可报销”展示保持不变。

诊断测试不再读取 `EntitlementConfig.diagnosticLimit` 判定次数。诊断权限由 `Paper.accessTier` 与对应考试类型的有效 `UserMembership` 共同决定：`free` 试卷可以不限次重新测试，`member` 试卷只有管理员或对应考试的有效会员可以创建新测试。`diagnosticLimit` 字段暂时保留用于兼容旧接口，不作为诊断测试业务依据。

`EntitlementConfig.questionBankLimit` 继续按 `examType` 配置题库免费额度；管理员和对应考试类型的有效会员不受该次数限制。

`UserMembership` 新增 `paymentOrderId`、`sourceType` 和 `sourceId`，用于区分在线支付、邀请赠送和历史会员记录。新支付订单不再把月卡或季卡时长直接合并到已有记录，而是从同一考试类型最晚有效期之后创建独立周期；月卡固定30天，季卡固定90天。邀请周卡使用 `weekly_reward` 计划标识并通过奖励记录关联。权限判断仍只读取当前时间处于有效周期且状态有效的 `UserMembership`，历史 `yearly` 记录继续按原年度期限展示和退款。

`InvitationCode` 按用户唯一保存八位分享码。`InvitationRelation.inviteeUserId` 唯一，保证受邀用户只能绑定一次；`triggerPaymentOrderId` 唯一，保证一笔首次有效支付最多触发一条邀请关系。`InvitationReward` 通过“邀请关系 + 受益角色”唯一约束分别保存邀请人和受邀人的结果，`membershipId` 唯一关联实际权益。`invitationRelationId` 允许为空，配合 `sourceType = admin_gift` 保存不依赖邀请关系的管理员赠送日卡。

奖励正常状态只包括 `pending_activation`（待启用）和 `activated`（已启用）。受邀人绑定邀请码后即建立待启用记录，`grantedAt` 是否存在用于区分首付前资格与首付后已到账卡；确认启用后统一进入 `activated`，不再根据权益周期派生排队、使用中或已结束状态。`expired` 和 `revoked` 表示失效与撤回；不再保存 `limit_reached` 状态。三张上限只统计 `beneficiaryRole = inviter` 的已到账奖励，`invitee` 来源的一张奖励独立计算，因此同一用户最多可能保留四张邀请活动周卡。达到三张邀请人奖励时通过邀请码有效性和发奖准入控制，不创建占位奖励。退款撤回只取消奖励关联的会员记录，奖励历史及其原来源计数继续保留。

### 4.12 支付策略、订单、退款、通知、对账与后台任务租约

`PaymentConfig` 使用固定主键 `default` 保存全局支付策略，包括月卡价格、季卡原价和季卡折扣价。金额均使用整数分，后台保存后前台支付弹窗读取同一数据源。

`PaymentOrder` 保存每次支付尝试的价格快照、备考类型、套餐、渠道、状态和渠道交易字段。支付订单与会员权益分离：外部订单确认支付成功后，再由履约流程创建与订单、考试类型关联的独立会员权益周期，并在存在待支付邀请关系时于同一事务内发放双边奖励。管理员赠送日卡启用时创建 `provider = internal`、`plan = daily_gift`、`priceType/channel = admin_gift`、金额为零且状态为已支付的内部订单，并关联 24 小时会员周期；内部订单不进入外部退款和对账。

`PaymentRefund` 保存每次退款尝试的退款单号、金额、原因、渠道退款号、操作管理员和最终结果。退款请求与支付订单采用 1:N 关系，允许失败后使用新的退款单号重试；全额退款成功后同步累计退款金额并回收该支付订单发放的会员权益。

`PaymentNotification` 保存银联商务通知的唯一标识、验签结果、脱敏报文和处理结果。`provider + notificationId` 唯一约束用于抵御重复通知，订单入账仍通过 `PaymentOrder` 条件更新和事务履约保证幂等。

`PaymentReconciliationRun` 按支付渠道和业务日期唯一保存每日对账批次、触发方式、核对数量和结果统计。`PaymentReconciliationItem` 保存每笔订单的本地/渠道状态、金额、异常类型、脱敏渠道快照和人工处理记录。第一阶段以本地已有订单逐笔调用银联查询接口为范围；取得渠道全量账单权限后可继续补充“渠道有、本地无”的交易识别。

`BackgroundJobLease` 保存后台任务名称、当前实例标识和租约截止时间。支付生命周期 Worker 使用固定任务名 `payment-lifecycle` 竞争数据库租约，确保多 API 实例中同一时刻只有一个实例执行支付查询、超时关单、退款查询和会员到期处理；实例异常退出后可在租约到期时由其他实例接管。

|------|------|

| `PaymentConfig.quarterlyOriginalPriceCents` | 90天季卡划线原价，单位分，默认59400 |
| `PaymentConfig.quarterlyPriceCents` | 90天季卡实付折扣价，单位分，默认35600 |
| `PaymentOrder.orderNo` | 系统支付订单号，全局唯一 |
| `PaymentOrder.examTypes` | 本次购买选择的考试类型数组，使用 MySQL JSON 保存 |
| `PaymentOrder.priceType` | `first_monthly` / `monthly` / `yearly` / `admin_gift`，记录价格或赠送来源规则 |
| `PaymentOrder.amountCents` | 下单时的价格快照，单位分 |
| `PaymentOrder.refundedAmountCents` | 已确认成功的累计退款金额，单位分 |

### 4.13 OperationLog（操作审计日志）

`OperationLog` 只保存能够归属到管理员或普通用户的关键业务操作，不承载系统运行日志、后台 Worker 事件、普通页面浏览和高频自动保存。诊断报告正文读取属于明确纳入统计的用户操作，使用 `diagnostic_report.view` 记录；报告状态轮询不记录。管理员与普通用户共用一张表，通过操作发生时的角色快照筛选。

```prisma
model OperationLog {
```

| 字段 | 说明 |
|------|------|
| `requestId` | 关联同一次 HTTP 请求的操作审计与服务端运行日志；历史记录为空 |
| `actorUserId` | 关联操作者；用户删除后置空，身份快照继续保留 |

### 4.15 WebsiteVisitDaily（网站访问日聚合）

`WebsiteVisitDaily` 按“北京时间自然日 + IP HMAC 摘要”唯一保存网站访问。服务端从可信代理解析后的 `req.ip` 读取来源地址，规范化后使用独立环境密钥生成 SHA-256 HMAC；数据库不保存明文 IP。当天同一 IP 重复打开网站只更新时间而不重复计数。`visitorType` 由服务端会话判断为登录学生或匿名访客；同一 IP 当天先匿名后登录时升级为学生，之后不降级。历史数据无法可靠反推身份，因此不进入身份分类折线。

```prisma
model WebsiteVisitDaily {
  id           String   @id @default(uuid()) @db.VarChar(191)
  businessDate DateTime @db.Date
  ipHash       String   @db.Char(64)
  visitorType  String?  @db.VarChar(16)
  visitCount   Int      @default(1)
  firstSeenAt  DateTime @default(now())
  lastSeenAt   DateTime @default(now())
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt

  @@unique([businessDate, ipHash])
  @@index([businessDate])
}
```

| 字段 | 说明 |
|------|------|
| `businessDate` | 访问发生时的北京时间自然日，仅表达日历日期 |
| `ipHash` | 使用 `VISITOR_IP_HASH_SECRET` 生成的稳定 HMAC 摘要，不用于反查明文 IP |
| `visitorType` | `student` 表示有有效学生会话，`anonymous` 表示匿名访问；历史记录可为空 |
| `visitCount` | 历史兼容字段；新统计不再累加或读取，去重访问量直接按日聚合记录数计算 |
| `firstSeenAt` / `lastSeenAt` | 当天首次与最近一次上报时间 |

管理端访问趋势分别展示登录学生和匿名访客的每日去重 IP 数；注册趋势直接按 `User.createdAt` 和 `role = student` 聚合，不在访问表中复制用户事实。访问统计最长查询 90 天，并以相同长度的上一周期计算变化率。

### 4.16 StudyResource（学习资料）

`StudyResource` 保存后台教材与备考资料库上传的 PDF 元数据。当前分类固定为考试资料、过往真题和知识点讲义；过往真题按考试类型与年份归组，并通过 `fileRole` 区分试题和答案。数据库不保存 PDF 二进制或服务器绝对路径，只保存可迁移到 OSS 的相对 `storageKey`。上传管理员被删除后资料仍保留，`uploadedById` 自动置空。

```prisma
model StudyResource {
  id               String   @id @default(uuid()) @db.VarChar(191)

  resourceYear     Int?
  fileRole         String   @default("main") @db.VarChar(32)
  accessTier       String   @default("free") @db.VarChar(32)
  status           String   @default("draft") @db.VarChar(32)
  originalFileName String   @db.VarChar(255)
  storageKey       String   @unique @db.VarChar(500)
  mimeType         String   @default("application/pdf") @db.VarChar(100)
  fileSizeBytes    Int
  downloadCount    Int      @default(0)
  checksumSha256   String   @db.Char(64)
  uploadedById     String?  @db.VarChar(191)
  publishedAt      DateTime?
  createdAt        DateTime @default(now())
  updatedAt        DateTime @updatedAt

  uploadedBy User? @relation(fields: [uploadedById], references: [id], onDelete: SetNull)

  @@index([examType, category, status])
  @@index([bundleKey])
  @@index([category, examType, resourceYear])
  @@index([status, createdAt])
  @@index([uploadedById, createdAt])
}
```

| 字段 | 说明 |
|------|------|
| `category` | `exam_material` 考试资料 / `past_paper` 过往真题 / `knowledge_handout` 知识点讲义 |
| `bundleKey` | 资料组稳定键；普通资料一组一文件，过往真题同一考试与年份的试题、答案共用一个值 |
| `resourceYear` | 过往真题的四位年份；其他资料为空 |
| `fileRole` | `main` 普通资料 / `question` 真题试题 / `answer` 真题答案 |
| `accessTier` | `free` 免费资料 / `member` 会员资料；当前后台新上传资料统一写入 `free` |
| `status` | `draft` 草稿 / `published` 已发布；新上传资料统一为草稿，由管理员在列表中确认发布，前台只读取已发布资料 |
| `storageKey` | ECS 资料根目录下的相对路径，使用年月目录和 UUID 文件名，不包含用户提交的文件名 |
| `originalFileName` | 管理后台展示和未来下载时使用的原始文件名 |
| `downloadCount` | PDF 文件成功完成传输的真实累计次数；前台资料组统一以 10 为展示基数，年度真题再合计试题与答案的真实次数 |
| `checksumSha256` | 上传文件完整内容的 SHA-256，用于完整性核对和后续去重 |
| `uploadedById` | 上传管理员；管理员账号删除后置空，不级联删除资料 |
