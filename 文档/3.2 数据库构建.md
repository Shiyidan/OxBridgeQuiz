# 数据库构建方案

> 基于 `api/prisma/schema.prisma` 的实际结构，后续所有数据库结构变更需要同步更新本文档。

---

## 一、数据库选型

当前开发环境数据库已切换为 MySQL。

- ORM：Prisma
- 数据库：MySQL 8.x
- 本地开发库：`quiztestdemo_dev`
- 主 schema：`api/prisma/schema.prisma`
- 当前迁移链：MySQL baseline migration
- 历史 SQLite 迁移：已在完成 MySQL 切换后清理，不再保留在主仓库

本次切换后，结构化字段不再使用“字符串里存 JSON”的方式。题目选项、答案、知识点、考纲源数据、用户备考偏好、诊断答案等字段均使用 MySQL `JSON` 列。

## 二、表关系总览

```text
Paper ──1:N── Question
Paper ──1:N── ParseTask
Paper ──1:N── ExamRecord ──1:N── AnswerRecord ──N:1── Question
Paper ──1:N── DiagnosticReportTask
Paper ──1:N── DiagnosticReport

User ──1:N── ExamRecord
User ──1:N── DiagnosticSession
User ──1:N── UserMembership
User ──1:N── DiagnosticReportTask
User ──1:N── DiagnosticReport
User ──1:N── AuthSession
User ──1:N── EmailVerificationChallenge（注册验证码可暂不关联用户）
User ──1:N── PaymentOrder
PaymentOrder ──1:N── PaymentRefund
PaymentReconciliationRun ──1:N── PaymentReconciliationItem ──N:1── PaymentOrder

ExamRecord ──1:0..1── DiagnosticReportTask
ExamRecord ──1:0..1── DiagnosticReport

Syllabus ──同步启用── SyllabusNode

RevenueCost、MembershipPlan、EntitlementConfig、PaymentConfig 为独立配置/运营表
BackgroundJobLease 为跨进程后台任务租约表
```

| 关系 | 说明 |
|------|------|
| `Paper` 1:N `Question` | 一份试卷包含多道题，删除试卷时级联删除题目 |
| `Paper` 1:N `ParseTask` | 一份试卷可有解析任务记录 |
| `Paper` 1:N `ExamRecord` | 一份试卷可被多次作答 |
| `User` 1:N `ExamRecord` | 一个用户可产生多次作答记录 |
| `User` 1:N `AuthSession` | 一个用户可在多个设备保持可撤销登录会话 |
| `User` 1:N `EmailVerificationChallenge` | 验证码按用户、邮箱和用途绑定；注册前允许 `userId` 为空 |
| `User` 1:N `PaymentOrder` | 用户每次发起支付生成独立支付订单，删除用户时限制删除以保留交易记录 |
| `PaymentReconciliationRun` 1:N `PaymentReconciliationItem` | 每个业务日保存一批对账结果和逐笔核对明细 |
| `PaymentOrder` 1:N `PaymentReconciliationItem` | 同一支付订单可在不同业务日或重跑批次中留下核对结果 |
| `ExamRecord` 1:N `AnswerRecord` | 一次作答包含逐题明细 |
| `AnswerRecord` N:1 `Question` | 逐题明细直接关联正式题目表 |
| `ExamRecord` 1:0..1 `DiagnosticReportTask` | 一次已交卷诊断测试只创建一个分析任务 |
| `ExamRecord` 1:0..1 `DiagnosticReport` | 当前被发布的考试记录关联一份报告快照 |
| `User + Paper` 唯一 `DiagnosticReport` | 同一学生同一试卷只保留当前有效报告 |
| `User` 1:N `DiagnosticSession` | 诊断测试记录支持绑定用户 |
| `Syllabus` 启用同步 `SyllabusNode` | 后台上传考纲 JSON，启用后同步为平表树节点 |

## 三、核心数据源规则

- `Question` 是唯一正式题目数据源。
- `Paper.questions` 仅作为历史兼容字段，不作为新业务查询来源。
- 上传 JSON / Markdown、解析导入、试卷编辑等写题目场景必须通过 `syncPaperQuestions` 写入 `Question`。
- 题目展示、在线答题、试题库、错题本、诊断报告均读取 `Question`。
- JSON 字段写入数据库时写入数组或对象，不再手动 `JSON.stringify`。
- API 返回前如遇历史字符串 JSON，可通过 `jsonField.ts` 做兼容解析。

## 四、主要模型

### 4.1 Paper（试卷）

```prisma
model Paper {
  id             String   @id @default(uuid()) @db.VarChar(191)
  title          String   @db.VarChar(255)
  code           String?  @db.VarChar(100)
  examType       String   @default("TMUA") @db.VarChar(32)
  year           Int
  duration       Int
  totalQuestions Int      @default(0)
  paperType      String   @default("realPaper") @db.VarChar(32)
  pdfUrl         String?  @db.Text
  status         String   @default("draft") @db.VarChar(32)
  questions      Json?
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt
}
```

| 字段 | 说明 |
|------|------|
| `paperType` | `realPaper` 真题卷 / `mockPaper` 模考卷 / `aiPaper` AI 生成卷 |
| `status` | `draft` 草稿 / `published` 已发布 |
| `questions` | 历史兼容 JSON，不再作为正式题目来源 |
| `pdfUrl` | PDF 地址或 OSS 地址，使用 `Text` 避免 URL 过长 |
| `id` | 新建试卷使用 `cuid()` 生成，不再使用带 `-` 的 UUID |

### 4.2 Question（试题）

```prisma
model Question {
  id              String   @id @default(uuid()) @db.VarChar(191)
  paperId         String   @db.VarChar(191)
  examType        String   @default("TMUA") @db.VarChar(32)
  number          Int
  title           String   @db.LongText
  options         Json
  answer          Json
  subject         String?  @db.VarChar(100)
  subjectCode     String?  @db.VarChar(64)
  questionType    String?  @db.VarChar(64)
  difficulty      String?  @db.VarChar(32)
  topic           String?  @db.VarChar(255)
  topicCode       String?  @db.VarChar(64)
  knowledgePoints Json
  syllabusPoints  Json
  meta            Json
  createdAt       DateTime @default(now())
}
```

| 字段 | 说明 |
|------|------|
| `title` | 题干正文，使用 `LongText`，避免长题干、段落、公式内容超出长度 |
| `options` | JSON 数组，格式为 `[{ label, text }]` |
| `answer` | JSON 数组，格式为 `["A"]`，支持后续多选 |
| `knowledgePoints` | JSON 数组，存知识点/考纲节点映射 |
| `syllabusPoints` | JSON 数组，历史考纲字段，保留用于兼容和后续清理 |
| `meta` | JSON 对象，存 `content_blocks`、`images`、`learning_analysis` 等展示/分析扩展信息 |

约束规则：

- `Question(paperId, number)` 唯一，同一张试卷内不允许出现重复题号。

### 4.3 ParseTask（解析任务）

```prisma
model ParseTask {
  id        String   @id @default(uuid()) @db.VarChar(191)
  paperId   String   @db.VarChar(191)
  status    String   @default("pending") @db.VarChar(32)
  progress  Int      @default(0)
  error     String?  @db.Text
  result    Json?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

| 字段 | 说明 |
|------|------|
| `status` | `pending` / `processing` / `completed` / `failed` |
| `progress` | 解析进度，0-100 |
| `error` | 错误信息，使用 `Text` |
| `result` | JSON 摘要，例如 `{ "questionsFound": 20 }` |

### 4.4 User（用户）

```prisma
model User {
  id              String   @id @default(uuid()) @db.VarChar(191)
  username        String   @unique @db.VarChar(191)
  email           String   @unique @db.VarChar(191)
  password        String   @db.VarChar(255)
  emailVerifiedAt DateTime?
  passwordChangedAt DateTime?
  role            String   @default("student") @db.VarChar(32)
  paymentStatus   String   @default("free") @db.VarChar(32)
  diagnosticUsed  Boolean  @default(false)
  avatar          String?  @db.Text
  examPreferences Json?
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt
}
```

| 字段 | 说明 |
|------|------|
| `username` | 登录用户名，全局唯一 |
| `email` | 邮箱，全局唯一，用于联系、找回密码和后续验证 |
| `emailVerifiedAt` | 当前邮箱完成所有权验证的时间 |
| `passwordChangedAt` | 最近一次修改或重置密码的时间 |
| `role` | 用户身份：`student` / `admin` |
| `examPreferences` | JSON 数组，备考偏好：`[{ examType, subjects }]` |

### 4.5 AuthSession（认证会话）

```prisma
model AuthSession {
  id               String    @id @default(uuid()) @db.VarChar(191)
  userId           String    @db.VarChar(191)
  refreshTokenHash String    @db.Char(64)
  expiresAt        DateTime
  lastUsedAt       DateTime  @default(now())
  revokedAt        DateTime?
  ipAddress        String?   @db.VarChar(64)
  userAgent        String?   @db.VarChar(512)
  createdAt        DateTime  @default(now())
  updatedAt        DateTime  @updatedAt
}
```

| 字段 | 说明 |
|------|------|
| `refreshTokenHash` | 只保存刷新令牌秘密部分的 SHA-256 摘要，不保存明文 Cookie |
| `expiresAt` | 当前空闲过期时间；每次成功轮换 Refresh Token 后顺延 7 天 |
| `lastUsedAt` | 最近一次成功轮换 Refresh Token 的时间，作为会话活动时间 |
| `revokedAt` | 非空表示会话已被登出、改密或管理员操作撤销 |
| `ipAddress` / `userAgent` | 用于个人中心设备列表和安全排查，不作为唯一身份凭证 |

### 4.6 EmailVerificationChallenge（邮箱验证挑战）

```prisma
model EmailVerificationChallenge {
  id            String    @id @default(uuid()) @db.VarChar(191)
  userId        String?   @db.VarChar(191)
  email         String    @db.VarChar(191)
  purpose       String    @db.VarChar(32)
  codeDigest    String    @db.Char(64)
  attempts      Int       @default(0)
  expiresAt     DateTime
  usedAt        DateTime?
  invalidatedAt DateTime?
  createdAt     DateTime  @default(now())
}
```

| 字段 | 说明 |
|------|------|
| `purpose` | `REGISTER` / `RESET_PASSWORD` / `CHANGE_EMAIL`，不同用途不可互换 |
| `codeDigest` | 邮箱、用途、challengeId 和验证码共同计算的 HMAC-SHA-256 摘要 |
| `attempts` | 验证失败次数，达到上限后挑战失效 |
| `usedAt` | 成功消费时间，保证验证码一次性使用 |
| `invalidatedAt` | 重发、发送失败或错误次数超限后的失效时间 |

### 4.9 ExamRecord 与 AnswerRecord（答题记录）

```prisma
model ExamRecord {
  id             String    @id @default(uuid()) @db.VarChar(191)
  userId         String    @db.VarChar(191)
  paperId        String    @db.VarChar(191)
  examType       String    @default("TMUA") @db.VarChar(32)
  totalQuestions Int       @default(0)
  correctCount   Int       @default(0)
  startedAt      DateTime
  expiresAt      DateTime?
  submittedAt    DateTime?
  durationSeconds Int      @default(0)
  status         String    @default("in_progress") @db.VarChar(32)
  submissionKey  String?   @unique @db.VarChar(191)
}
```

```prisma
model AnswerRecord {
  id              String    @id @default(uuid()) @db.VarChar(191)
  examRecordId    String    @db.VarChar(191)
  questionId      String    @db.VarChar(191)
  selectedAnswer  String?   @db.VarChar(64)
  answerState     String    @default("unseen") @db.VarChar(16)
  isCorrect       Boolean   @default(false)
  durationSeconds Int       @default(0)
  answeredAt      DateTime?

  @@unique([examRecordId, questionId])
}
```

| 字段 | 说明 |
|------|------|
| `ExamRecord.status` | `in_progress` 答题中 / `submitted` 已交卷 |
| `ExamRecord.submissionKey` | 前端一次交卷流程的幂等标识，重复请求复用同一考试记录 |
| `ExamRecord.expiresAt` | 真题和仿真考试的服务端截止时间；试题库练习为空 |
| `ExamRecord.durationSeconds` | 最终考试总耗时；真题最多计算到截止时间，练习按单题活跃耗时合计 |
| `AnswerRecord.questionId` | 外键关联 `Question.id` |
| `AnswerRecord.answerState` | `unseen` 从未查看 / `skipped` 已查看未作答 / `answered` 已作答 |
| `AnswerRecord.durationSeconds` | 单题作答耗时 |
| `AnswerRecord(examRecordId, questionId)` | 联合唯一，防止同一次考试重复保存同一道题 |

### 4.10 DiagnosticReportTask 与 DiagnosticReport（诊断分析任务与报告快照）

`DiagnosticReportTask` 保存后台分析生命周期，包括 `pending / analyzing / completed / failed` 状态、分析阶段、真实进度、心跳、重试次数、错误信息和待发布结果。API 服务重启后通过数据库状态恢复中断任务。

`DiagnosticReport` 保存学生与试卷当前有效的完整报告 JSON。`@@unique([userId, paperId])` 保证同一学生同一试卷只有一个当前报告；新报告只有成功生成后才覆盖旧报告。

| 字段 | 说明 |
|------|------|
| `DiagnosticReportTask.examRecordId` | 唯一关联一次已提交考试，保证同一次交卷只生成一个任务 |
| `status` | `pending` / `analyzing` / `completed` / `failed` |
| `stage` | `answers_saved`、固定计算、模块分析、ROI 分析、路径分析、保存报告或完成 |
| `progress` | 后端真实阶段进度，报告成功保存后才为 100 |
| `heartbeatAt` | 后台执行器心跳，用于服务重启和超时任务恢复 |
| `result` | 本次任务生成的报告 JSON，便于失败排查和发布审计 |
| `DiagnosticReport.result` | 当前有效完整报告快照，前端查看时直接读取，不重新调用模型 |
| `sourceSnapshot` | 生成报告时使用的考试、题目和备考资料摘要 |
| `generationMode` | `full_ai` / `mixed_fallback` / `rules_only` |
| `reportVersion`、`promptVersion`、`modelName` | 报告算法、提示词和模型版本追踪 |

### 4.11 运营与会员表

`RevenueCost` 用于营收成本管理；`MembershipPlan`、`UserMembership`、`EntitlementConfig` 用于会员套餐、用户权益和免费额度配置。

`EntitlementConfig.diagnosticLimit` 和 `questionBankLimit` 按 `examType` 分别配置学生免费额度，当前默认值均为 `1`；既有配置记录迁移后也统一为 `1`。管理员和有效会员仍按不限额度处理。

### 4.12 支付策略、订单、退款、通知、对账与后台任务租约

`PaymentConfig` 使用固定主键 `default` 保存全局支付策略，包括首次月付、正常月付和年度价格。金额均使用整数分，后台保存后前台支付弹窗读取同一数据源。

`PaymentOrder` 保存每次支付尝试的价格快照、备考类型、套餐、渠道、状态和银联商务交易字段。支付订单与会员权益分离：订单确认支付成功后，再由后续履约流程创建或延长会员权益。

`PaymentRefund` 保存每次退款尝试的退款单号、金额、原因、渠道退款号、操作管理员和最终结果。退款请求与支付订单采用 1:N 关系，允许失败后使用新的退款单号重试；全额退款成功后同步累计退款金额并回收该支付订单发放的会员权益。

`PaymentNotification` 保存银联商务通知的唯一标识、验签结果、脱敏报文和处理结果。`provider + notificationId` 唯一约束用于抵御重复通知，订单入账仍通过 `PaymentOrder` 条件更新和事务履约保证幂等。

`PaymentReconciliationRun` 按支付渠道和业务日期唯一保存每日对账批次、触发方式、核对数量和结果统计。`PaymentReconciliationItem` 保存每笔订单的本地/渠道状态、金额、异常类型、脱敏渠道快照和人工处理记录。第一阶段以本地已有订单逐笔调用银联查询接口为范围；取得渠道全量账单权限后可继续补充“渠道有、本地无”的交易识别。

`BackgroundJobLease` 保存后台任务名称、当前实例标识和租约截止时间。支付生命周期 Worker 使用固定任务名 `payment-lifecycle` 竞争数据库租约，确保多 API 实例中同一时刻只有一个实例执行支付查询、超时关单、退款查询和会员到期处理；实例异常退出后可在租约到期时由其他实例接管。

| 字段 | 说明 |
|------|------|
| `PaymentConfig.firstMonthlyPriceCents` | 用户首次成功购买月度套餐的价格，单位分 |
| `PaymentConfig.monthlyPriceCents` | 非首次购买月度套餐的价格，单位分 |
| `PaymentConfig.yearlyPriceCents` | 年度套餐价格，单位分 |
| `PaymentOrder.orderNo` | 系统支付订单号，全局唯一 |
| `PaymentOrder.examTypes` | 本次购买选择的考试类型数组，使用 MySQL JSON 保存 |
| `PaymentOrder.priceType` | `first_monthly` / `monthly` / `yearly`，记录价格命中规则 |
| `PaymentOrder.amountCents` | 下单时的价格快照，单位分 |
| `PaymentOrder.refundedAmountCents` | 已确认成功的累计退款金额，单位分 |
| `PaymentOrder.status` | `pending` / `paid` / `failed` / `closed` / `refunding` / `refunded` |
| `PaymentOrder.providerOrderNo` | 银联商务或目标渠道交易号，存在时唯一 |
| `PaymentOrder.providerPayload` | 渠道响应必要快照，使用 JSON 保存并要求敏感字段脱敏 |
| `PaymentRefund.refundOrderNo` | 系统退款单号，每次退款尝试唯一 |
| `PaymentRefund.status` | `processing` / `succeeded` / `failed` |
| `PaymentRefund.providerRefundNo` | 银联商务或目标支付渠道退款流水号 |
| `PaymentRefund.operatorId` | 发起退款的管理员用户 ID，用于操作审计 |
| `PaymentNotification.notificationId` | 银联商务通知号；缺失时使用通知报文摘要 |
| `PaymentNotification.signatureValid` | 通知是否通过通讯密钥验签 |
| `PaymentNotification.processStatus` | `received` / `processed` / `ignored` / `failed` |
| `PaymentNotification.rawPayload` | 脱敏后的通知报文，用于审计与问题定位 |
| `PaymentReconciliationRun.businessDate` | 中国时区自然日，同一渠道每天只保留一个可重跑批次 |
| `PaymentReconciliationRun.status` | `running` / `completed` / `partial` / `failed` |
| `PaymentReconciliationRun.correctedOrders` | 管理员根据银联可验证结果显式修复的订单数量 |
| `PaymentReconciliationItem.result` | `matched` / `corrected` / `anomaly` / `error` |
| `PaymentReconciliationItem.resolutionStatus` | `none` / `open` / `auto_resolved` / `manually_resolved` |
| `PaymentReconciliationItem.resolutionNote` | 管理员线下核查和关闭异常时填写的处理依据 |
| `BackgroundJobLease.name` | 后台任务唯一名称，也是租约主键 |
| `BackgroundJobLease.ownerId` | 当前持有租约的 API 实例标识 |
| `BackgroundJobLease.lockedUntil` | 租约截止时间，超时后允许其他实例接管 |

### 4.13 OperationLog（操作审计日志）

`OperationLog` 只保存能够归属到管理员或普通用户的关键业务操作，不承载系统运行日志、后台 Worker 事件、普通页面浏览和高频自动保存。诊断报告正文读取属于明确纳入统计的用户操作，使用 `diagnostic_report.view` 记录；报告状态轮询不记录。管理员与普通用户共用一张表，通过操作发生时的角色快照筛选。

```prisma
model OperationLog {
  id                 String   @id @default(uuid()) @db.VarChar(191)
  occurredAt         DateTime @default(now())
  requestId          String?  @db.VarChar(64)
  actorUserId        String?  @db.VarChar(191)
  actorNameSnapshot  String   @db.VarChar(191)
  actorEmailSnapshot String   @db.VarChar(191)
  actorRoleSnapshot  String   @db.VarChar(32)
  module             String   @db.VarChar(64)
  action             String   @db.VarChar(128)
  summary            String   @db.VarChar(500)
  result             String   @db.VarChar(32)
  resourceType       String?  @db.VarChar(64)
  resourceId         String?  @db.VarChar(191)
  changes            Json?
  method             String   @db.VarChar(16)
  path               String   @db.VarChar(500)
  statusCode         Int
  ipAddress          String?  @db.VarChar(64)
  userAgent          String?  @db.VarChar(512)
  errorCode          String?  @db.VarChar(64)
  createdAt          DateTime @default(now())
}
```

| 字段 | 说明 |
|------|------|
| `requestId` | 关联同一次 HTTP 请求的操作审计与服务端运行日志；历史记录为空 |
| `actorUserId` | 关联操作者；用户删除后置空，身份快照继续保留 |
| `actorNameSnapshot` / `actorEmailSnapshot` | 操作发生时的账号快照，不跟随用户后续资料变化 |
| `actorRoleSnapshot` | 操作发生时的 `admin` / `student` 身份，用于后台角色筛选 |
| `module` / `action` | 稳定的业务模块与操作编码，例如 `profile` / `profile.update` |
| `summary` | 面向后台管理员展示的操作说明 |
| `result` | `success` / `failure`，按最终 HTTP 状态确定 |
| `resourceType` / `resourceId` | 被操作业务对象的类型和标识 |
| `changes` | 仅保存业务白名单字段的前后值；密码只记录是否修改，不保存密码或哈希 |
| `method` / `path` / `statusCode` | 本次业务操作对应的接口上下文，查询参数不写入路径 |
| `ipAddress` / `userAgent` | 操作来源快照，用于后台审计定位 |
| `errorCode` | 失败响应中的业务错误码，可空 |

审计范围包括账号资料、密码、备考偏好、考试开始与提交、诊断报告正文查看、支付订单，以及管理员的用户权限、支付策略、成本、试卷和考纲操作。考试进度自动保存、诊断报告状态轮询、支付状态轮询、验证码发送和逐页解析等高频请求不进入审计表。

学生用户行为分析使用已提交的 `ExamRecord` 统计诊断、试题库和模考完成次数，并复用本表的 `diagnostic_report.view` 成功记录统计报告查看；通用操作概览固定读取 `actorRoleSnapshot = student` 的角色快照并排除 `auth` 模块。缺少 `actorUserId` 的历史日志只计总操作次数，不计活跃人数与人均次数。最长 90 天范围内实时聚合，不新增汇总表或数据库迁移；报告查看次数只能从该审计动作上线后开始积累。
