# 试卷上传与结构化导入技术方案

## 一、当前边界

当前正式导入入口为 JSON 和“单一 JSON 代码块”的 Markdown。它们面向已经完成识别、校对与解析的成品试卷数据。

旧 PDF / 图片调用 Qwen 自动解析的链路仅作历史兼容，不是当前活跃产品路径；除非专项恢复该能力，新功能不得依赖旧解析任务或 `Paper.questions`。

所有正式题目最终通过 `syncPaperQuestions` 写入 `Question` 表：

- `Question` 是上传预览、考试、报告、题库和错题本的唯一正式题目数据源。
- `Paper.questions` 只保留为旧数据回填输入，不得由新导入流程读写。
- 试卷级交付方式、模块配置、休息策略和来源说明写入 `Paper`。

## 二、支持的数据容器

### 2.1 兼容扁平试卷

```json
{
  "metadata": {},
  "questions": []
}
```

仅适用于普通练习、题库或仍按整卷连续作答的历史兼容数据。ESAT 与 TMUA 的 `realPaper` 诊断卷发布前必须转换为分段结构。

### 2.2 ESAT 三模块等效诊断卷

```json
{
  "metadata": {
    "code": "ESAT-EQUIV-2023-M1-PHY-M2",
    "title": "ESAT 2023 Equivalent Diagnostic",
    "examType": "ESAT",
    "year": 2023,
    "paperType": "realPaper",
    "assemblyType": "legacy_equivalent",
    "deliveryMode": "section_sequence"
  },
  "sections": [
    {
      "code": "maths1",
      "sectionType": "subject",
      "order": 1,
      "questions": []
    }
  ]
}
```

上例只展示容器字段，正式文件必须提供恰好三个非空 section、必须包含 `maths1`，每个 section 的 `sectionType` 为 `subject`。服务端为每科派生 40 分钟时长和 180 秒可跳过休息。

### 2.3 TMUA 两卷诊断卷

TMUA 使用两个 `paper` section。上传文件不携带分卷名称、时长或切换策略：

```json
{
  "metadata": {
    "code": "TMUA-2018",
    "title": "TMUA 2018 Diagnostic Paper",
    "examType": "TMUA",
    "year": 2018,
    "paperType": "realPaper",
    "assemblyType": "original",
    "deliveryMode": "section_sequence"
  },
  "sections": [
    {
      "code": "paper1",
      "sectionType": "paper",
      "order": 1,
      "questions": []
    },
    {
      "code": "paper2",
      "sectionType": "paper",
      "order": 2,
      "questions": []
    }
  ]
}
```

正式文件必须为每卷提供 20 道完整 `single_choice` 题目。服务端派生每卷 75 分钟、整卷 150 分钟；Paper 1 锁定后直接启动 Paper 2。

公开主格式固定为：

- 分段容器：`sections[].questions`。
- 分段稳定标识：`sections[].code`。
- ESAT `sectionType = subject`；代码为 `maths1`、`maths2`、`physics`、`chemistry`、`biology`。
- TMUA `sectionType = paper`；代码依次为 `paper1`、`paper2`。
- 题目内容字段使用 `contentBlocks`、`questionType`、`classification`、`source`、`learningAnalysis`。
- `name`、`duration`、`durationSeconds`、`transitionAfter` 不属于 section 数据。

兼容读取但不再生成：

- `diagnostic-paper-v2` 的 `modules[].questions`。
- 当前两份组合样例使用的根级 `questions[].items`。
- 早期 `modules[].items`。
- 早期 `component_code/component_order/component_question_number`。
- `metadata.deliveryMode = "module"` 和 `metadata.breakDurationSeconds`。

## 三、导入流程

### 3.1 JSON

```text
选择 .json
  → 前端读取 metadata + sections 并生成分段/题目预览
  → POST /papers/import-json
  → validateStandardPaperDocument
  → 结构校验、兼容归一化、安全清洗
  → 创建或更新 Paper
  → syncPaperQuestions 写入 Question
  → 返回 Paper ID 与 warnings
```

### 3.2 Markdown

```text
选择 .md
  → 只允许一个 JSON 代码块
  → POST /papers/import-markdown
  → processMarkdownImport
  → 与 JSON 入口共用相同校验和清洗
  → 写入 Paper 与 Question
```

Markdown 不是多题块拼接容器，也不接受纯数组。新版代码块内必须是包含 `metadata` 和 `sections` 的完整标准文档。

### 3.3 更新保护

`syncPaperQuestions` 在事务内同步题目。试卷一旦存在 `ExamRecord`，不得覆盖题目或模块结构；应创建新试卷版本，保证历史作答和诊断报告可复现。

## 四、校验与归一化

服务端校验器负责：

- 元数据类型、考试类型和试卷类型。
- `metadata.code/title/year/examType/paperType/assemblyType/deliveryMode` 完整，`deliveryMode = section_sequence`。
- ESAT 恰好三个不同 subject section 且必须包含 `maths1`。
- TMUA 恰好两个 paper section，必须依次为 `paper1`、`paper2`，每卷 20 题。
- section `code/sectionType/order/questions`，并拒绝名称、时长与跳转规则字段。
- 分段时长和切换规则由服务端考试配置派生：ESAT 每科 40 分钟、休息 180 秒可跳过；TMUA 每卷 75 分钟、无休息。
- section 内题号唯一；入库时另生成全卷连续 `Question.number`。
- ESAT/TMUA 分段诊断题目仅允许 `single_choice`，正确答案必须是选项标签子集。
- `title` 与首个 `contentBlocks` 文本一致。
- `paragraph.align` 为可选字段且目前只允许 `center`；其他值拒绝导入。
- `image_ref`、图像选项与 `images[].id` 引用完整。
- 每题 `classification`、`source`、`learningAnalysis` 完整；来源 section 和题号必须与外层一致。

新版文件在上传边界归一化后，数据库字段为：

| 外部语义                         | Question 字段            |
| -------------------------------- | ------------------------ |
| 来源稳定题号 `question.code`     | `sourceQuestionCode`     |
| `sections[].code`                | `moduleCode`             |
| `sections[].order`               | `moduleOrder`            |
| section 内 `number`              | `moduleQuestionNumber`   |
| `contentBlocks`                  | `meta.content_blocks`    |
| `classification.subjectCode`     | `subjectCode`            |
| `classification.topicCode`       | `topicCode`              |
| `classification.knowledgePoints` | `knowledgePoints`        |
| `learningAnalysis`               | `meta.learning_analysis` |
| 全卷连续题号                     | `number`                 |

## 五、安全与渲染

JSON 和 Markdown 共用相同的结构校验入口：

- 位图地址只允许站内相对地址、HTTP(S)、临时 blob 和常见位图 base64，不接受 data:SVG/HTML。
- SVG 只通过 `<img src="data:image/svg+xml,...">` 展示，不使用 `v-html` 注入 DOM。
- 当前不对全部题目文本执行通用 HTML 正则清洗，因为该方式会误删数学表达式中的 `<`、`>`；恢复清洗前必须采用能够区分数学文本和标签的字段级方案。
- 作答接口对白名单字段做深度投影，永不下发 `answer`、`learning_analysis` 或嵌套正确标记。

前端正式渲染链路：

- 上传的 `contentBlocks` 在边界归一化为 `content_blocks`，并决定文字与题图顺序。
- `paragraph.align = center` 时，该段落作为独立内容块整体居中；未填写时维持普通题干流。
- `LatexText` 支持 `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]`。
- SVG 编码为 `data:image/svg+xml` 后通过 `<img>` 展示，不使用上传内容的 `v-html`。
- 解析优先读取 `learning_analysis.correct_solution`，兼容历史 `solution`。

## 六、分段诊断运行时

发布后的分段卷由服务端冻结 `structureSnapshot`，只下发当前分段题目。每个分段独立计时且完成后答案锁定。ESAT 在前两个科目后进入 180 秒可跳过休息；TMUA 在 Paper 1 后直接启动 Paper 2，不产生休息阶段。刷新或重新进入时，阶段、截止时间和答案都从服务端恢复。

最终交卷只读取已持久化的 `AnswerRecord`。休息不计入 `activeDurationSeconds`。本轮 TMUA 改造覆盖上传、展示和在线答题；TMUA 诊断报告不属于本轮交付范围。
