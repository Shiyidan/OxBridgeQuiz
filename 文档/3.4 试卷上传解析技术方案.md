# 试卷上传与结构化导入技术方案

## 一、当前边界

当前正式导入入口为 JSON 和“单一 JSON 代码块”的 Markdown。它们面向已经完成识别、校对与解析的成品试卷数据。

旧 PDF / 图片调用 Qwen 自动解析的链路仅作历史兼容，不是当前活跃产品路径；除非专项恢复该能力，新功能不得依赖旧解析任务或 `Paper.questions`。

所有正式题目最终通过 `syncPaperQuestions` 写入 `Question` 表：

- `Question` 是上传预览、考试、报告、题库和错题本的唯一正式题目数据源。
- `Paper.questions` 只保留为旧数据回填输入，不得由新导入流程读写。
- 试卷级交付方式、模块配置、休息策略和来源说明写入 `Paper`。

## 二、支持的数据容器

### 2.1 扁平试卷

```json
{
  "metadata": {},
  "questions": []
}
```

适用于 TMUA 或仍按整卷连续作答的历史试卷。

### 2.2 ESAT 三模块等效诊断卷

```json
{
  "schemaVersion": "diagnostic-paper-v2",
  "metadata": {
    "paperName": "ESAT 2023 Equivalent Diagnostic",
    "year": 2023,
    "duration": 120,
    "examType": "ESAT",
    "paperType": "realPaper",
    "totalQuestions": 81,
    "deliveryMode": "module_sequence",
    "breakPolicy": {
      "durationSeconds": 180,
      "skippable": true
    },
    "assemblyType": "legacy_equivalent",
    "sourceExamTypes": ["ENGAA", "NSAA"]
  },
  "modules": [
    {
      "code": "maths1",
      "order": 1,
      "subject": "Mathematics 1",
      "subject_code": "110000",
      "duration": 40,
      "totalQuestions": 27,
      "questions": []
    }
  ]
}
```

上例只展示容器字段，正式文件必须提供恰好三个非空模块和完整题目。完整题目字段见 [standard.md](standard.md)。

公开主格式固定为：

- 模块容器：`modules[].questions`。
- 模块稳定标识：`modules[].code`。
- 归一化题目标识：`module_code`、`module_order`、`module_question_number`。
- ESAT 模块代码：`maths1`、`maths2`、`physics`、`chemistry`、`biology`。

兼容读取但不再生成：

- 当前两份组合样例使用的根级 `questions[].items`。
- 早期 `modules[].items`。
- 早期 `component_code/component_order/component_question_number`。
- `metadata.deliveryMode = "module"` 和 `metadata.breakDurationSeconds`。

## 三、导入流程

### 3.1 JSON

```text
选择 .json
  → 前端读取完整文档并生成模块/题目预览
  → POST /papers/import-json
  → validateStandardPaperDocument
  → 结构校验、兼容归一化、安全清洗
  → 创建或更新 Paper
  → syncPaperQuestions 写入 Question
  → 返回 Paper ID 与 warnings
```

### 3.2 Markdown

```text
选择 .md
  → 只允许一个 JSON 代码块
  → POST /papers/import-markdown
  → processMarkdownImport
  → 与 JSON 入口共用相同校验和清洗
  → 写入 Paper 与 Question
```

Markdown 不是多题块拼接容器，也不接受纯数组。代码块内必须是包含 `metadata` 和 `questions/modules` 的完整标准文档。

### 3.3 更新保护

`syncPaperQuestions` 在事务内同步题目。试卷一旦存在 `ExamRecord`，不得覆盖题目或模块结构；应创建新试卷版本，保证历史作答和诊断报告可复现。

## 四、校验与归一化

服务端校验器负责：

- 元数据类型、考试类型和试卷类型。
- ESAT 恰好三个不同模块且必须包含 `maths1`。
- 模块 `code/order/subject_code/duration/totalQuestions`。
- `metadata.duration` 等于模块作答时长之和，不含休息。
- `breakPolicy.durationSeconds = 180` 且 `skippable = true`。
- 模块题号卷内唯一；入库时另生成全卷连续 `Question.number`。
- ESAT 题目仅允许 `single_choice`，正确答案必须是选项标签子集。
- `title` 与首个 `content_blocks` 文本一致。
- `image_ref`、图像选项与 `images[].id` 引用完整。
- 每题真实 `source_examType`、年份、来源稳定 `code`。

兼容文件归一化后，数据库字段为：

| 外部语义 | Question 字段 |
| --- | --- |
| 来源稳定题号 `question.code` | `sourceQuestionCode` |
| 模块 `code` | `moduleCode` |
| 模块 `order` | `moduleOrder` |
| 模块内 `number` | `moduleQuestionNumber` |
| 全卷连续题号 | `number` |

## 五、安全与渲染

JSON 和 Markdown 共用相同的递归清洗入口：

- 先解码 HTML 实体，再移除脚本、危险标签、事件属性和 `javascript:` 协议。
- SVG 移除脚本、外部对象、样式块、事件属性和外部引用。
- 作答接口对白名单字段做深度投影，永不下发 `answer`、`learning_analysis` 或嵌套正确标记。

前端正式渲染链路：

- `content_blocks` 决定文字与题图顺序。
- `LatexText` 支持 `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]`。
- SVG 编码为 `data:image/svg+xml` 后通过 `<img>` 展示，不使用上传内容的 `v-html`。
- 解析优先读取 `learning_analysis.correct_solution`，兼容历史 `solution`。

## 六、模块化诊断运行时

发布后的模块卷由服务端冻结 `structureSnapshot`，只下发当前模块题目。每个模块独立计时；模块完成后答案锁定，前两个模块进入 180 秒休息，学生可跳过。刷新或重新进入时，阶段、截止时间和答案都从服务端恢复。

最终交卷只读取已持久化的 `AnswerRecord`。休息不计入 `activeDurationSeconds`，报告按三个模块分别估分，不生成虚构的 ESAT 合成总分。
