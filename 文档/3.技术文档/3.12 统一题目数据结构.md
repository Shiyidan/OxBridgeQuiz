# 统一题目数据结构

2026-10-14 起，诊断真题、独立试题库和模考引用的正式题目共用 `Question`，单题文档统一为 `id/code/content/solution/meta`。年度诊断按年度、科目保存；题目本身保存所属年度容器及科目内题号，每名学生选科后的顺序固定在自己的答卷快照中。

## 文档格式

以下示例说明单题结构。导出时 `id`、管理状态和时间来自数据库，上传不能用这些字段覆盖原记录。

```json
{
  "id": "稳定题目 ID",
  "code": "系统内全局唯一编码",
  "content": {
    "title": "Find the value of x.",
    "blocks": [{ "type": "paragraph", "text": "Find $x$ if $2x=4$.", "inline": true }],
    "options": [{ "label": "A", "text": "2" }, { "label": "B", "text": "3" }],
    "images": [],
    "examType": "ESAT",
    "questionType": "single_choice",
    "difficulty": "medium",
    "subject": "Mathematics 1",
    "subjectCode": "110000",
    "topic": "Algebra",
    "topicCode": "110100",
    "qualityTier": null,
    "knowledgePoints": []
  },
  "solution": {
    "answer": ["A"],
    "correctSolution": "两边同时除以 2，得到 x=2。",
    "examFocus": "一元一次方程",
    "commonErrorCauses": ["等式两边未进行相同运算"],
    "reviewGuidance": "复习等式的基本性质。"
  },
  "meta": {
    "source": { "questionCode": "ESAT-2023-M1-001", "examType": "ENGAA", "year": 2023 },
    "paperId": "所属年度试卷 ID",
    "number": 1,
    "moduleCode": "maths1",
    "moduleOrder": 1,
    "moduleQuestionNumber": 1,
    "status": "draft",
    "importBatchId": null,
    "revision": null,
    "createdAt": "2026-10-14T00:00:00.000Z",
    "updatedAt": "2026-10-14T00:00:00.000Z",
    "publishedAt": null,
    "archivedAt": null
  }
}
```

- `content` 包含题目内容与分类。`title` 保留供错题本等列表概览、搜索和无内容块时展示；完整题干以 `blocks` 为准。当前迁移不重写历史 `title`，不改变历史题目文字。
- `solution` 保存判分答案和学习解析。已存在的解析扩展字段也保留，不因为分组变化而丢失。
- `meta.source` 描述原始来源；其 `questionCode` 与顶层系统唯一 `code` 的用途不同。修订关系输出为 `meta.revision`，管理信息与题号也在 `meta` 中。
- 未组卷的独立题目不需要填写试卷归属和模块题号；字段可为空。已有来源、生成和修订扩展按实际业务保留。

## 物理存储与公共入口

统一文档不要求数据库所有查询字段也藏进 JSON。以下列继续承担索引、外键和管理约束，由公共工具构造文档，避免重复保存分类和管理字段。

| 数据库位置 | 唯一保存内容 | 文档对应位置 |
| --- | --- | --- |
| `Question.content` | `blocks/options/images` | `content` 的内容字段 |
| `Question.solution` | `answer` 及 camelCase 学习解析、解析扩展 | `solution` |
| `Question.meta` | `source`、来源/修订及其他保留扩展 | `meta` 的来源和扩展 |
| `title/examType/questionType/difficulty/subject/subjectCode/topic/topicCode/qualityTier/knowledgePoints` | 可检索的概览及分类 | `content` 对应字段 |
| `id/uniqueCode` | 稳定身份与唯一编码 | `id/code` |
| `sourceQuestionCode` | 来源编号索引 | `meta.source.questionCode` |
| `paperId/number/moduleCode/moduleOrder/moduleQuestionNumber` | 所属容器和稳定题目位置 | `meta` 对应字段 |
| 批次、版本关系、状态和时间列 | 数据库关系及系统管理信息 | `meta`，版本关系聚合到 `revision` |

最终 schema 已删除 `Question.options`、`Question.answer`、`Question.syllabusPoints`。`attemptPayload` 也已删除。禁止恢复旧列读取或把正文、选项、答案和解析重新塞回 `meta`。`Paper.questions` 仍仅用于旧数据回填，不能作为新业务题目来源。

公共入口如下：

- `buildQuestionStorage` 将统一内部输入构造为三个 JSON 存储字段；`syncPaperQuestions` 是诊断真题和独立题库共同的正式写入入口。独立题库传 `paperId=null` 和导入批次，只追加题目。
- `formatQuestionDocument` 将存储列聚合为以上完整文档；`canonicalQuestionToInput` 将文档转换为公共写入入口使用的输入，不允许上传文件改写原题 ID、状态、时间或管理关系。
- `formatQuestionRow` 只读取新存储，投影为现有题卡使用的固定 DTO，例如 `content_blocks`、`options`、`answer`、`learning_analysis`。这不是多版本存储兼容，页面不得再尝试读取旧数据库字段。
- `getQuestionAnswer` 从 `solution.answer` 读取判分答案；损坏或缺失的答案结构必须报错，不能默认全部判错。
- 学生作答查询 `attemptQuestionSelect` 不选取 `solution`；`formatQuestionForAttempt` 再对题干、选项、图片、知识点逐层白名单投影，防止上传扩展携带答案或解析。管理预览和交卷后查看可以获得完整内容。

## 年度诊断导入与历史记录

年度诊断文件外层为 `{ format: "paper-content-solution-meta-v1", paper, questions }`，`questions` 使用上述单题文档。`paper.moduleConfig` 声明当年完整模块：ESAT 五科，TMUA Paper 1/Paper 2。其他既有普通试卷和独立题库上传外层协议保留，由入口校验器转换后写入同一种 `Question` 存储。

年度容器仍使用 `Paper`，`assemblyType=annual_subjects`。ESAT 开考要求数学 1 必选、另外四科选两科；所选题目、实际模块顺序和题目顺序冻结于答卷结构与作答明细中，不能回写共享题目。TMUA 保持两卷顺序。

此次存储迁移原地更新 JSON，但保留所有原题 ID、标量字段、更新时间和关联。年度分科内容另建新试卷和题目，旧组合卷、旧题、原作答明细、分数和报告不删除、不替换；用户查看历史记录仍使用当时的关联和内容。后续修改已有作答的题目或模块结构必须建立新版本。

## 旧环境升级顺序

**有旧数据的数据库必须分阶段升级。不能直接对完整迁移目录运行一次 `migrate deploy`，因为它会连续执行加列和删列，跳过内容回填。** 先暂停应用题目写入和后台任务，完成数据库备份，明确目标环境；本地完成状态不能替代测试、线上各自的审计。

### 前置阶段：尚有 attemptPayload 的环境

已经完成 `20261014010000_unify_question_meta` 的环境跳过本阶段；仍有该旧列的环境先保留能读取它的旧 Prisma Client。

1. 不先运行会覆盖旧 Client 的 `npm ci` 或 `prisma generate`。将 `migrate-question-meta.ts` 及其依赖维护脚本放入使用旧 Client 的目录，确保可运行 `tsx`；需要安装维护依赖时使用独立维护目录。
2. 在 `api` 目录、正确 `API_ENV_FILE` 下执行：

   ```bash
   npm run migrate:question-meta -- --dry-run --environment=local
   npm run migrate:question-meta -- --apply --confirm=MERGE_QUESTION_META --environment=local
   ```

   测试和生产分别替换为 `test`、`prod`。旧 package.json 没有命令时使用该目录的 `tsx scripts/migrate-question-meta.ts`。默认备份位置 `.private/question-meta-migration/`，可用 `--backup-dir=<目录>` 指定。
3. 全量备份和合并验证成功、零冲突且零待补项后，才允许执行 `20261014010000_unify_question_meta` 的删列迁移。此时的正文仍在 `meta`，继续执行下方两阶段升级。

### 第一阶段：只加列，再回填

1. 在独立维护目录准备 `question-content-stage.prisma` 的副本和与其同级的 `migrations` 目录。原样复制仓库中的迁移锁及**截至 `20261014020000_add_question_content_solution` 的全部迁移**；不要包含 `20261014030000_finalize_question_content_solution`。不得修改或删除仓库原始迁移文件，也不能手改迁移 SQL。维护目录用于限定 Prisma 本次可执行的迁移集合。
2. 为 Prisma CLI 设置与应用一致的目标 `DATABASE_URL`；`API_ENV_FILE` 由维护脚本读取，不能代替 Prisma CLI 的数据库环境配置。对维护目录 schema 执行 `prisma migrate deploy --schema <维护目录>/question-content-stage.prisma`，只推进到加列阶段。若前置 meta 迁移尚待应用，本次可一起应用已通过回填校验的该迁移。
3. 在项目 `api` 中用正常 Prisma 引擎生成阶段 Client：

   ```bash
   ./node_modules/.bin/prisma generate --schema prisma/question-content-stage.prisma
   npm run migrate:question-content -- --dry-run --environment=local
   npm run migrate:question-content -- --apply --confirm=SPLIT_QUESTION_CONTENT --environment=local
   ```

   Windows 使用 `npm.cmd` 和 `./node_modules/.bin/prisma.cmd`。阶段 schema 同时保留旧列和可空 `content/solution`，只供迁移使用；不要在阶段 Client 状态启动应用。
4. 脚本先审计全库，再备份全部 Question 行为 gzip NDJSON，默认 `.private/question-content-migration/`。新旧字段冲突、损坏 JSON、解析命名冲突，或 `syllabusPoints` 中有未被 `knowledgePoints` 覆盖的标注，均停止且禁止删列。逐题事务验证正文、图片、答案、解析、未知扩展、ID 和其他标量不变，显式保持 `updatedAt`。
5. 保存备份和 `verified-*.json` 结果。仅当 `errors=[]`、`pending=0`、验证题数与迁移前一致时继续。运行中断时保留旧列及所有备份，在排除冲突后重跑脚本；不要丢弃首次备份。

### 第二阶段：删旧列，恢复服务

1. 回填验证成功后，回到项目完整迁移目录执行正常 `prisma migrate deploy --schema prisma/schema.prisma`。本阶段执行 `20261014030000_finalize_question_content_solution`，删除 `options/answer/syllabusPoints`，将 `content/solution` 设为非空。
2. 执行正常 `prisma generate --schema prisma/schema.prisma` 和 `prisma migrate status --schema prisma/schema.prisma`；不得留下阶段 Client 或无引擎生成模式。停止占用引擎 DLL 的 API 进程后再生成。
3. 构建后端并运行回归，对照备份逐题核验，验证历史列表、答卷详情、逐题解析、报告和未交卷恢复。年度分科重组应另做完整备份及去重审计，不覆盖旧关联。
4. 校验成功再启动应用。删列后不能仅回滚旧代码；回退必须恢复相应 schema 和备份内容。新空数据库无需回填，可直接执行全部迁移并生成最终 Client。

本次仅改造开发环境；测试和生产执行上述升级属于各自部署流程，尚未执行。

```bash
npm run test:modular-diagnostic

```

`test:question-document` 为纯内存检查，覆盖文档往返、迁移无损、冲突拒绝和作答白名单。数据库回归使用独立测试 fixture 并清理；执行期间应避开全表历史哈希对比，防止把测试临时记录误判为业务数据变化。最终验收必须同时核对历史记录数量、内容及关联，不能只以构建通过替代。
