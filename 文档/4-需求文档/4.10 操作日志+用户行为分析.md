# 4.10 操作日志与用户行为分析

> 文档对象：产品经理、测试人员、运营管理员与问题排查人员
> 文档性质：当前操作日志与学生用户行为分析的功能边界、统计口径及验收依据
> 当前版本日期：2026-10-06
> 本文只描述用户可感知的功能、检查规则和未实现范围，不描述开发过程。

---

## 1. 功能边界与目的

### 1.1 功能目标

本功能包含“操作日志”和“用户行为分析”两个后台菜单：

- 操作日志用于回答“谁在什么时间执行了什么关键操作、操作是否成功、修改了哪些字段、如何继续定位同一次请求”。
- 用户行为分析用于回答“学生主要使用诊断测试、试题库还是模考，以及完成诊断后是否继续查看分析报告”。

操作日志承担业务审计和问题定位职责；用户行为分析承担产品使用偏好判断职责。两者共享部分关键操作数据，但展示目标和统计口径不同。

### 1.2 角色与权限边界

| 角色 | 操作日志 | 用户行为分析 |
|---|---|---|
| 未登录访客 | 不可访问 | 不可访问 |
| 普通学生 | 不可访问后台页面；学生本人产生的部分关键操作会被记录 | 不可访问后台页面；符合口径的学习活动会进入汇总统计 |
| 会员学生 | 权限与普通学生一致 | 权限与普通学生一致，不因会员状态改变统计规则 |
| 管理员 | 可以查看全部管理员和普通用户操作日志及详情 | 可以查看学生汇总行为，不统计管理员行为 |

后台入口和数据接口都必须校验管理员身份。仅隐藏前端菜单不视为完成权限控制。

### 1.3 当前交付范围

当前版本包含：

1. 管理员按角色、模块、结果、关键词、行为编码和时间查询操作日志。
2. 管理员查看操作日志详情、字段修改前后值和 Request ID。
3. 管理员通过 Request ID 关联同一次请求的运行日志进行问题排查。
4. 管理员查看最近 7 天、30 天、90 天或自定义时间范围的学生行为分析。
5. 统计诊断测试完成次数、诊断报告查看次数、试题库练习完成次数、模考完成次数，以及错题本和收藏夹中的题目查看次数。
6. 展示三类学习活动的使用占比、学生偏好分布和每日趋势。
7. 展示用户访问与注册分布、付费转化、累计付费用户趋势、付费用户地域与转化时长。

### 1.4 核心术语

| 术语 | 含义 | 检查重点 |
|---|---|---|
| 操作日志 | 能够归属到具体用户的关键业务操作记录 | 不是所有请求都会产生操作日志 |
| 操作人快照 | 操作发生时保存的用户名、邮箱和角色 | 后续修改用户资料或角色不应改写历史快照 |
| 成功操作 | 对应业务请求最终成功 | 页面显示“成功” |
| 失败操作 | 对应业务请求最终失败 | 页面显示“失败”，有业务错误码时可在详情查看 |
| Request ID | 标识一次请求的唯一编号 | 可复制，并用于关联运行日志中的同一次请求 |
| 字段变更 | 明确纳入记录范围的字段修改前后值 | 非修改类操作允许显示“无字段变更” |
| 产品完成次数 | 成功提交并形成已完成考试记录的次数 | 开始、恢复、自动保存和失败提交不计入 |
| 报告查看次数 | 学生成功打开诊断报告正文的次数 | 报告生成状态轮询和失败读取不计入 |
| 活跃学生 | 统计周期内至少产生一条符合当前统计口径且能关联学生的记录 | 同一学生重复操作只计一个活跃学生 |
| 使用占比 | 某类已完成学习活动次数占三类完成总次数的比例 | 报告查看次数不参与三类活动占比 |
| 同期 | 与当前统计范围长度相同、紧邻当前范围之前的时间段 | 用于计算环比变化 |
| 同期报告查看率 | 当期完成的诊断测试中，其报告也在同一统计周期内被成功打开的比例 | 不表示所有历史诊断报告的累计查看率 |

### 1.5 试卷类型与产品模块映射

| 试卷类型 `paperType` | 产品模块 | 计数条件 |
|---|---|---|
| `realPaper` | 诊断测试 | 成功提交并形成已完成记录 |
| `aiPaper` | 试题库练习 | 成功提交并形成已完成记录 |
| `mockPaper` | 模考练习 | 成功提交并形成已完成记录 |

本功能只负责统计已有的模考完成记录，不负责提供模考入口、模考组卷或模考答题功能。没有符合条件的模考记录时，模考次数显示为 0。

### 1.6 操作日志记录范围

只有下表中明确列出的关键操作进入操作日志。未列出的普通查询、页面浏览、状态轮询和后台任务不应因为访问接口而自动产生操作日志。

| 操作对象 | 当前纳入的关键操作 | 详情中的操作编码 |
|---|---|---|
| 账号与安全 | 注册、登录、重置密码、修改密码、修改个人资料、退出当前设备、退出全部设备、移除登录设备 | `auth.register`、`auth.login`、`auth.password.reset`、`auth.password.change`、`profile.update`、`auth.logout`、`auth.logout_all`、`auth.session.revoke` |
| 学生偏好 | 修改备考偏好 | `profile.exam_preferences.update` |
| 考试与报告 | 开始或恢复考试、提交考试、读取诊断分析报告正文 | `exam.start`、`exam.submit`、`diagnostic_report.view` |
| 错题本与收藏夹 | 成功查看具体错题、成功查看收藏题目、单题或批量移出错题 | `mistake_notebook.view`、`favorite_notebook.question_view`、`mistake_notebook.remove` |
| 学生支付 | 创建支付订单、关闭支付订单 | `payment.order.create`、`payment.order.close` |
| 用户管理 | 管理员修改用户角色、修改用户权限或会员权益 | `admin.user.role.update`、`admin.user.access.update` |
| 支付管理 | 修改支付策略、发起退款、查询退款结果、执行对账、复核支付异常、关闭支付异常 | `admin.payment_config.update`、`admin.payment_refund.create`、`admin.payment_refund.query`、`admin.payment_reconciliation.run`、`admin.payment_reconciliation.recheck`、`admin.payment_reconciliation.resolve` |
| 营收成本 | 新增成本记录、修改成本记录 | `admin.revenue_cost.create`、`admin.revenue_cost.update` |
| 试卷题库 | 修改、删除、发布试卷，导入 JSON 试卷 | `admin.paper.update`、`admin.paper.delete`、`admin.paper.publish`、`admin.paper.import_json` |
| 教学大纲 | 上传考纲、启用考纲、停用考纲 | `admin.syllabus.create`、`admin.syllabus.enable`、`admin.syllabus.disable` |
| 学习资料 | 上传 PDF 学习资料、上传年度真题资料组、发布或撤回资料、删除学习资料 | `admin.study_resource.upload`、`admin.study_resource.past_paper_upload`、`admin.study_resource.status_update`、`admin.study_resource.delete` |

### 1.7 功能边界检查规则

1. 操作必须能够归属到具体管理员或普通用户，才进入操作日志。
2. 系统 Worker、定时任务、服务启动、运行错误和其他系统事件不作为“用户操作”展示。
3. 考试自动保存、诊断报告状态轮询、支付状态轮询、验证码发送和普通列表查询不进入操作日志。
4. 诊断报告正文读取属于明确的用户操作；成功读取计为成功查看，失败读取可以形成失败日志，但不计入报告查看统计。
5. 操作日志不保存密码、验证码、令牌、支付密钥或完整敏感请求参数。
6. 接口路径不包含查询参数，避免搜索内容、邮箱或其他输入被附带保存。
7. 字段前后值只记录业务允许的字段；没有前后值的操作显示“本次操作没有字段前后值”。
8. 新产生的操作日志应包含 Request ID；历史日志允许没有 Request ID。
9. 本机 IPv6 地址 `::1` 显示为 `127.0.0.1`，IPv4 映射地址显示为对应 IPv4；真实 IPv6 保持原格式。
10. 操作日志保存失败不得把已经完成的业务操作改成失败，但该次操作可能无法在日志页面查询到。

### 1.8 后台分析的统一封禁口径

后台分析按查询时的账号状态，统一剔除当前封禁用户。适用范围包括注册人数与地域、产品使用、付费转化、累计付费用户趋势、累计付费地域和时长、营收分析及员工赠卡统计。总览、明细、人数、次数、金额、占比、分组、趋势和上一周期比较使用同一筛选范围，分页总数也随之调整。

封禁会使该用户在所选历史期间的数据退出统计，解封后重新查询即可恢复，无需补录。账号、订单、付款退款、作答、赠卡和审计原始记录保留。支付运营中的订单处理与对账告警承担账务追溯职责，仍覆盖完整业务记录；封禁用户管理和单个账号详情继续可查。

网站访问按 IP 去重，新增已登录访问关联实际账号，以支持封禁筛选。同一 IP 共用网络的正常访问、匿名访问，以及历史未关联账号的记录按第 3.6 节处理，不通过 IP 猜测用户身份。

## 2. 页面描述

### 2.1 后台入口与权限

管理员登录后台后，在左侧导航看到：

- 用户行为分析
- 操作日志

普通学生、会员学生和未登录用户均不应看到或访问这两个后台页面。登录失效后访问页面，应进入统一登录失效处理流程。

### 2.2 操作日志页面

#### 2.2.1 默认状态

- 默认角色为“全部”。
- 默认不限制模块、结果、关键词和时间。
- 默认按发生时间倒序展示，最新操作在最前；时间相同时保持稳定顺序。
- 默认每页 20 条，使用统一分页控件。
- 没有符合条件的数据时显示“暂无操作记录”。

#### 2.2.2 角色筛选

页面顶部提供：

- 全部
- 管理员操作
- 普通用户操作

点击角色后立即查询并回到第一页。角色判断以操作发生时保存的角色快照为准，不以用户当前角色为准。

#### 2.2.3 组合筛选

| 筛选项 | 规则 |
|---|---|
| 关键词 | 可匹配操作人、邮箱、操作内容、操作对象 ID 或 Request ID |
| 模块 | 可选择认证安全、个人资料、考试作答、支付订阅、用户管理、试卷题库、教学大纲、营收成本 |
| 结果 | 成功或失败 |
| 时间 | 支持开始时间和结束时间，包含两个边界时刻 |
| 行为编码 | 可通过地址栏条件恢复精确行为筛选 |

不同类型筛选条件之间采用“同时满足”规则；关键词内部多个匹配字段采用“任一命中”规则。

点击“查询”后使用当前填写条件查询并回到第一页。点击“重置”后恢复全部角色、全部模块、全部结果、无关键词、无行为编码和无时间限制，同时保留当前每页数量。

已应用的筛选条件同步到地址栏。刷新页面或复制当前链接后，页面应尽量恢复合法的筛选条件；无法识别的角色、模块、结果或时间条件应回退为默认值。

#### 2.2.4 列表字段

| 字段 | 展示规则 |
|---|---|
| 发生时间 | 按管理端浏览器当前时区展示完整日期和时间 |
| 操作人 | 展示操作发生时的用户名和邮箱快照 |
| 角色 | 管理员或普通用户 |
| 模块 | 展示业务模块中文名称 |
| 操作内容 | 展示该次操作的可读摘要 |
| 操作对象 | 展示对象类型和对象 ID；均缺失时显示 `-` |
| 结果 | 成功或失败 |
| 来源 IP | 以可读 IP 格式展示；缺失时显示 `-` |
| 详情 | 打开当前记录的操作详情 |

列表不展示字段修改前后值。字段前后值只在管理员打开详情后展示。

#### 2.2.5 操作详情

详情抽屉展示：

- 发生时间
- Request ID 及复制按钮
- 操作人、邮箱和角色快照
- 模块、操作内容和操作编码
- 操作对象
- 请求方法和状态码
- 来源 IP
- 接口路径
- 业务错误码（存在时）
- 设备信息
- 字段变更前后值

历史记录没有 Request ID 时，显示“历史日志暂无 Request ID”，不显示复制按钮。

复制成功提示“Request ID 已复制”；浏览器不允许复制时提示复制失败，管理员仍可手动选择文本。

#### 2.2.6 操作日志时间口径

操作日志列表和详情按管理端浏览器当前时区显示时间。测试不同电脑时区时，同一条日志显示的钟点可能不同，但应表示同一真实时刻。

### 2.3 用户行为分析页面

页面依次提供“用户访问”“产品使用”“转化分析”三个页签。转化分析单独保存日期与观察期选择，切换页签后返回保留查询结果。

#### 2.3.1 默认状态与时间选择

- 默认统计北京时间今天及此前 29 个自然日，共 30 天。
- 提供最近 7 天、最近 30 天和最近 90 天快捷选择。
- 支持自定义完整自然日范围。
- 不允许选择未来日期。
- 单次统计范围最少 1 天，最多 90 天。
- 所有产品趋势和日期分桶固定使用北京时间，不随管理端浏览器时区变化。

产品使用页签按日期查询，始终同时比较诊断测试、试题库练习和模考练习。

#### 2.3.2 产品使用偏好区

产品使用偏好区展示六个核心指标：

1. 诊断测试次数。
2. 查看分析报告次数。
3. 试题库练习次数。
4. 模考练习次数。
5. 查看错题本次数：成功打开具体错题的次数。
6. 查看收藏夹次数：成功打开具体收藏题目的次数。

三类学习活动卡片同时展示完成学生数及与上一等长周期相比的变化。报告查看卡片同时展示查看学生数和同期报告查看率。

错题本与收藏夹卡片各自展示查看题目的去重学生数，以及与上一等长周期相比的次数变化。仅进入列表、切换页签、筛选和翻页不增加查看次数。

#### 2.3.3 学习活动使用占比

使用占比只比较：

- 诊断测试完成次数
- 试题库练习完成次数
- 模考练习完成次数

报告、错题和收藏题目查看次数不参与三类完成活动的占比。页面展示每类活动的完成次数、占比、完成学生数和人均完成次数。

三类活动都为 0 时，各项占比应为 0，不出现除零错误、无穷大或非数字。

#### 2.3.4 学生偏好分布

学生偏好只根据同一统计周期内三类学习活动的完成次数判断：

| 条件 | 偏好结果 |
|---|---|
| 三类活动完成总数少于 3 次 | 数据不足 |
| 完成总数至少 3 次，且某一模块次数唯一最高 | 偏好该模块 |
| 完成总数至少 3 次，且两个或三个模块并列最高 | 混合使用 |

偏好分布展示：偏好诊断测试、偏好试题库、偏好模考、混合使用和数据不足五类人数及占比。

仅在统计周期内至少完成一次三类学习活动的学生进入偏好分布。只查看历史报告但当期没有完成学习活动的学生，不进入当期偏好分类。

#### 2.3.5 每日产品使用趋势

趋势图按北京时间自然日展示：

- 诊断测试完成次数
- 试题库练习完成次数
- 模考练习完成次数
- 分析报告查看次数
- 错题本题目查看次数
- 收藏夹题目查看次数

统计范围内没有数据的日期仍保留，次数显示为 0，避免趋势轴断开。

#### 2.3.6 网站访问与封禁口径提示

“用户访问”展示统计日期、独立 IP 与去重访问量、注册人数、每日趋势以及注册地域和备考偏好分布。页面明确提示已剔除当前封禁账号，并说明匿名及历史未关联账号的访问保留。封禁或解封后，管理员重新查询或刷新页面即可取得最新结果。

注册地区和付费地区统一读取用户资料中已保存的注册属地。新用户注册成功后在后台补全，历史用户逐步补全；未查到时显示“暂无属地”，不展示定位状态。成功定位后每 30 天更新，仍使用注册时的 IP，不随登录地点变化。更新失败保留已有属地，稍后自动重试；刷新分析页面只重新统计已保存结果，不重新定位。

#### 2.3.7 注册与付费用户的考试偏好

“用户偏好的考试类型”在用户访问页签中统一展示，提供“注册用户 / 付费用户”切换，默认注册用户。注册用户指所选期间新注册的普通学生；付费用户指所选期间至少发生一笔仍保留实付金额的真实付款的普通学生，包含更早注册和复购的用户，每人计一次。两组均按查询时的当前备考偏好划分为 ESAT、TMUA、ESAT + TMUA、未设置，选择两种考试的用户不重复分摊。图表显示人数和占比，分母为当前选择的人群总人数，不把两组人数之比称为注册转化率，也不用购买套餐包含的考试代替用户偏好。

两组都剔除管理员和封禁用户；付费组剔除赠送、零金额、未成功付款和全额退款订单，部分退款后仍保留实付金额的订单计入。用户只有所选范围之外的有效付款时，不进入本期付费组。切换人群不改变日期和其他图表，也不重新请求；查询或刷新时两组同时更新，已选择的人群保留。无数据分别提示“所选期间暂无新注册用户”或“所选期间暂无有效付费用户”。原转化分析中的“不同备考方向的转化”表移除，不再展示分组激活、转化率及首付时长。

验收时，先查询所选期间并记录注册偏好人数，再切到付费用户：更早注册但本期付款者计入，复购仍只计一人；套餐考试与当前偏好不同时以偏好为准。全额退款后重新查询，该订单不再贡献付费人数；部分退款保留实付时仍计入。封禁后两组同时剔除，解封重新查询后恢复。缩短日期范围时按各自事件日期筛选；切换到空人群时清除原扇区并显示对应提示，查询失败时保留上次结果和范围。

## 3. 核心流程与检查规则

### 3.1 操作日志形成规则

当用户执行一项已纳入范围的关键操作时，应按照以下业务结果形成记录：

1. 识别操作发生时的用户身份。
2. 保存用户名、邮箱和角色快照。
3. 记录发生时间、模块、操作编码、可读摘要和操作对象。
4. 记录成功或失败结果，以及对应请求的状态码和业务错误码。
5. 对允许记录修改内容的操作，保存白名单字段的修改前后值。
6. 保存 Request ID、来源 IP 和设备信息，供后续排查。
7. 管理员进入操作日志后可以按条件查询并查看详情。

### 3.2 操作日志一致性规则

#### 3.2.1 身份快照

- 用户操作后修改用户名或邮箱，历史日志仍显示操作发生时的旧用户名或旧邮箱。
- 普通用户操作后被提升为管理员，历史日志仍归类为普通用户操作。
- 管理员被调整为普通用户后，历史管理员操作仍归类为管理员操作。
- 用户被删除后，允许原用户关联标识为空，但姓名、邮箱和角色快照仍应保留。

#### 3.2.2 成功与失败

- 业务请求成功时日志结果为“成功”。
- 业务请求失败时日志结果为“失败”。
- 失败响应存在业务错误码时，详情应展示错误码。
- 同一业务操作失败后再次成功，应形成可分别查询的失败记录和成功记录。

#### 3.2.3 字段前后值

- 修改个人资料时，可以核对用户名、邮箱等已纳入白名单字段的修改前后值。
- 修改用户角色、权限、会员权益、支付价格、成本、试卷或考纲状态时，只展示已纳入记录范围的字段。
- 密码修改只能记录“是否发生密码修改”等非敏感结果，不得展示密码明文或密码摘要。
- 新增、查询、登录、开始考试和提交考试等没有字段对比的操作，详情显示“本次操作没有字段前后值”。
- 修改后值与修改前值相同的字段不应被伪造为变更项。

#### 3.2.4 Request ID 与问题排查

- 每条新日志应有 Request ID，且在列表关键词中可以精确搜索到对应记录。
- 详情复制的 Request ID 应与列表搜索使用的值一致。
- 运行日志仍在保留周期内且也记录该 Request ID 时，可以用它定位同一次请求。
- 操作日志只提供 Request ID，不提供运行日志正文和运行日志搜索页面。
- 历史日志没有 Request ID 时属于允许状态，页面应明确提示而不是报错。

### 3.3 产品使用统计规则

#### 3.3.1 三类学习活动完成次数

- 只统计状态为已提交的考试记录。
- 发生时间使用实际提交时间。
- 每个考试记录 ID 在一个统计周期内最多计一次。
- 开始考试、恢复考试、自动保存、未提交退出和失败提交均不计入完成次数。
- 完成记录按对应试卷类型归入诊断测试、试题库练习或模考练习。
- 完成次数只统计查询时仍为学生角色的账号，当前管理员账号的考试记录不进入产品完成统计。

#### 3.3.2 诊断报告查看次数

- 学生成功读取报告正文，每次成功打开计一次查看。
- 同一学生重复打开同一报告，可以产生多次报告查看次数。
- 报告生成状态轮询不计查看。
- 报告尚未生成、报告生成失败、无权查看或其他失败读取不计入成功查看次数。
- 报告查看按操作发生时的学生角色快照判断；管理员查看不进入学生报告查看统计。
- 报告查看统计只能从本版本部署并开始记录后累计，部署前历史访问无法回填。

#### 3.3.3 使用人数与人均次数

- 某模块使用人数为当期至少完成一次该模块活动的去重学生数。
- 某模块人均完成次数为该模块完成次数除以该模块使用人数。
- 没有使用学生时，人均次数为 0。
- 学生在多个模块完成活动时，可以同时计入多个模块的使用人数，但在全局活跃学生中只计一次。

#### 3.3.4 同期变化

- 当前范围为 7 天时，对比紧邻当前范围之前的 7 天。
- 当前范围为 30 天时，对比紧邻当前范围之前的 30 天。
- 自定义范围按相同持续时长向前取上一周期。
- 上一周期为 0 时，不计算虚假的增长百分比；当前有数据时显示“新增”，当前也为 0 时显示“暂无对比”。

#### 3.3.5 同期报告查看率

计算规则：

```text
同期报告查看率
= 当期已完成且报告也在当期成功打开的诊断记录数
÷ 当期诊断测试完成记录数
```

- 分母为 0 时，查看率为 0。
- 查看当期以前完成的诊断报告会增加报告查看次数，但不增加当期诊断完成记录的同期查看数。
- 一份当期报告重复打开多次，在查看率分子中仍只对应一份诊断记录。

#### 3.3.6 错题本与收藏夹题目查看

学生进入错题本后，可以在“我的错题”和“我的收藏”中浏览、筛选和翻页，此时两项查看次数均不增加。学生打开某一道题，题目正文成功显示后，才按入口增加一次对应的查看次数。错题本解析和收藏题目详情分别统计；普通答题页、整卷解析与诊断报告不计为错题本题目查看。

同一学生返回列表后再次打开同一道题，或刷新题目详情并成功显示，均增加一次查看；同一次打开中的分类修改、收藏状态刷新和右侧历次作答刷新不重复计数。收藏题目无需等待交卷即可查看并计数。

加载失败、无权查看、题目不存在、已移出错题本或已取消收藏时，不增加成功查看次数。学生在正文加载完成前离开页面，迟到的结果也不计数。查看人数在各自统计周期内按学生去重，人均次数为查看次数除以查看人数；无人查看时为零。管理员操作和当前被封禁账号不进入学生产品统计。

历史错题本查看记录与新增记录统一显示为“查看错题本”，并按原发生时间计入同一项次数、人数和趋势统计。历史记录每条仍计一次，不额外推算题目数量；新增记录仅在具体错题正文成功显示后产生。页面不再区分新旧口径。

移出错题沿用原规则：确认后每次操作形成一条日志，单题和批量均按操作次数记录，取消确认不记录。移出不会删除作答记录或收藏，也不会增加查看次数。

### 3.5 转化分析的运营观察流程

管理员进入“转化分析”后，先选择统计日期和注册后的观察期，再查看注册人群在哪个环节停止，以及付款后的学习习惯。日期默认最近 30 天，可选最近 7 天、90 天或最长 90 天自定义范围；观察期为注册后 7、14 或 30 天，默认 7 天。

#### 3.5.1 从整体结果定位流失环节

页面从上到下依次显示筛选条件、累计付费用户分析、转化总览、累计付费用户趋势、购买与学习两个漏斗、四种转化时长、付费学习时段热力图、考前付费高峰分析、付款后使用及数据覆盖说明。

总览的六项指标为新增注册用户、观察期内学习激活率、观察期内首次付费转化率、所选日期首次付费用户、注册到首次付费的中位时长、首次付费后 7 天内学习率。每项同时给出人数或样本说明。

累计付费用户趋势使用折线图，沿用统计日期筛选，按北京时间展示截至每日的历史付费学生总数。每人只在首次真实付款成功的日期增加一次，复购不重复增加；所选日期之前已经付费的用户作为期初基数，缩短日期范围不能把累计值重置为零。没有新增付费的日期沿用前一天人数，今日只统计到查询时刻，未来日期不展示。该趋势不受注册观察期限制，也不限制注册日期。

管理员、当前封禁用户、赠送、奖励、零金额和未成功付款的订单不计入。退款或会员到期不扣减已经发生的历史付费人数；首次付款时间缺失或异常、无法确定首次付款的用户不进入趋势。悬停显示完整日期和累计人数。验收时核对期初已有付费用户、同日多笔付款、跨日复购、北京时间零点首付、无新增日、退款、日期范围缩短及封禁解封后的计数。

注册转化率以所选日期注册、并且截至查询时已完整经过观察期的普通学生为分母；分子为这些用户在各自注册后的观察期内完成相应转化的人数。仍在观察的用户单独显示，不作为未转化者。观察期按注册时刻起的连续 24 小时计算，终点不包含在内。

购买漏斗依次为注册、创建真实支付订单、首次支付成功；学习漏斗依次为注册、开始练习、完成练习。每一步显示人数、相对上一步的转化率和流失人数。用户可直接购买，无需先完成学习漏斗。诊断、题库和模考中的任意一次练习成功交卷即视为学习激活。

首次付费以用户最早一笔真实付款为准，不因重复购买重新计算。月卡和季卡的正金额成功付款进入统计；管理员赠送与邀请奖励不计入。后续发生退款不抹去已发生的首次付款，注册转化人群中首单已全额退款的人数单独展示。所选日期首付人数包含更早注册、本期才付款的用户，因此可能大于本期注册转化人数。

成功付款记录缺失时间，或不符合注册、下单、付款的时间顺序时，页面提示异常记录数量。无法确认首次付款时间的用户不进入首付、复购和付费后学习统计，避免把后续订单当成首次转化；其他时间有效的订单仍可用于支付耗时统计。

#### 3.5.2 区分决策周期和支付耗时

四种时长可在同一区域切换：本浏览器首次可关联访问至注册、注册至首次完成练习、注册至首次真实付款、单笔订单创建至支付成功。其中，注册至首次完成练习和注册至首次付费按完整观察人群计算；订单支付耗时按所选日期支付成功的订单计算，包含复购。

时长区域展示中位数、P75、P90、有效样本数和分布。未转化用户不填入零时长。首次访问归因只对本浏览器有效且未超过 90 天的服务端记录生效，注册成功后消费该记录；跨设备、清除 Cookie 和历史未采集的数据保持未知，并显示有效覆盖人数，不从 IP 地址猜测访问者。

#### 3.5.3 观察付费后的使用与考前付费高峰

热力图按北京时间的星期和小时展示所选日期内、发生在首次真实付款之后的学习行为。开始练习、完成练习、成功查看分析报告、错题或收藏题目均可形成学习活动。登录、付款本身、筛选和自动保存不计入。每位用户每个自然日每小时最多计一次，再汇总到对应星期和小时；悬停同时展示活跃人次和去重人数，高频时段列出前三项。

热力图反映行为发生的时段，不代表连续在线或学习时长。有过真实付款后又退款的用户仍属于历史付费人群。运营提示仅建议检查使用引导、练习完成和支付过程，不能将相关性表述为已证实的转化原因。

考前付费高峰区域替代注册周批次表，默认以当年 10 月 12 日为考试节点（当前为 2026-10-12），管理员可调整具体考试日期，选择后立即重新查询。区域沿用顶部所选统计日期，不受注册观察期限制，也不限制用户注册日期；显示的考试节点和统计范围始终来自已成功加载的结果，失败时保留原结果并可重试。

按考前 90 天以上、61–90 天、31–60 天、15–30 天、8–14 天及 1–7 天六个阶段展示实际统计日期、自然日数、新增付费人数、人数占比、日均新增与统计状态。以北京时间每位用户最早一笔未全额退款的真实付款日分组，复购不重复计数；首单全退后重买时使用最早仍保留实付金额的订单，部分退款后仍有实付金额的订单保留。剔除管理员、当前封禁用户、赠送、零金额及首次付款时间无法确认的用户，考试当天和之后不计入。

高峰按日均新增人数比较，避免不同阶段长度影响判断；日均人数为阶段内新增付费人数除以所选范围与阶段交集中的已到来北京时间自然日数，包含查询当天并提示当天尚未完整。并列高峰全部展示；无付费时不生成高峰结论。尚未开始、范围外、统计中、部分覆盖和完整阶段分别标注，未来日不进入分母。结果只反映已统计日期，小样本提示谨慎判断，可扩大至近 90 天观察更完整走势。

付款后七天学习率以所选日期首次付款、截至查询已完整经过七天的用户为分母，其中付款后七天内有学习行为者为分子；复购人数先剔除当前已全额退款的订单，再按付款时间判断：用户至少有两笔仍保留实付金额的真实付款，且第二笔或后续付款发生在所选日期内，才计为一位复购用户。首单退款后仅重新购买一次、复购单全退后只剩一笔有效订单，以及所有订单全退的用户不计入；部分退款后仍有实付金额的订单保留，会员到期不影响计数。

#### 3.5.4 累计付费用户的地域与决策时长

“累计付费用户分析”标记为“全部历史”，按截至查询时的所有历史真实付费用户统计，不受顶部日期和注册观察期影响。管理员可以单独点击“刷新数据”，不改变其他图表的查询条件。区域顶部展示纳入分析人数、历史成功付费人数及已全部退款人数，并显示北京时间的查询截止时间。

该区域排除管理员、当前封禁账号、赠送、奖励、零金额和未成功付款的订单。同一用户多次付款只计一人；所有实付金额均已退完的用户单独计入“已全部退款”，不参与地域和时长分析。有部分实付金额保留、退款后再次付费或会员已到期的用户仍参与分析。此处的净付费人群与按历史付费身份统计的累计付费用户趋势、首付漏斗有所区别，页面应保留各自口径说明。

左侧展示付费用户地域排名、人数、占比及条形图，按人数从多到少排列。地域取注册时 IP 对应的国家 / 地区和省份，仅供运营参考，不代表用户当前所在地或常住地。多个用户共用同一 IP 时各计一人；占比以全部纳入分析用户为分母。尚未取得注册属地时归入“暂无属地”，不得减少付费总人数。排名较长时区域内滚动，所有地区均可查看；页面不展示用户姓名、邮箱或原始 IP。

右侧展示注册到首次真实付款成功的平均时长、中位时长、最快、最慢及有效样本数。时长以账号注册为起点，不因复购重置；首笔付款退款后再购买的用户，仍使用第一次成功付款。分布为不足 1 小时、1 小时至不足 24 小时、1 天至不足 3 天、3 天至不足 7 天、7 天至不足 30 天、30 天及以上；边界值归入后一个区间。每段展示人数和占比，并汇总 24 小时内、7 天内的付费比例。

时长统计的分母为有效时长样本。成功付款时间缺失、早于下单、下单早于注册或付款时间晚于查询时刻时，该用户不进入时长分析，页面提示排除人数；仍保留其付费身份和地域统计。无样本时各项时长和比例显示“—”，不将缺失数据当成零时长。大屏下两张卡片左右排列，窄屏上下排列。

#### 3.5.5 验收旅程

- 管理员设置考试日为 2026-10-12，付款发生在 10 月 5 日零点的用户进入考前 1–7 天，10 月 12 日零点及之后不进入考前统计。老注册用户在本期首次有效付款也计入，复购不重复计数；切换注册观察期后这部分结果不变。
- 考前阶段尚未开始时显示占位符，不将未来日期按零付款纳入日均分母。缩短日期范围后仅统计交集，标记部分覆盖；无付费时显示暂无考前付费数据。调整考试日后阶段归属同步变化，查询失败时保留上次节点和数据，再次查询可恢复。

- 学生注册后开始并完成练习、创建订单并成功付款。观察期结束后，各阶段人数各增加一人，时长按真实事件计算；再次付款且保留至少两笔有效付款时增加相应期间的复购，不改变首付时间。
- 对上述两笔付款中的任一笔完成全额退款后，复购人数减少一人；两笔均全退时同样不计入。首单退款后再购买一次不计复购，再购买第二笔有效订单才重新计入。部分退款但仍有实付金额时保留，其他首付及历史累计付费指标沿用各自口径。
- 一名学生注册未满观察期时，页面仅增加注册和观察中人数。达到观察期后再查询，才进入转化率分母；尚未付款者不进入付费时长分布。
- 赠送会员的学生不会增加首次付费人数。真实付款后全额退款的学生仍保留首付转化，首单全退人数增加；管理员和当前被封禁用户不进入统计。
- 学生付款前的学习行为不进入付费热图；同一小时重复打开多道题只计一次。北京时间跨零点后进入次日格子。
- 查询失败时保留上一次结果与原范围说明，管理员点击“重新加载”后恢复；无数据时显示空态或无分母占位符，不能将未知时长显示为零。
- 一名注册已超过 90 天的普通学生真实付款后，在累计付费人数、地域及首付时长中各计一次。切换顶部日期或观察期，这部分结果保持不变；单独刷新后更新查询截止时间。
- 同一用户多次付款不重复计数；所有付款全退后退出这两项分析，全退人数增加。再次付款后重新纳入，时长仍从注册计算到最早的成功付款。赠送、零金额订单、管理员和封禁账号不能增加分析人数。
- 两位付费用户使用同一注册 IP 时，地域人数增加两人。从未取得属地时进入“暂无属地”，再次更新失败时保留已保存的属地，不影响总人数和有效首付时长；全部地区人数之和等于纳入分析人数。
- 首笔付款缺少时间、后续有正常付款时，不能把后续付款误当首付；该用户仍进入地域分析，但不进入时长分布。分段人数之和等于有效样本数。
- 累计分析与其他图表独立加载。请求失败时可单独重试；保留旧结果时同时保留原查询截止时间。没有符合口径的付费用户时，两张卡片展示空态及零人数，不出现空白图表或虚构比例。

### 3.6 网站访问关联与跨模块验收

用户打开网站时记录当天访问；登录或注册成功后补充账号关联，身份由服务端登录状态确认。访问按北京时间自然日和 IP 去重，同一账号重复访问、先匿名后登录、多人共用一个 IP 都不会增加当天 IP 数。账号关联只用于后台汇总，不向分析页面返回账号名单或原始 IP。

当某个 IP 当天关联的账号全部被封禁，且没有匿名访问时，这条访问从总量、独立 IP、趋势和同期比较中剔除。该 IP 有其他未封禁账号访问时，仍归为登录学生访问；只剩匿名访问时保留一条匿名访问。历史没有账号关联的数据保留原分类，不能用当前账号状态反推身份。旧数据缺少分类时沿用匿名归类。持有封禁账号凭证的请求被拒绝，不降级为匿名访问。

原有产品趋势人工修正仍可下调展示值，但不能高于剔除封禁用户后的真实次数，避免修正值重新抬高已清理的统计。

验收时按以下完整路径核对：

- 普通用户完成练习、查看复习内容、成功付款并获赠日卡，管理员记下相关分析。封禁该用户后重新查询，注册、行为、营收、赠卡、转化及付费地域和时长均剔除其贡献，分组之和与总数一致；订单、作答和赠卡记录仍可追溯。解封后重新查询，历史统计恢复。
- 两个账号在同一天共用 IP 访问，只计一个 IP；封禁其中一个后正常访问仍保留。另一个 IP 只有被封禁账号访问且无匿名访问时剔除；先匿名后登录的 IP 在账号封禁后保留匿名访问。两者的当期与上期均按相同规则处理。
- 封禁当前范围内全部已知用户后，相关人数、金额和活动次数归零，无分母比例与未知时长按各模块空态规则显示。人工趋势修正不能把该日次数重新抬高。
- 访问上报失败不阻断页面、登录或注册。管理员查询失败时使用原有错误提示和重试出口，不把失败结果保存为零；恢复查询后按最新账号状态重新计算。

### 3.7 注册属地补全与定期更新

用户注册后可正常使用网站，无需等待属地查询。后台按受控频率补全注册国家和地区，并安排下次更新；没有注册 IP 或使用内网地址的用户保持“暂无属地”，不会减少注册人数或付费人数。已有用户也沿用同一流程补全，不依赖再次登录。

距上次成功查询满 30 天后，后台重新定位注册 IP。取得新结果后保存并用于后续分析；超时、限流或返回空结果时保留原结果，公网查询失败一小时后重试。第三方限流时暂停请求至少一小时，按服务方要求延长等待，恢复后继续处理。

验收时检查新注册用户和历史用户均能补全，同一 IP 的不同账号各计一人；连续刷新两处地区图表不产生新定位请求。模拟到期后属地变化，应更新两处统计；模拟失败，应保留原属地。从未成功定位的账号显示“暂无属地”；封禁后退出两处统计，解封后恢复。

## 4. 异常容错

### 4.1 权限与登录异常

- 登录失效、令牌无效或未登录时，不返回后台日志或统计数据。
- 非管理员即使直接输入后台地址，也不能读取操作日志详情或学生行为统计。
- 管理员身份在页面使用期间被收回后，后续请求进入统一无权限处理，不继续展示新数据。

### 4.2 查询参数异常

| 异常 | 预期处理 |
|---|---|
| 操作日志角色非法 | 拒绝查询并返回明确错误 |
| 操作日志模块非法 | 拒绝查询并返回明确错误 |
| 操作日志结果非法 | 拒绝查询并返回明确错误 |
| 操作日志开始时间晚于结束时间 | 拒绝查询并提示时间范围无效 |
| 行为分析只提供开始或结束时间 | 拒绝查询，要求两个时间同时提供 |
| 行为分析结束时间不晚于开始时间 | 拒绝查询 |
| 行为分析超过 90 天 | 拒绝查询并提示最大范围为 90 天 |

### 4.3 数据异常与空数据

- 操作日志列表为空时显示空态，不影响管理员重新筛选。
- 详情记录不存在时提示“操作日志不存在”，不展示上一条详情残留内容。
- 字段、来源 IP、设备信息或操作对象缺失时使用 `-` 或对应空态文案。
- 历史日志缺少用户标识时仍可查询日志，但不推算为可关联学生的产品使用人数。
- 行为统计无数据时返回稳定的 0 值结构，三类产品模块和五类偏好分组仍保持可识别。
- 未知扩展模块或行为编码没有中文名称时，页面显示原始编码，不能显示空白。

### 4.4 重复操作与时序

- 同一考试完成记录因刷新或重复请求被再次读取时，产品完成次数仍只计一次。
- 同一报告每次成功打开都属于一次查看，因此重复打开可以增加查看次数。
- 错题和收藏题目按每次成功显示正文计数；统计上报失败不阻断复习，也不自动重试补记，以免重复计数。
- 操作日志在业务响应完成后可能存在短暂可见延迟；刷新后应能查询到，不要求页面实时推送。
- 多个查询快速连续发出时，页面只采用最后一次有效查询结果，较早响应不能覆盖较新条件。

### 4.5 Request ID 排查边界

- Request ID 只能定位同一次请求，不能保证运行日志仍在服务器保留周期内。
- 如果运行日志没有记录同一 Request ID、已经轮转删除或目标服务未输出对应内容，操作日志页面不能自动恢复运行日志。
- Request ID 相同不代表业务一定成功，必须结合操作结果、状态码、错误码和运行日志判断。

### 4.6 异常验收点

1. 非管理员访问任一页面时不得看到日志或统计数据。
2. 非法筛选条件不得导致页面白屏、服务崩溃或返回其他角色数据。
3. 空数据范围不得出现 `NaN`、`Infinity` 或负数。转化分析无分母或无时长样本时显示“—”，有观察用户但无人转化时显示 0.0%。
4. 详情加载失败后不得残留上一条记录的字段前后值。
5. 快速切换时间或模块时，最终页面必须对应最后一次选择。
6. 操作日志记录失败不应中断原业务，但应允许通过运行日志发现日志保存异常。

- 管理员与普通用户操作区分。
- 用户身份快照、业务结果、字段前后值、来源 IP、设备信息和 Request ID。

- 诊断报告查看次数和同期报告查看率。
- 错题本与收藏夹具体题目的查看次数、去重查看人数及每日趋势，保留原有移出错题日志规则。
- 产品使用占比、学生偏好分布和北京时间每日趋势。
- 独立转化分析页签：注册观察期、真实付费漏斗、转化时长、付费学习热力图、考前付费高峰、首单退款及复购观察。
- 累计付费用户地域分布与注册到首次付款的时长分析，使用全部历史净付费人群，支持独立刷新。
- 后台分析统一剔除当前封禁用户，支持解封恢复；新增登录访问关联账号，共用 IP 和匿名访问保留独立口径。
- 最近 7 天、30 天、90 天及最长 90 天自定义查询。

### 5.2 当前未实现的功能

以下功能不属于当前版本，产品和测试不得按“已经支持”验收：

1. 不记录所有页面访问、按钮点击、停留时间、滚动深度或访问来源。
2. 不统计错题本或收藏夹列表打开次数，也不统计错题重练漏斗。
3. 不统计诊断测试列表访问、试题库列表访问或普通查询次数。
4. 除本文定义的注册、学习、购买漏斗和付款后七天使用外，不提供任意用户路径、自定义漏斗、连续在线时长或完整留存矩阵。
5. 不提供单个学生的行为画像、个人行为时间线或学生名单下钻。
6. 不统计管理员产品使用偏好。
7. 不回填诊断报告查看功能上线前的历史访问次数。
8. 不提供操作日志导出、批量下载、删除、修改、备注或人工补录。
9. 不提供运行日志正文查看、运行日志全文搜索或服务器日志下载。
10. 不记录后台 Worker、定时任务、服务启动、数据库慢查询或系统异常事件。
11. 不提供操作日志异常实时告警、邮件通知、短信通知或企业消息通知。
12. 不提供独立的日志归档、自动清理、保留天数配置或冷热存储管理页面。
13. 除明确标记“全部历史”的累计付费用户分析外，单次行为分析最长 90 天，不提供任意无限时间范围查询。
14. 不提供分钟级实时大屏、自动刷新或消息推送。
15. 不因本统计功能自动新增模考入口或改变现有考试、会员和支付规则。

### 5.3 后续迭代建议

后续如需更深入的产品决策能力，可以单独评审：

- 从错题查看到重练、再次答对的转化漏斗。
- 诊断测试列表到开始、提交、报告查看的完整漏斗。
- 试题库筛选、开始练习、完成练习和重复练习的路径分析。
- 按考试类型、会员状态、新老用户或注册渠道进行分群对比。
- 独立的用户行为事件体系，用于承载页面访问、点击和停留时间，而不污染操作审计日志。
- 数据量增长后的日汇总、长期趋势和报表导出。
- 操作日志保留策略、归档策略、异常告警和运行日志联动查询。

以上建议均不改变当前版本的检查规则，进入开发前需要重新明确统计口径、隐私边界和验收标准。
