# 4.8.1 诊断报告改版方案（原型分析与生成方式）

> 方案基线：用户提供的诊断报告原型截图、`诊断报告改版设计文档 v2.0`、`诊断报告后台数据包 v1.0` 与当前项目代码。
>
> 本文定义原型中每个 Part 的展示内容、数据来源及完成方式，并明确哪些内容由代码固定计算、哪些内容由 DeepSeek 推理生成。现有未完成的旧报告代码不作为产品逻辑基线。

## 1. 功能边界与目的

### 1.1 目标

学生完成一次诊断测试后，通过同一份报告了解本次成绩、时间使用、知识点掌握、错题详情、优先提升方向和后续学习路径。

原型包含以下区域：

1. 报告头与模块切换。
2. Part 1：等效评估分。
3. Part 2：总体成绩概览。
4. Part 3：知识点掌握度。
5. Part 4：错题逐题分析。
6. Part 5：AI 提升规划表。
7. Part 6：AI 定制三阶段学习路径。

### 1.2 生成原则

| 完成方式 | 定义 | 约束 |
| --- | --- | --- |
| 代码固定读取 | 从 `Paper`、`Question`、`ExamRecord`、`AnswerRecord` 等正式数据源读取 | 不允许 DeepSeek 改写 |
| 代码固定计算 | 按评分表、时间公式、聚合公式、考纲规则得到结果 | 相同输入必须得到相同输出 |
| 代码固定模板 | 根据明确阈值选择产品文案 | 文案可配置，但不调用模型 |
| DeepSeek 推理 | 基于代码提供的结构化事实进行解释、排序或任务编排 | 不得自行生成事实数据 |

分数、正确率、题数、时间、百分位、样本量、知识点矩阵、目标阈值和资源链接全部由代码负责；DeepSeek 只负责风险总结、高 ROI 排序说明和学习任务编排。

### 1.3 权限和状态

- 学生只能读取自己的已交卷报告。
- 管理员可查看报告版本和生成日志，但不能直接覆盖学生成绩。
- 报告状态：`pending`、`generating`、`completed`、`partial`、`failed`。
- AI 生成失败时报告进入 `partial`，基础成绩和逐题分析继续展示。

### 1.4 原型中必须修正的数据矛盾

截图是展示原型，不可直接作为计算样例。开发时必须修正以下问题：

- 等效评估分显示 `6.5`，总体成绩概览显示 `7.5/9.0`。新版必须使用同一评分结果；如需同时显示原始分和等效分，必须明确字段名称，不能都称“成绩/评估分”。
- 总用时 `118 min`、规定 `150 min` 时，剩余时间应为 `32 min`，不能显示 `2 min`。
- 标题为 TMUA，但顶部模块为“数学1、数学2、物理”，属于 ESAT 模块组合。模块必须由实际 `examType` 和试卷结构生成。
- 错题截图中选项 A 被标为正确，但解析写“正确选项为 B”，必须以 `Question.answer` 为唯一正确答案来源。
- 题目标签显示 Differentiation，考察点却显示 Surds，解析又描述三角形面积，存在内容错配。题干、答案、知识点和解析必须来自同一个 Question 记录并通过一致性校验。
- 知识点区的分母可能是多标签“考查次数”，不能统一写成“题数”，否则会与试卷总题数矛盾。

## 2. 页面描述与各 Part 完成方式

### 2.1 报告头与模块切换

#### 展示内容

- 报告标题：考试类型、试卷名称或年份、成绩报告。
- 模块页签：切换报告模块上下文。

#### 完成方式

| 内容 | 数据来源 | 完成方式 | 规则 |
| --- | --- | --- | --- |
| 报告标题 | Paper.code/title/year | 代码固定拼接 | 不使用截图中的固定标题 |
| 模块页签 | Paper 与 Question 的模块/卷别字段 | 代码固定生成 | 不硬编码数学1/数学2/物理 |
| 当前页签 | URL 或页面状态 | 代码交互 | 切换后重新过滤对应模块数据 |

考试差异：

- TMUA：使用 Paper 1、Paper 2；是否增加“总体”页签见待确认项。
- ESAT：只展示学生本次实际参加的三个模块，例如 Mathematics 1、Mathematics 2、Physics。
- STEP：按本次记录展示 STEP 2 或 STEP 3，一次单卷报告不额外显示模块页签。

本区不调用 DeepSeek。

前端页面与诊断策略按考试类型拆分：ESAT 使用 `/exam-result/:id/esat` 和独立 ESAT 诊断服务；TMUA 使用 `/exam-result/:id/tmua` 和独立 TMUA 诊断服务。公共入口 `/exam-result/:id` 只负责读取答卷类型并跳转，不在一个页面内混合两套考试规则。

### 2.2 Part 1：等效评估分

#### 2.2.1 核心评估分

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 等效评估分 | 作答结果 + 版本化评分换算表 | 代码固定计算 |
| 分数区间 | 题量、难度分布、已评审区间算法 | 代码固定计算 |
| “基于本次 N 题” | 当前评分范围内的唯一题目数 | 代码固定统计 |
| “参考换算估计”说明 | 产品固定文案 | 代码固定展示 |

规则：

- TMUA 展示新制单一总分；Paper 1/2 分值只作为内部诊断辅助。
- ESAT 逐模块展示 1.0-9.0 分，不生成无官方定义的总分。
- STEP 展示原始分和对应等级，不显示 1.0-9.0 等效分。
- 缺少适用评分表时只展示原始正确数与正确率，不使用前端公式兜底。
- TMUA/ESAT 等效分按原始正确数查询对应年度参考换算曲线；难度标签不参与标准分加权，只用于后续能力分析。
- 由于官方 Rasch IRT 每年动态等值，页面必须标注“平台等效评估”，不得宣称为官方出分。
- 标准 ESAT 模块为 27 题；ENGAA 等历史卷题量不等于 27 时，按模块正确率归一为 `/27` 等效原始分，并扩大区间、标注“非标准题量归一”，不能直接拿少量题的正确数查询 `/27` 换算表。

#### 2.2.2 水平定位与竞争力

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 进度条位置 | 百分位数值 | 代码固定计算样式位置 |
| Top 15% 等百分位 | 版本化分数分布表 | 代码查表 |
| Very Good 等水平标签 | 分数等级映射表 | 代码查表 |
| 通用竞争力描述 | 后台竞争力映射表 | 代码查表/固定文案 |
| 同期众数和相对位置 | 对应场次分数分布 | 代码查表 |

DeepSeek 不计算百分位，也不生成院校竞争力事实。ESAT 必须显示“历史数据有限，仅供参考”。

#### 2.2.3 分卷/模块表现

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| Paper 1/2 或模块分数 | 模块内作答结果 + 对应评分规则 | 代码固定计算 |
| 高低对比 | 两个模块的计算结果 | 代码固定比较 |
| “基础较扎实/推理需突破”等短句 | 分差和阈值 | 代码固定模板 |

分卷评价采用固定规则即可，不需要为一句稳定文案额外调用大模型。

#### 2.2.4 难度掌握度

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 低/中/高难度正确数与总数 | Question.difficulty + AnswerRecord | 代码固定聚合 |
| 正确率 | 正确数/总数 | 代码固定计算 |
| 状态颜色 | 正确率阈值 | 代码固定映射到全局 token |

难度标签只接受标准化的 `low/medium/high`。缺少难度的题仍计入总成绩，但不进入难度掌握度。

#### 2.2.5 关键风险信号

风险信号是 Part 1 唯一需要 DeepSeek 的内容。

DeepSeek 输入：代码计算出的评估分、分卷表现、难度掌握度及样本量。输出最多两句，只指出本次最主要风险，不提供新分数、不提院校、不编造错误类型。

### 2.3 Part 2：总体成绩概览

#### 2.3.1 成绩总览

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 成绩总分 | Part 1 的同一评分结果 | 代码固定复用，不重复计算 |
| 满分标尺 | 对应考试评分规则 | 代码固定读取 |
| 正确率 | 正确题数/总题数 | 代码固定计算 |
| 正确、错误、未答题数 | AnswerRecord | 代码固定统计 |
| 分布条 | 三类题数占总题数比例 | 代码固定计算 |

此处不得出现与 Part 1 不一致的第二套评估分。若产品希望这里展示原始分，应明确写成“原始得分”，而不是重复写“成绩总览”。

#### 2.3.2 时间与模块分析

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 总用时 | 逐题真实作答时长之和，或 submittedAt-startedAt | 代码固定计算 |
| 规定时长 | Paper.duration 或模块配置 | 代码固定读取 |
| 平均用时 | 总用时/本次题目数 | 代码固定计算 |
| 剩余时间 | max(规定时长-总用时, 0) | 代码固定计算 |
| 超时题目数 | 单题用时超过该模块基准用时的题目数 | 代码固定计算 |
| Paper/模块时间条 | 模块实际用时与计划用时 | 代码固定计算 |

当前项目已具备逐题耗时基础：答题页在切题、保存进度和交卷时累计 `questionDurations`，后端保存到 `AnswerRecord.durationSeconds`。一期保留平均用时、超时题数和模块时间条，但开发时必须先统一计时口径：

- 页面切到后台、锁屏或弹出“继续答题”确认框期间，总计时和当前题计时必须同时暂停。
- 恢复答题时同时重置当前题计时起点，不能把后台停留时间累计到当前题。
- 每次切题、保存进度、自动交卷和手动交卷前都要结算当前题时长。
- 增加周期性自动保存，并在页面隐藏/刷新前尽可能保存已结算时长，避免异常关闭丢失当前题最后一段时间。
- 报告生成前校验“逐题时长之和”和“有效总用时”的差值；超过允许误差时记录数据异常，不展示错误的模块分析。
- 禁止旧报告当前使用的兜底方式：没有模块逐题时长时，不得按题量比例估算实际模块用时。

Part 2 不调用 DeepSeek。

### 2.4 Part 3：知识点掌握度

#### 展示内容

- 按 Paper/模块分组。
- 展示知识点大类、所含细分知识点数量、正确考查次数/总考查次数、掌握率。
- 点击加号展开细分知识点明细。

#### 完成方式

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| Paper/模块分组 | Question.module/paper | 代码固定分组 |
| 知识点大类与细分项 | Question.knowledgePoints + SyllabusNode | 代码按考纲树映射 |
| “N 个知识点” | 分组下去重后的知识点 ID | 代码固定统计 |
| 正确/总考查次数 | 多标签观测 | 代码固定聚合 |
| 掌握率 | 正确考查次数/总考查次数 | 代码固定计算 |
| 进度条 | 掌握率 | 代码固定展示 |
| 展开明细 | 对应子知识点的统计 | 代码交互读取 |

多标签题会同时计入多个知识点，因此此区统一使用“考查次数”，不使用“题数”。知识点掌握度不调用 DeepSeek，也不根据历史模考修正。

### 2.5 Part 4：错题逐题分析

#### 2.5.1 题目导航

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 题号列表 | 当前 Paper/模块题目顺序 | 代码固定读取 |
| 已答/跳过/未答数量 | AnswerRecord 状态 | 代码固定统计 |
| 当前题、正确题、错误题、未答题样式 | AnswerRecord | 代码固定映射 |

#### 2.5.2 题目详情

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 题干、选项、图片、公式 | Question | 代码固定读取，复用 QuestionCard |
| 用户选择 | AnswerRecord.selectedAnswer | 代码固定读取 |
| 正确答案 | Question.answer | 代码固定读取 |
| 选项判定样式 | 用户答案与正确答案比较 | 代码固定计算 |
| 考察点 | Question.knowledgePoints | 代码固定读取 |
| 题目解析 | Question.explanation | 代码固定读取 |
| 针对练习入口 | 当前题知识点、难度和 examType | 代码固定生成试题库筛选条件 |

Part 4 不实时调用 DeepSeek。标准答案和解析属于题库正式内容，应由教研审核后随 Question 入库；实时生成可能出现截图中的题干、知识点、答案和解析互相矛盾。

“复习引导”改为“去针对练习”：点击后携带该题的 `examType`、主要知识点 ID 和难度进入试题库，默认应用筛选并从符合条件的题目开始练习。若题目缺少有效知识点，则按钮禁用并提示“该题暂未完成知识点标注”。若解析缺失，显示“暂无解析”，不得临时让模型补写。

### 2.6 Part 5：AI 提升规划表

#### 2.6.1 能力缺口矩阵

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 知识点大类 | 本次 Question 标签 + 考纲树 | 代码固定归类 |
| 低/中/高难度列 | Question.difficulty | 代码固定分组 |
| 正确数、总数、正确率、n | AnswerRecord 聚合 | 代码固定计算 |
| 绿色/黄色/红色/灰色状态 | 评审后的正确率与样本阈值 | 代码固定映射 |

能力矩阵不调用 DeepSeek。一期不依赖知识点依赖图、不生成推断百分比，截图中的虚线“推断”格取消。`n < 3` 的格统一标记“样本不足”，`n = 0` 的格标记“本次未考查”。

#### 2.6.2 高 ROI 缺口清单

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 候选格 | `n >= 3` 的直接观测矩阵格 | 代码固定筛选 |
| 正确率、样本量、难度、考查覆盖率 | 本次直接观测矩阵 | 代码固定提供 |
| Top 1-5 排名 | 合法候选格 | DeepSeek 推理 |
| 优先原因 | 已提供的正确率、样本量、难度和覆盖率 | DeepSeek 组织解释 |
| 建议投入时长区间 | 缺口严重度、可用时长规则 | DeepSeek 在代码允许范围内选择 |

一期 ROI 排序不依赖知识点依赖图，也不生成“前置检查”结论。DeepSeek 不能新增候选知识点，不能修改正确率和样本量。有效候选不足 3 个时按实际数量展示，不补造。

### 2.7 Part 6：AI 定制三阶段学习路径

#### 2.7.1 路径总览

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 考试日期 | 用户输入或个人备考设置 | 代码校验并保存 |
| 每周可投入时长 | 用户输入或个人备考设置 | 代码校验并保存 |
| 距考试周数 | 当前日期与考试日期 | 代码固定计算 |
| 总可投入时长 | 周数×每周时长 | 代码固定计算 |
| Sprint/Standard/Systematic 模式 | 周数阈值 | 代码固定判断 |
| 三阶段周数和进度条比例 | 模式对应的分配规则 | 代码固定计算 |

截图中的“96 小时”和 Standard 模式不能由模型凭空生成，必须能反查用户输入和计算过程。

#### 2.7.2 阶段内容

| 内容 | 完成方式 | 约束 |
| --- | --- | --- |
| 每阶段目标阈值 | 代码固定规则 | 如高难度目标 50%+，由产品/教研配置 |
| 阶段重点知识点 | DeepSeek 从 gapList 选择 | 阶段 1 最多 2-3 个 |
| 阶段 1 Day 1-7 任务编排 | DeepSeek 推理 | 总任务量不得超过代码计算的可用时间 |
| 阶段 2 周级大纲 | DeepSeek 推理 | 不提前生成每日细节 |
| 阶段 3 模考冲刺大纲 | DeepSeek 推理 | 不承诺伪精确提分 |
| 平台资源候选 | 资源库按知识点和难度检索 | 代码固定查询 |
| 资源选择 | DeepSeek 仅在候选资源中选择 | 不得编造 ID |
| 资源链接 | 资源 ID 对应站内路由 | 代码固定生成 |
| 完成状态 | 用户任务记录 | 代码固定读写 |

#### 2.7.3 Checkpoint 与滚动更新

截图中包含“阶段结束后触发再诊断”按钮。该功能如果进入本期，需要额外实现：

- 按阶段知识点和难度抽取 5-8 题靶向微测。
- 保存独立微测记录和逐题答案。
- 完成后重新计算 Part 1 和 Part 5。
- 基于新结果重新生成下一阶段详细任务。
- 保留原报告与原路径版本，不能静默覆盖。

微测选题、评分和报告重算由代码完成；更新后的风险信号、缺口排序和下一阶段任务由 DeepSeek 推理。

### 2.8 整页生成方式总览

| 页面区域 | 代码固定读取/计算 | DeepSeek 推理 |
| --- | --- | --- |
| 报告头与模块切换 | 全部 | 无 |
| Part 1 等效评估分 | 分数、区间、百分位、竞争力、分卷与难度表现 | 关键风险信号 |
| Part 2 总体成绩概览 | 全部 | 无 |
| Part 3 知识点掌握度 | 全部 | 无 |
| Part 4 错题逐题分析 | 全部 | 无 |
| Part 5 AI 提升规划表 | 能力矩阵、候选缺口及所有事实数值 | 缺口排序、优先原因、投入区间 |
| Part 6 三阶段学习路径 | 时间、模式、阶段比例、目标阈值、资源候选和完成状态 | 知识点选择、任务编排和阶段大纲 |

## 3. 核心流程

### 3.1 交卷后

1. 事务内固化 ExamRecord 和逐题 AnswerRecord。
2. 校验 Question、答案、知识点、难度、模块和解析的一致性。
3. 代码计算 Part 1、Part 2、Part 3 和 Part 5 矩阵。
4. 代码从 Question 读取 Part 4 内容。
5. 代码筛选 Part 5 合法候选缺口。
6. 后端调用一次 DeepSeek，生成 Part 1 风险信号和 Part 5 高 ROI 清单。
7. 校验 AI JSON 并保存报告快照；AI 失败时报告状态为 `partial`。

### 3.2 生成学习路径

1. 用户提供考试日期和每周时长，或读取已保存的备考设置。
2. 代码计算周数、总时长、模式、阶段分配和目标阈值。
3. 代码根据 gapList 查询真实站内资源候选。
4. 后端调用 DeepSeek 生成阶段重点、近期任务和远期大纲。
5. 后端校验知识点、时长、任务类型和资源 ID 后保存。

### 3.3 DeepSeek 调用约定

- 默认使用 `deepseek-v4-flash`，允许通过 `DEEPSEEK_MODEL` 调整，仅在 Express 后端调用。
- API Key 只从 `DEEPSEEK_API_KEY` 环境变量读取，不入库、不写日志、不提交 Git。
- 只接受 JSON 输出，不接受 Markdown 包裹。
- 记录模型、报告 ID、模块、耗时、Token 用量、状态和错误码。
- 单次超时后自动重试一次；相同报告版本和模块保证幂等。
- AI 输出必须通过 JSON Schema、考纲白名单、事实数字和资源存在性校验。

### 3.4 核心验收点

- Part 1 与 Part 2 使用同一成绩事实源，不出现 6.5/7.5 冲突。
- 总用时、规定时长、剩余时间满足数学关系。
- 页签与实际考试类型、模块组合一致。
- 题目正确答案、判定样式和解析结论一致。
- 知识点多标签统计统一标为“考查次数”。
- `n < 3` 的矩阵格不进入高 ROI 清单。
- AI 生成失败不影响前四个固定数据 Part。
- AI 不得新增考纲外知识点、事实数字、资源 ID 或外部链接。

## 4. 异常容错

### 4.1 数据异常

- 缺少评分表：显示原始成绩，隐藏等效分和百分位。
- 新记录逐题耗时校验失败：显示总用时，并将模块分析标记为数据异常；历史记录确实没有逐题耗时时，才隐藏平均用时、超时题目和模块时间条。
- 缺少知识点：题目仍计入成绩，但不进入知识点统计和矩阵。
- 缺少难度：题目仍计入成绩，但不进入难度分析。
- 答案、解析或考察点冲突：后台记录数据异常；报告只展示可确认部分，不展示矛盾解析。
- 缺少题目解析：显示“暂无解析”，不实时调用模型补写。

### 4.2 DeepSeek 异常

- 超时、限流、网络失败：自动重试一次，仍失败则显示可重试状态。
- JSON 错误或字段缺失：拒绝输出。
- 模型改写正确率、样本量或其他事实：拒绝对应模块。
- 考纲越界：拒绝输出，不允许仅靠前端隐藏。
- 资源 ID 不存在：删除该资源引用，任务显示“平台资源待匹配”。

### 4.3 页面降级

- 风险信号失败：Part 1 其他内容正常展示。
- 高 ROI 清单失败：能力矩阵正常展示。
- 学习路径失败：路径总览和用户输入保留，任务区允许重试。
- 不得使用旧报告中的估算百分位、固定四周路径或虚构提升分作为兜底。
