# 4.8.1 诊断测试提交与 ESAT 诊断报告方案

> 方案基线：诊断报告原型截图、`诊断报告改版设计文档 v2.0`、`诊断报告后台数据包 v1.0`、ESAT/TMUA 计分规则、当前项目代码及已确认的产品决策。
>
> 本文第一节定义诊断测试从交卷、分析、落库到报告展示的完整链路；第二节定义 ESAT 诊断报告各模块的业务含义、数据来源、固定计算与 DeepSeek 分析边界。TMUA 使用独立页面和独立诊断逻辑，不在第二节混用 ESAT 规则。

---

## 第一节：诊断测试提交、分析与报告展示流程

### 1. 功能边界与目的

#### 1.1 目标

学生从诊断测试首页选择一套真题，完成作答并交卷后，系统必须先可靠保存考试记录和逐题答案，再在后台完成确定性指标计算与个性化分析，最后将完整诊断报告保存入库并展示。

完整流程为：

```text
选择真题
  → 开始或继续测试
  → 提交答卷
  → 原子化保存考试记录与逐题答案
  → 创建诊断分析任务
  → 在答题页打开报告分析弹窗
  → 固定规则计算
  → DeepSeek 个性化分析
  → 规则兜底与结果校验
  → 保存并发布最新报告
  → 弹窗进入完成态
  → 学生点击“查看诊断报告”
  → 进入 ESAT 或 TMUA 独立报告页
```

#### 1.2 考试记录与报告的关系

重新测试时必须创建新的 `ExamRecord` 和新的 `AnswerRecord`，保留每一次真实作答数据；但同一学生、同一试卷只对外展示一份当前有效诊断报告。

重新测试属于正式业务流程：前端只发起正常开始请求，后端根据最近一次考试状态、当前考试类型权益和进行中诊断占用决定是否创建新记录。重测资格是服务端本次请求的计算结果，不由客户端声明。

```text
学生 + 试卷
  ├─ 第 1 次 ExamRecord + AnswerRecord
  ├─ 第 2 次 ExamRecord + AnswerRecord
  └─ 1 份当前有效 DiagnosticReport
                         ↑
                 指向最近一次成功分析
```

覆盖规则：

- 新一次测试交卷后创建新的分析任务，但不立即删除上一份成功报告。
- 新报告全部分析完成、结构校验通过并成功入库后，才替换当前有效报告。
- 新报告生成失败时保留上一份成功报告，并允许学生继续查看。
- 失败状态下明确提示：`最新一次分析失败，当前展示上一次报告`。
- 新报告发布后，旧报告不再提供查看入口，也不参与新报告分析。
- 历史 `ExamRecord` 和 `AnswerRecord` 继续保留，用于审计、统计和问题排查，但本期不做跨考试滚动分析。

#### 1.3 数据对象

| 数据对象 | 作用 | 保存策略 |
| --- | --- | --- |
| `Paper` | 真题试卷、考试类型、规定时长 | 正式试卷数据源 |
| `Question` | 题干、答案、模块、难度、知识点、解析 | 诊断计算唯一正式题目来源 |
| `ExamRecord` | 每次测试的开始、交卷、题量与正确数 | 每次重新测试新增一条 |
| `AnswerRecord` | 每道题的选择、正误、耗时与作答时间 | 按考试记录逐题保存 |
| `DiagnosticReportTask` | 分析状态、阶段、进度、重试和错误 | 每次成功交卷创建或幂等复用 |
| `DiagnosticReport` | 当前有效报告快照 | `userId + paperId` 唯一，成功发布时覆盖 |

`DiagnosticReport.result` 与分析输入快照必须使用数据库 JSON 对象保存，不得保存为 JSON 字符串。建议同时保存：

- `examRecordId`
- `reportKind`
- `result`
- `sourceSnapshot`
- `reportVersion`
- `promptVersion`
- `modelName`
- `generationMode`
- `completedAt`

`generationMode` 用于说明报告实际生成质量：

- `full_ai`：所有需要大模型的区域均使用有效 DeepSeek 结果。
- `mixed_fallback`：部分大模型区域使用规则兜底。
- `rules_only`：大模型整体不可用，但固定指标和规则文案已成功生成。

#### 1.4 状态定义

考试记录状态：

```text
in_progress → submitted
```

分析任务状态：

```text
pending → analyzing → completed
                    ↘ failed
```

分析阶段：

```text
answers_saved
fixed_calculating
module_analyzing
roi_analyzing
path_analyzing
report_saving
completed
```

只有固定计算或报告保存无法完成时，任务才进入 `failed`。DeepSeek 调用失败但固定指标能够完成时，使用规则兜底并将任务置为 `completed`，同时记录对应的 `generationMode`。

#### 1.5 权限边界

- 学生只能提交自己的考试记录并读取自己的分析状态和报告。
- 前端不能提交正确答案、正确性结论、难度结论或知识点统计作为可信结果。
- 后端必须根据 `Question` 正式数据重新计算正误和诊断指标。
- 管理员可查看任务状态、版本与错误日志，但不得直接修改学生作答结果。
- 报告接口必须同时校验 `examRecordId` 与当前登录用户，禁止通过猜测 ID 越权读取。

### 2. 页面描述

#### 2.1 诊断测试首页

每套真题根据当前学生的最新考试与分析状态展示：

| 状态 | 页面说明 | 主操作 |
| --- | --- | --- |
| 未开始 | 没有进行中的考试记录 | 开始测试 |
| 进行中 | 存在 `in_progress` 记录 | 继续测试 |
| 已交卷待分析 | 答卷已保存，任务为 `pending` | 查看生成进度 |
| 分析中 | 任务为 `analyzing` | 查看生成进度 |
| 报告已完成 | 当前有效报告已发布 | 查看报告 / 重新测试 |
| 最新分析失败且有旧报告 | 新任务失败，旧报告仍有效 | 查看上一次报告 / 重新分析 |
| 最新分析失败且无旧报告 | 当前没有可展示报告 | 重新分析 |

学生点击“重新测试”后，系统先校验考试类型是否开放、诊断额度是否充足，以及同一考试类型是否已有进行中的真题诊断。校验通过才创建新的考试记录；校验失败不得改变旧记录或旧报告。新报告完成前，旧报告可作为临时可用结果；新报告发布后，首页报告入口自动指向最新 `examRecordId`。

#### 2.2 诊断测试答题页

进入答题页时，前端先调用开始接口取得后端生成的 `examRecordId`。如果同一学生、同一考试类型存在未交卷真题诊断，则按以下规则处理：

- 未交卷记录属于当前试卷：接口返回该记录及已保存答案、耗时，页面恢复现场。
- 未交卷记录属于其他试卷：返回 `DIAGNOSTIC_IN_PROGRESS`，提示先完成正在进行的诊断，不创建新记录。
- 不存在未交卷记录：通过权益校验后创建新的考试记录和逐题作答记录，并写入 `activeDiagnosticKey`。

同一用户、同一考试类型的进行中诊断由数据库唯一占用约束兜底，避免重复点击、多窗口或并发请求创建多条进行中记录。

保存进度和交卷均只提交最小化逐题响应：

```json
{
  "responses": [
    {
      "questionId": "question-id",
      "selectedAnswer": "A",
      "durationSeconds": 35,
      "answerState": "answered"
    }
  ]
}
```

- 前端不提交题干、选项、正确答案、难度、知识点、试卷代码或正确性结论。
- `answerState` 只允许 `unseen / skipped / answered`；有答案时后端强制归为 `answered`，正确性始终由后端计算。
- 后端通过 URL 中的 `examRecordId` 获取用户、试卷、考试类型和正式题目范围。
- 请求仍兼容携带 `startedAt`，但诊断真题以服务端创建的 `ExamRecord.startedAt` 和 `expiresAt` 为准；后续保存与交卷不得覆盖开始时间或延长截止时间。
- 开始和重新测试请求中的客户端数据只用于定位目标试卷和提交作答；用户身份、考试类型、权益、考试状态与并发占用均由后端可信数据确定。
- 交卷额外携带 `submissionKey`，配合考试记录状态实现网络重试和重复点击幂等。

交卷交互必须包含：

- 未答题提示与二次确认。
- `confirmingSubmit`：确认弹窗打开期间禁止再次触发。
- `submitting`：请求发出后禁用交卷按钮并显示“正在交卷”。
- 交卷动作使用立即触发的节流与状态锁，不使用延迟执行的纯防抖。
- 手动交卷、倒计时自动交卷和页面其他提交入口共用同一提交锁。
- 请求失败后解除锁并保留当前答案，允许重新提交。

前端防重复仅改善交互，后端幂等仍是最终保障。

#### 2.3 报告分析弹窗

诊断测试成功交卷后不再跳转到独立分析过渡页，而是在当前答题页上方打开 `DiagnosticAnalysisDialog`。`ExamResultView.vue` 仅保留为刷新恢复和旧入口兼容，并直接复用同一个 `DiagnosticAnalysisDialog`，不再维护第二套轮询、重试或最短展示逻辑。

| 后端阶段 | 建议进度 | 页面文案 |
| --- | ---: | --- |
| `answers_saved` | 10% | 答卷已安全保存 |
| `fixed_calculating` | 20%～45% | 正在计算成绩与能力表现 |
| `module_analyzing` | 45%～65% | 正在分析各考试模块 |
| `roi_analyzing` | 65%～80% | 正在定位高价值提升方向 |
| `path_analyzing` | 80%～95% | 正在生成个性化学习路径 |
| `report_saving` | 95%～99% | 正在保存诊断报告 |
| `completed` | 100% | 诊断报告生成完成 |

进度规则：

- 前端不得再根据固定时间自行走到 100%。
- 后端未完成当前阶段时，前端可在阶段区间内缓慢动画，但不得越过阶段上限。
- 只有规则计算、DeepSeek 分析或规则兜底、结果校验和报告落库全部完成后，进度才到 100%。
- 报告保存失败时最多停在 99%，不能提前展示“已完成”。
- 到达 100% 且报告成功落库后进入完成态，不得自动跳转报告页面。
- 完成态提供“查看诊断报告”主按钮和“返回诊断测试”次按钮；只有学生点击主按钮后，才根据 `reportKind` 进入 ESAT 或 TMUA 独立报告页。
- 分析弹窗右上角提供关闭按钮；关闭后返回诊断测试首页，后台任务继续执行，不取消、不重建，也不丢失已保存进度。
- 分析弹窗从打开起最少展示 6 秒；后端在 6 秒内完成时等待满 6 秒再进入完成态，后端超过 6 秒时继续等待真实任务完成。
- 进度条下方每秒循环滚动六大模块名称：等效评估分、总体成绩概览、知识点掌握度、错题逐题分析、AI 提升规划表、AI 定制三阶段学习路径。
- 六大模块滚动字幕只用于等待反馈，不代表后端当前正在执行的精确阶段；标题和进度仍以后端任务状态为准。
- 页面刷新、关闭后可从诊断测试列表重新进入状态恢复页，并从后端读取真实状态，不从 0 重新模拟。
- 去掉固定“预计剩余 10 秒”，改为不承诺具体时长的说明。

#### 2.4 报告页面

- ESAT 路由：`/exam-result/:id/esat`。
- TMUA 路由：`/exam-result/:id/tmua`。
- 公共入口只负责根据考试类型跳转，不在同一页面混用两套诊断逻辑。
- 报告页读取已保存的 `DiagnosticReport.result`，不得在每次打开页面时重新调用 DeepSeek。
- 当前任务仍在分析时进入状态恢复页，继续读取同一个后台任务，不重复交卷或创建任务。
- 最新任务失败但存在旧报告时，允许进入旧报告并展示明确提示。

### 3. 核心流程

#### 3.1 开始与继续测试

1. 学生从诊断测试首页选择真题。
2. 前端调用 `POST /api/exams/start`，诊断真题提交 `paperId`，题库练习提交正式 `questionIds`。
3. 后端校验登录、会员权限、试卷类型、考试类型及题目范围。
4. 存在同试卷 `in_progress` 记录时返回同一 `examRecordId`、已保存答案和耗时；不存在时创建新的 `ExamRecord` 与对应 `AnswerRecord`。
5. 切换上一题、下一题或题号导航时，调用 `PUT /api/exams/:examRecordId/progress` 增量保存离开的题目；后端只更新请求中携带的 `AnswerRecord`，不得删除或覆盖其他题目。
6. 选择答案只更新前端状态并标记脏题；每 60 秒检查一次，只有答案尚未保存或当前题累计耗时比上次落库新增满 60 秒时才补交。
7. 页面隐藏或确认退出时结算并保存当前模块完整快照，后端进入 `paused` 并冻结剩余时间；切回或继续测试时由后端生成新截止时间，恢复成功后才重新累计单题耗时。
8. 逐题耗时传累计值而不是本次增量值，使重复请求保持幂等。
9. 意外退出后再次进入时重新调用开始接口，页面根据答案、累计耗时和 `answerState` 从数据库恢复。

#### 3.2 交卷事务

交卷接口必须在同一个数据库事务中完成：

1. 根据 URL 中的 `examRecordId` 校验考试记录属于当前学生且仍可提交。
2. 从考试记录推导 `paperId`、`examType` 与正式题目范围，不信任前端重复提交的上下文。
3. 从 `Question` 表加载正式答案、难度和知识点等分析事实。
4. 根据正式答案计算每题正误及总体统计。
5. 使用交卷携带的完整快照校验并保存全部 `AnswerRecord`，作为本次考试最终事实。
6. 更新 `ExamRecord.status = submitted`、`submittedAt` 与 `durationSeconds`；诊断真题总耗时最多计算到服务端 `expiresAt`。
7. 幂等创建 `DiagnosticReportTask`，初始状态为 `pending`。
8. 提交事务后返回考试记录和分析任务状态。

任何一步失败均整体回滚，不能出现“考试已提交但逐题答案不完整”或“答卷未保存但已开始分析”。

#### 3.3 后台分析任务

第一期采用“数据库任务状态 + API 后台执行 + 服务重启恢复”，暂不引入 Redis 或独立消息队列：

1. API 后台任务执行器领取 `pending` 任务。
2. 通过事务锁或租约将任务标记为 `analyzing`。
3. 更新心跳、当前阶段与进度。
4. 完成固定评分、模块统计、知识点聚合、能力矩阵等确定性计算。
5. 调用 DeepSeek 生成限定范围内的模块分析、高 ROI 解释和学习路径。
6. DeepSeek 失败时使用规则兜底，不阻塞固定报告生成。
7. 校验完整报告结构、事实数字、考纲白名单和资源引用。
8. 将任务结果保存为待发布报告快照。

服务启动时扫描长时间没有心跳的 `analyzing` 任务，将其重新置为可领取状态；因此任务状态不能只放在 Node 内存中。

#### 3.4 报告发布与覆盖

新报告完成后，在事务中执行：

1. 检查该任务是否仍属于该学生、该试卷最新一次已提交考试。
2. 对 `DiagnosticReport` 按 `userId + paperId` 执行 `upsert`。
3. 覆盖 `examRecordId`、报告结果、版本、模型信息和完成时间。
4. 将任务更新为 `completed`、阶段更新为 `completed`、进度更新为 `100`。

如果更早的任务在更晚的任务之后才完成，不允许反向覆盖最新报告。发布时必须比较提交时间或报告任务序号。

#### 3.5 前端轮询

分析弹窗和状态恢复页每约 2 秒查询一次：

```text
GET /api/exams/:examRecordId/diagnostic-report/status
```

建议返回：

```json
{
  "status": "analyzing",
  "stage": "roi_analyzing",
  "progress": 72,
  "message": "正在定位高价值提升方向",
  "reportExamRecordId": null,
  "reportKind": "esat"
}
```

完成后返回当前有效报告的考试记录 ID；前端先展示完成态，等待学生点击“查看诊断报告”后再跳转。组件卸载时停止轮询；再次进入时重新读取后端状态。

#### 3.6 幂等与并发

- 前端使用确认锁、提交锁、按钮禁用和节流，避免重复操作。
- 前端交卷前等待已经发出的增量保存请求结束，再提交完整最终快照。
- 后端以考试记录或幂等标识识别同一次提交。
- 进度更新语句必须同时满足 `ExamRecord.status = in_progress`；交卷先完成时，迟到的保存请求返回 `EXAM_ALREADY_SUBMITTED`，不得覆盖已判分答案。
- 交卷事务使用条件更新原子执行 `in_progress → submitted`；并发交卷只有第一个请求获得提交权，其余请求返回第一次提交的既有结果。
- `AnswerRecord` 按考试记录与题目唯一保存。
- `DiagnosticReportTask` 对同一次考试只允许一条有效任务。
- 重复提交返回同一考试记录和任务状态，不重复扣减权益、不重复调用 DeepSeek。
- 多窗口提交、网络自动重试和倒计时交卷必须得到相同结果。
- 重试报告分析只重试失败任务，不重新提交答卷、不重复扣减权益。

#### 3.7 建议接口

```text
POST /api/exams/start
创建考试记录；存在未交卷记录时返回该记录和已保存进度

PUT /api/exams/:id/progress
增量保存请求中发生变化题目的答案、状态与累计有效耗时

进行中保存只更新 `AnswerRecord`，不统计正确数、不更新 `ExamRecord.correctCount`；正式答案校验和总量统计统一在交卷事务中完成

POST /api/exams/:id/submit
提交最小化逐题响应，按正式题目判分并创建诊断分析任务

GET /api/exams/:id/diagnostic-report/status
查询真实分析状态与进度

GET /api/exams/:id/diagnostic-report
读取已持久化的当前有效报告

POST /api/exams/:id/diagnostic-report/retry
重新执行失败的分析任务
```

现有 `/diagnostic-report/summary` 应从“访问时重新计算”调整为“读取持久化结果”，或逐步迁移到新的报告读取接口。

### 4. 异常容错

#### 4.1 交卷失败

- 停留在答题页并保留本地答案。
- 不创建诊断任务，不打开分析弹窗。
- 解除提交锁后允许重试。

#### 4.2 重复提交

- 前端不重复弹窗、不重复发起请求。
- 即使前端失效，后端也只保留一份本次答案和一个分析任务。
- 返回既有 `examRecordId` 与任务状态。

#### 4.3 DeepSeek 异常

- 超时、限流、网络错误或非法 JSON 按约定进行有限次数重试。
- 重试后仍失败时，模块诊断、高 ROI 解释和学习路径使用规则兜底。
- 固定指标和报告保存成功时，任务仍为 `completed`。
- 报告记录 `mixed_fallback` 或 `rules_only`，便于后台追踪。

#### 4.4 新报告整体失败

- 不覆盖上一份成功报告。
- 有旧报告时显示：`最新一次分析失败，当前展示上一次报告`。
- 无旧报告时显示失败状态和“重新分析”。
- 重新分析不重复提交答案、不重复扣减权益。

#### 4.5 服务中断

- 任务进度和心跳保存在数据库。
- 服务重启后重新领取失去心跳的任务。
- 同一个任务被多个执行器同时领取时，通过数据库锁或租约保证只有一个有效执行者。

#### 4.6 数据异常

- 缺少难度或知识点不影响基础评分，但对应分析区域降级。
- 评分规则不可用时不伪造等效分，只展示原始作答数据和明确提示。
- 报告结构校验失败时不得发布不完整 JSON。

### 5. 后续与非目标说明

#### 5.1 本期包含

- 答卷事务化保存。
- 诊断任务状态与进度持久化。
- 交卷后使用分析弹窗承载真实进度，独立状态页保留为恢复入口。
- 报告结果持久化，打开报告时不重新分析。
- 最新成功报告覆盖旧报告。
- 最新分析失败时保留并允许查看上一份成功报告。
- DeepSeek 失败时使用规则兜底生成报告。
- 前后端幂等、重复提交与并发保护。
- API 服务重启后的任务恢复。

#### 5.2 本期不包含

- 不合并多次测试数据生成滚动报告。
- 不保留多个可供学生切换查看的历史报告版本。
- 不实现阶段 Checkpoint、微测或滚动学习路径更新。
- 不引入 Redis、BullMQ、RabbitMQ 或其他独立消息队列。
- 不在报告打开时自动使用新算法覆盖旧结果。

#### 5.3 后续升级消息队列的条件

当出现多实例部署、高并发交卷、DeepSeek 长时间排队、需要独立扩缩容分析 Worker 或需要更成熟的失败队列管理时，可将数据库任务执行器替换为 Redis + BullMQ 或独立消息队列。任务状态和报告快照仍以数据库为最终事实来源。

## 第二节：ESAT 诊断报告详解

### 1. 功能边界与目的

#### 1.1 报告目标

ESAT 诊断报告用于回答以下问题：

- 每个考试模块本次表现如何。
- 当前模块大致处于什么水平。
- 不同难度与知识点上的直接作答表现如何。
- 哪些“知识点 × 难度”格子最值得优先投入。
- 如何结合学生的备考目标生成三阶段学习安排。

#### 1.2 ESAT 核心评分原则

- ESAT 各模块独立评分，不计算总分。
- 模块切换只属于“等效评估分”模块，不放在整份报告最外层，避免造成整页按科目切换的误解。
- 评分、正确率、样本量、难度、知识点、时间、百分位参考位置等事实由代码读取或计算。
- DeepSeek 只解释确定性事实、生成个性化建议和学习任务，不得修改事实数字。
- 报告生成后保存为快照，后续查看不再次调用模型。

#### 1.3 完成方式

| 完成方式 | 定义 | 约束 |
| --- | --- | --- |
| 代码固定读取 | 从 `Paper`、`Question`、`ExamRecord`、`AnswerRecord`、`SyllabusNode` 和用户备考资料读取 | 不允许模型改写 |
| 代码固定计算 | 按评分映射、统计公式、样本阈值和阶段规则计算 | 相同输入必须得到相同输出 |
| 代码固定模板 | 在模型不可用时生成安全、可解释的兜底文案 | 只能引用已计算事实 |
| DeepSeek 推理 | 基于结构化事实生成分析、解释和学习安排 | 不得创造分数、知识点、资源或录取结论 |

#### 1.4 报告组成

1. 报告头。
2. Part 1：等效评估分。
3. Part 2：总体成绩概览。
4. Part 3：知识点掌握度。
5. Part 4：错题逐题分析。
6. Part 5：AI 提升规划表。
7. Part 6：AI 定制三阶段学习路径。

### 2. 页面描述与各 Part 完成方式

#### 2.1 报告头

展示考试类型、试卷名称或年份及“成绩报告”标题。页面宽度与导航栏内容区、个人中心内容区保持一致。

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 考试类型 | `ExamRecord.examType` | 代码固定读取 |
| 试卷名称、年份 | `Paper.title/code/year` | 代码固定拼接 |
| 报告类型 | 已保存报告的 `reportKind` | 代码固定读取 |

报告头不放置数学 1、数学 2、物理等全局切换器。

#### 2.2 Part 1：等效评估分

##### 2.2.1 模块切换

- 模块切换器放在等效评估分组件内部。
- 模块来源于本次试卷实际包含的 ESAT 模块，不写死数学 1、数学 2、物理。
- 切换只改变 Part 1 当前模块的估分、定位、难度分析和模块诊断。
- ESAT 报告不生成多个模块相加后的总分。

##### 2.2.2 模块估分

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 原始正确数与题量 | 当前模块 `Question` + `AnswerRecord` | 代码固定统计 |
| 原始正确率 | 正确数 / 当前模块题量 | 代码固定计算 |
| `/27` 等效原始分 | 正确率 × 27 | 非标准题量时固定归一 |
| 当前估分 | `/27` 等效原始分 + 版本化换算规则 | 代码固定计算 |
| 80% 估分参考区间 | 当前样本量的 Wilson 区间映射到评分规则 | 代码固定计算 |

标准 ESAT 模块按 27 题处理。历史卷或非标准题量模块先按正确率归一为 `/27` 等效原始分，再进行换算，并显示：

> 本模块为 N 题非标准题量，已按正确率归一为 /27 等效原始分，区间相应放宽。

计算过程在黄色说明区域一行展示，例如：

```text
原始作答 1/10 → 原始正确率 10.0% → /27 等效原始分 2.7
```

当前估分下方一行展示“估分参考区间”，并通过 Element Plus Tooltip 解释：

- 当前估分基于本次模块作答结果与平台参考换算规则。
- 区间用于表达当前题量下的估分不确定性。
- 该结果是平台等效评估，不是官方出分。

##### 2.2.3 水平定位与竞争力评估

使用 ECharts 展示当前模块的官方历史成绩分布，不再绘制假设性的标准钟形曲线：

- 数据来源为 UAT-UK 发布的 ESAT 2025 年 10 月与 2026 年 1 月合并成绩分布。
- 数学 1、数学 2、物理、化学、生物分别使用自身的 0.5 分档分布，切换模块时同步切换曲线。
- 横轴显示 1.0～9.0 模块分数，纵轴显示对应分数档考生占比。
- 图中使用定位线和散点显示考生当前模块估分及其所在真实分布高度。
- 鼠标悬浮到曲线数据点时，显示该分数档及考生占比。
- 官方材料只发布柱状图，项目数据由官方图表数字化并归一，界面需提示可能存在约 0.1 个百分点的读取误差。
- 曲线仅对官方离散分档进行平滑连接，不使用正态分布公式生成或补造数据。

当前表现等级采用固定映射：

| 模块估分 | 表现等级 |
| --- | --- |
| 8.0～9.0 | Excellent |
| 7.0～7.9 | Very Good |
| 6.0～6.9 | Good |
| 4.0～5.9 | Average |
| 1.0～3.9 | Below Average |

表现等级后增加 Tooltip，说明等级由平台按当前模块估分区间映射；参考百分位不再使用固定档位，而是按当前模块官方分布采用中秩累计并在相邻分数档间插值估算。

“该模块仍有较大提升空间”等竞争力描述不再只使用单调固定短句：

- 估分、表现等级和参考百分位由代码固定计算，其中百分位与图表共用同一份官方模块分布数据。
- DeepSeek 根据模块正确率、难度分布和样本量生成更具体的定位解释。
- DeepSeek 不得改变等级、百分位或分数。
- 模型不可用时使用规则兜底文案。

##### 2.2.4 难度掌握分析

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 低、中、高难度题量 | `Question.difficulty` | 代码固定分组 |
| 正确题数 | `AnswerRecord.isCorrect` | 代码固定统计 |
| 正确率 | 正确数 / 对应难度题量 | 代码固定计算 |
| 当前科目标识 | 当前 Part 1 模块 | 代码固定展示 |

每张难度卡明确标注当前模块名称，避免切换数学 1、数学 2、物理后误认为仍在查看上一科。没有对应难度题时显示“无此难度题”，不显示误导性的 0%。

##### 2.2.5 模块诊断分析

每个模块的诊断提示由 DeepSeek 基于以下固定事实生成：

- 模块估分与参考区间。
- 正确数、总题量与正确率。
- 低、中、高难度正确数、总数和样本量。
- 当前表现等级。

输出包含：

- 本次表现总结。
- 相对优势。
- 主要问题。
- 优先改进建议。

模型不得生成新分数、院校结论、心理归因或未观察到的错误类型。模型失败时由代码生成引用真实题量、正确率和难度表现的规则分析。

#### 2.3 Part 2：总体成绩概览

ESAT 不展示 `7.5/9.0` 一类跨模块总分，也不展示整场汇总的“正确、错误、未答”大卡片。

左侧成绩概览以分模块作答为核心：

- 每个模块的正确数 / 总题数。
- 模块正确率。
- 模块内低、中、高难度的正确数 / 总题数。
- 没有对应难度题时显示“无题”。

各模块卡片同时展示，不承担模块切换；Part 1 的模块切换器是全页唯一的当前模块选择入口。所有成绩统计均由代码固定计算，不调用 DeepSeek。

##### 2.3.1 考试节奏与时间效率

时间模块不以“平均每题几分钟”为核心，而是回答以下问题：

1. 本次是否在规定时限内完成整卷？
2. 已记录的时间主要消耗在哪一类题目？
3. 耗时是否换来了正确率？
4. 哪个模块存在时间黑洞，下一次应限时训练、复盘，还是调整跳题策略？

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 总用时 | `ExamRecord.durationSeconds` | 代码固定读取 |
| 作答覆盖、已记录题时覆盖 | `AnswerRecord.answerState/selectedAnswer/durationSeconds` | 代码固定统计 |
| 节奏状态 | 总用时、规定时长、实际覆盖题数 | 代码固定计算 |
| 单题目标题时 | `Paper.duration` + 当前题 `difficulty` | 代码按难度权重分配 |
| 时间效率四象限 | 单题耗时、目标题时、正误 | 代码固定分类 |

总用时代表真实考试从开始到提交的持续时长；逐题耗时只累计题目处于可作答状态时的活跃时间。两者口径不同，因此不得把差值解释为“中断耗时”，一期也不单独展示该差值。

单题目标题时不按模块题量平均估算，而是先为低、中、高难度赋予 `0.8 / 1.0 / 1.25` 的时间权重，再将整卷规定时长按权重分配。所有题目的目标题时之和必须等于试卷规定时长。

节奏状态采用固定规则：

| 条件 | 状态 |
| --- | --- |
| 总用时超过规定时长 | 已超过规定时长 |
| 未超时但实际覆盖题数少于全卷题数 | 本次未完成整卷 |
| 未超时且已覆盖全卷 | 节奏在时限内 |
| 缺失总用时或规定时长 | 节奏待记录 |

时间效率四象限只统计“已作答且已记录正耗时”的题目；快慢以该题实际耗时是否超过其目标题时划分：

| 象限 | 代码条件 | 解释 |
| --- | --- | --- |
| 快且对 | 实际耗时 ≤ 目标题时，且答对 | 相对熟练，可保持节奏 |
| 慢且对 | 实际耗时 > 目标题时，且答对 | 理解正确，但需训练熟练度 |
| 快且错 | 实际耗时 ≤ 目标题时，且答错 | 优先检查审题、计算或作答策略 |
| 慢且错 | 实际耗时 > 目标题时，且答错 | 核心时间黑洞，优先复盘 |

模块时间效率不在总体成绩概览展示，而是作为 Part 6 学习路径的限时训练分析输入。

逐题计时按可靠度分三档展示，不再让短时测试出现整块空白：

| 条件 | 展示 |
| --- | --- |
| 计时覆盖 <30%，或缺少总用时/规定时长 | 仅显示总用时、覆盖情况与样本不足提示 |
| 计时覆盖 30%～79%，或逐题时长合计与总用时比例不在 70%～115% | 直接展示四象限与模块效率，并通过“已记录题数 / 模块题数”表达样本边界，不额外显示参考性提示条 |
| 计时覆盖 ≥80%，且逐题时长合计 / 总用时在 70%～115% | 显示“完整时间分析”，额外展示已记录题平均耗时与超出目标题时题数 |

时间事实、状态、阈值、象限和模块效率均由代码计算；DeepSeek 不参与时间判定，也不得生成未被记录的时间结论。

#### 2.4 Part 3：知识点掌握度

- 按本次实际考试模块分组。
- 默认展开第一个模块，其余模块收起。
- 所有模块均可独立展开和收起。
- 模块内默认展示本次试卷涉及的二级知识点。
- 点击二级知识点前的加号展开三级知识点。
- 不展示当前试卷完全没有涉及的知识点。

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 模块分组 | `Question.subject/module` | 代码固定分组 |
| 二、三级知识点 | `Question.topicCode/knowledgePoints` + `SyllabusNode` | 代码按考纲映射 |
| 正确考查次数 | 正确题对应知识标签 | 代码固定聚合 |
| 总考查次数 | 本次题目知识标签出现次数 | 代码固定聚合 |
| 掌握率 | 正确考查次数 / 总考查次数 | 代码固定计算 |

一道题含多个知识标签时会计入多个知识点，因此统一使用“考查次数”，不误写为“题数”。本模块不调用 DeepSeek。

#### 2.5 Part 4：错题逐题分析

| 内容 | 数据来源 | 完成方式 |
| --- | --- | --- |
| 题号导航与作答状态 | `Question.number` + `AnswerRecord` | 代码固定读取 |
| 题干、选项、图片、公式 | `Question` | 复用正式题目渲染链路 |
| 用户选择 | `AnswerRecord.selectedAnswer` | 代码固定读取 |
| 正确答案 | `Question.answer` | 代码固定读取 |
| 考察点 | `Question.knowledgePoints` | 代码固定读取 |
| 题目解析 | `Question.explanation` | 代码固定读取 |
| 针对练习入口 | 考试类型、知识点和难度 | 代码生成试题库筛选条件 |

题干、答案、知识点和解析必须来自同一条 `Question` 正式记录。报告打开时不让 DeepSeek 临时补写标准答案或题目解析。

“复习引导”跳转到试题库，自动带入当前题目的考试类型、主要知识点和难度。知识点缺失时禁用该入口并提示题目尚未完成知识点标注。

#### 2.6 Part 5：AI 提升规划表

##### 2.6.1 能力缺口矩阵

矩阵行是本次试卷涉及的二级知识点，列是低、中、高难度。每格展示正确数、总数、正确率和样本量 `n`。

| 条件 | 状态 | 展示规则 |
| --- | --- | --- |
| `n = 0` | 本次未考查 | 灰色，不计算正确率结论 |
| `n < 3` | 样本不足 | 灰色，只展示直接作答数据 |
| `n ≥ 3` 且正确率 > 70% | 较强 | 绿色 |
| `n ≥ 3` 且正确率 40%～70% | 待提升 | 黄色 |
| `n ≥ 3` 且正确率 < 40% | 明显缺口 | 红色 |

“样本不足”表示本次试卷在该“知识点 × 难度”格子中的题目少于 3 道，当前数据不足以形成稳定掌握结论，不代表学生一定不会。

矩阵、样本量、正确率和颜色完全由代码计算；一期不依赖知识点依赖图，也不生成推断百分比。

##### 2.6.2 高 ROI 缺口清单

候选条件：

- 只从 `n ≥ 3` 的直接观察格中选择。
- 正确率不高于 70%。
- 最多展示 5 项；不足 5 项时按实际数量展示，不补造。

固定代码负责：

- 候选筛选。
- 排序基础：红色优先、较高难度优先、较低正确率优先、较大样本优先。
- 正确率、样本量和难度事实。
- 建议投入时长区间。

DeepSeek 负责：

- 使用具体正确率和样本量解释为什么优先。
- 给出不依赖知识点依赖图的基础检查建议。
- 不得新增候选项、修改排名事实、修改投入时长或创造知识点。

5 张卡片保持一行展示，内容区宽度不变；超出宽度时使用横向滚动条，不换成多行。

#### 2.7 Part 6：AI 定制三阶段学习路径

##### 2.7.1 分析输入

学习路径结合：

- 备考科目。
- 目标院校。
- 目标专业。
- 考试日期。
- 每周可投入时长。
- 目标分数或目标要求。
- 当前各模块预估分。
- 高 ROI 缺口数量和严重程度。
- 模块时间效率：当前模块已记录题平均耗时 / 当前模块目标平均题时；仅在逐题计时可用时纳入。

缺失资料时明确列出“尚未设置”项并使用保守默认值，不推断院校录取门槛。

学习路径总览区展示“模块时间效率”分析卡：以 `1.0×` 为当前模块目标题时；小于 `0.75×` 为相对快，大于 `1.25×` 为相对慢。每张卡同时展示“已记录题数 / 模块题数”和模块正确率，并给出代码固定的限时训练或审题复盘建议。该分析会传入 DeepSeek 学习路径提示词，模型只能据此调整训练表达，不得创造未记录的耗时、比例或速度问题。

##### 2.7.2 模式判定

当前模式不能只根据考试日期划分。代码综合以下因素计算压力指数和规划周期：

- 距离考试周数。
- 每周可投入时长。
- 当前模块平均预估分。
- 高 ROI 缺口总数。
- 正确率低于 40% 的严重缺口数量。
- 当前分数与目标分数的差距。

模式为 `Intensive`、`Standard` 或 `Extended`。模式名称、周数、总投入时长和判定原因由代码固定计算，DeepSeek 不得修改。页面不展示“路径分析：DeepSeek 个性化”等技术实现文案。

##### 2.7.3 三阶段内容

| 阶段 | 固定骨架 | DeepSeek 个性化内容 |
| --- | --- | --- |
| 基础补漏 | 周数、时间预算、候选缺口、目标阈值 | 阶段目标、执行策略、重点任务表达 |
| 难度提升 | 周数、时间预算、训练范围 | 中高难度迁移与限时训练安排 |
| 模考冲刺 | 周数、考试日期、备考科目 | 模考节奏、错题回收与稳定性安排 |

三阶段周数由代码按总周期分配并保证连续。DeepSeek 只能从代码提供的高 ROI 缺口和真实备考资料中选择，不得新增知识点或虚构资源。

任务项使用“学习安排”样式，表示建议执行的计划，不显示已完成勾选，也不显示空心待办框。本期没有任务完成后回到报告勾选的交互。

##### 2.7.4 本期取消内容

- 不展示“滚动路径 V3”。
- 不展示阶段 Checkpoint。
- 不提供阶段结束后触发再诊断。
- 不根据后续学习行为自动更新路径。
- 不展示任务完成状态。

### 3. 核心分析策略

#### 3.1 固定计算先于模型推理

ESAT 报告生成顺序：

1. 后端加载正式试卷、题目、逐题答案、考纲和用户备考资料。
2. 代码完成模块分组、估分、区间、表现等级、难度、知识点和能力矩阵。
3. 代码筛选高 ROI 候选并计算建议投入区间。
4. DeepSeek 基于固定事实生成模块分析和高 ROI 解释。
5. 代码根据时间、投入、分数、缺口和目标确定学习模式及三阶段骨架。
6. DeepSeek 在骨架和候选范围内生成个性化学习安排。
7. 后端校验模型 JSON、事实数字、百分比、知识点、时长和资源引用。
8. 无效模型输出逐项回退到规则文案。
9. 保存完整 ESAT 报告快照。

#### 3.2 DeepSeek 提示词位置与约束

ESAT 模块分析、高 ROI 解释和学习路径提示词统一维护在：

```text
api/src/services/esatDiagnosticReport.ts
```

模型调用封装位于：

```text
api/src/services/deepseek.ts
```

API Key 只从 `DEEPSEEK_API_KEY` 环境变量读取，不写入数据库、日志、前端或 Git。模型只接受 JSON 输入并返回 JSON，不接受 Markdown 包装。

#### 3.3 模型输出校验

- 模块 ID 必须属于本次实际模块。
- 高 ROI `gapKey` 必须属于代码候选集合。
- 正确率、样本量和分数必须与输入一致。
- 百分比只能引用允许的输入值和固定目标值。
- 学习时长不得超过代码预算。
- 不得生成院校录取线、录取概率或心理归因。
- 不得声明未经数据支持的知识点依赖关系。
- 不得生成不存在的试题、资源 ID 或站外链接。

#### 3.4 规则兜底

DeepSeek 失败时仍生成完整可查看报告：

- 模块分析引用真实正确数、正确率和难度表现。
- 高 ROI 原因引用真实正确率、样本量和风险阈值。
- 学习路径使用固定模式、阶段骨架和候选缺口生成保守安排。
- 页面可通过后台字段识别分析来源，但不因模型失败阻塞学生查看。

### 4. 异常容错

#### 4.1 非标准题量

按正确率归一到 `/27` 等效原始分，扩大估分区间并明确标记“非标准题量归一”。不得直接使用少量题目的正确数查询 27 题换算表。

#### 4.2 评分规则缺失

隐藏无法可靠生成的估分、区间、等级和定位，只展示原始作答结果，不使用前端公式猜测。

#### 4.3 难度缺失

题目仍计入模块正确率和估分，但不进入难度掌握和能力矩阵，对缺失字段记录数据质量异常。

#### 4.4 知识点缺失

题目仍计入模块成绩，但不进入知识点掌握度、高 ROI 矩阵和针对练习筛选。

#### 4.5 样本不足

`n < 3` 只展示直接作答数据，不生成强弱结论，不进入高 ROI 候选。

#### 4.6 用户备考资料缺失

列出缺失项，使用保守默认周数或每周时长，不推断目标院校要求；学习路径仍可使用本次报告事实生成规则兜底。

#### 4.7 DeepSeek 异常

单个分析区域失败时只降级该区域；全部模型调用失败时使用 `rules_only` 报告。固定估分、难度、知识点和矩阵不受影响。

### 5. 后续与非目标说明

#### 5.1 本期确定

- ESAT 与 TMUA 前端页面和后端诊断逻辑分开。
- ESAT 各模块独立评分，不计算总分。
- 科目切换位于等效评估分内部。
- 固定事实由代码计算，大模型只做受控解释和个性化安排。
- 报告结果持久化，后续查看不重复分析。
- 知识点只展示本次试卷实际涉及项。
- 高 ROI 最多 5 项并横向滚动展示。
- 学习路径结合个人备考信息和本次诊断事实。
- DeepSeek 失败时生成规则兜底报告。

#### 5.2 本期不做

- 不计算 ESAT 跨模块总分。
- 不做知识点依赖图推理。
- 不做多次考试滚动分析。
- 不做 Checkpoint、微测和路径滚动更新。
- 不做学习任务完成勾选。
- 不让 AI 计算分数、正确率、样本量、表现等级或投入预算。
- 不生成院校录取概率、虚构资源或站外学习链接。

#### 5.3 核心验收点

1. 同一学生、同一试卷的新报告只有成功发布后才覆盖旧报告。
2. 新报告失败时可查看上一份成功报告，并显示明确提示。
3. DeepSeek 失败但固定计算成功时仍能生成完整规则兜底报告。
4. 分析弹窗进度由后端真实阶段驱动，报告保存前不能到 100%，完成后不得自动跳转。
5. ESAT 页面不显示总分，模块切换只出现在等效评估分内部。
6. 所有分数、题数、正确率、难度和知识点均可追溯到正式数据库数据。
7. `n < 3` 的矩阵格显示样本不足且不进入高 ROI 候选。
8. 学习路径不展示滚动更新、Checkpoint 或已完成任务状态。
9. 再次打开报告时读取已保存结果，不重新调用 DeepSeek。
