# 4.9 支付功能说明

> 文档对象：产品经理、测试人员、运营管理员、客服与财务协作人员  
> 文档性质：当前系统支付功能的产品行为说明与测试验收依据  
> 支付服务商：银联商务天满服务平台  
> 当前支付形态：C 扫 B 聚合二维码支付  
> 当前版本日期：2026-07-15

本文从功能角度说明会员支付的完整链路，包括定价、创建订单、扫码支付、支付确认、会员权益发放、个人支付记录、管理员全站订单、退款、订单详情、每日交易对账和异常人工处理。

本文不展开 OPEN-BODY-SIG、接口报文签名等开发实现；技术接入细节参见 [3.5支付技术方案.md](./3.5支付技术方案.md)。

## 1. 功能边界与目的

### 1.1 功能目标

学生可以在首页购买 TMUA、ESAT 会员套餐，通过银联商务聚合二维码使用支付宝、微信或云闪付完成付款；系统确认真实支付结果后自动发放或延长会员权益。管理员可以配置价格、查看全站订单、发起全额退款、查看完整审计详情，并通过逐单查询银联的方式发现和人工处理交易差异。

### 1.2 角色与权限边界

| 角色 | 可以执行 | 不可以执行 |
|---|---|---|
| 未登录访客 | 查看首页会员方案和价格；打开支付弹窗 | 创建支付订单、查看个人支付记录、获得会员权益 |
| 已登录学生 | 选择考试类型、套餐和支付方式；生成二维码；支付；查看自己的支付记录 | 查看其他用户订单；配置价格；退款；执行对账 |
| 已登录会员 | 执行学生的全部支付操作；购买新考试类型会员；续费或延长现有会员 | 管理全站支付、退款和对账 |
| 管理员 | 配置全站价格和支付开关；查看所有用户订单；查看订单详情；发起全额退款；执行对账；人工复核或标记异常已处理 | 在没有银联可信结果的情况下强制把订单改为已支付；查看 AppKey、通讯密钥等秘密 |
| 银联商务 | 生成聚合支付二维码；受理支付；返回支付、关闭、退款和查询结果；发送异步通知 | 决定系统会员套餐、业务价格和权益内容 |

所有后台支付接口均要求管理员身份。仅在前端隐藏按钮不能替代服务端权限校验。

### 1.3 当前交付范围

当前版本包含：

1. 管理员配置首次月付价、正常月价、年价和支付开放状态。
2. 首页会员卡片读取后台正常月价。
3. 支付弹窗选择考试类型、月度或年度套餐及支付方式。
4. 后端按实时策略计算金额并创建银联商务一次性聚合二维码。
5. 支付异步通知验签、主动查询、前台轮询和后台补偿查询。
6. 支付成功后创建或延长会员权益。
7. 用户在个人中心查看自己的支付记录。
8. 管理员查看全站支付订单，支持搜索、状态筛选和分页。
9. 管理员对已支付订单发起全额退款并查询退款结果。
10. 退款成功后回收该订单对应的会员时长。
11. 支付、退款、过期订单和会员到期的后台生命周期处理。
12. 从本地订单出发、逐笔查询银联状态的每日交易核对。
13. 对账异常由管理员显式执行“复核并修复”或“标记已处理”。
14. 管理员查看订单、银联标识、时间线、通知、退款、权益和对账详情。

### 1.4 关键术语

#### 1.4.1 业务与交易术语

| 术语 | 含义 | 产品与测试关注点 |
|---|---|---|
| 银联商务 | 本系统接入的支付服务商，负责连接支付宝、微信、云闪付等付款渠道 | “使用银联商务”不等于用户只能使用银行卡或云闪付 |
| 天满服务平台 | 银联商务提供的开发者、参数与接口管理平台 | 测试参数和生产参数相互隔离，不可混用 |
| 聚合支付 | 通过一套银联商务接口受理多种钱包渠道 | 商户必须分别具备相应渠道权限 |
| C 扫 B | Customer Scan Business，消费者扫描商户生成的二维码付款 | 当前系统的主要支付形态 |
| 支付策略 | 管理员配置的首次月价、正常月价、年价和支付开关 | 保存后影响后续创建的新订单，不追溯修改旧订单 |
| 支付订单 | 用户一次购买尝试形成的交易记录 | 每次重新生成二维码都会创建一笔新订单 |
| 业务订单号 / `orderNo` / `billNo` | 系统生成并提交给银联的唯一账单号 | 是用户、客服、管理员和银联共同定位交易的主要编号 |
| 渠道流水号 / `providerOrderNo` | 银联或目标支付渠道在付款成功后返回的交易编号 | 通常支付成功后才存在，用于渠道侧排查 |
| 支付渠道 | 用户计划使用的支付宝、微信或云闪付 | 当前记录的是生成订单时选中的渠道，参见 5.3 的已知边界 |
| 应付金额 | 创建订单时由后端依据支付策略计算的金额 | 前端显示值不能作为最终定价依据，金额以人民币“分”保存 |
| 一次性二维码 | 对应一笔确定金额和订单号的付款二维码 | 支付成功或关闭后不能再次使用；默认有效期 15 分钟 |
| 异步通知 | 用户支付后，银联从服务端主动通知本系统的结果 | 不依赖用户浏览器是否仍然打开；必须验签和幂等处理 |
| 主动查询 | 本系统使用订单号向银联查询实时状态 | 用于前台轮询、通知兜底、退款查询、对账和人工复核 |
| 履约 | 支付确认后真正发放业务权益 | 当前履约内容是创建或延长对应考试类型的会员权益 |
| 幂等 | 同一通知或同一操作重复到达时，结果只生效一次 | 重复通知不能重复开通会员；重复退款不能产生多笔有效退款 |
| 关单 | 关闭未支付二维码，使订单不能继续付款 | 关闭弹窗和订单过期时可能触发；已支付订单不能关单 |
| 退款单 | 管理员针对原支付订单发起退款时生成的独立记录 | 退款单号与支付订单号不同；当前只支持全额退款 |
| 原路退款 | 资金退回用户原付款渠道 | 退款到账时间由银联及目标支付渠道决定 |
| 会员权益 | 用户在某考试类型下的会员套餐、状态和有效期 | 一笔订单可同时为多个所选考试类型发放权益 |

#### 1.4.2 银联标识与配置术语

| 术语 | 含义 | 后台展示规则 |
|---|---|---|
| 测试环境 / 生产环境 | 分别用于模拟联调与正式商户真实资金交易 | 订单详情显示当前服务端所处环境 |
| AppId | 天满平台分配给开发者应用的标识 | 详情页只显示脱敏值 |
| AppKey | 平台接入签名密钥 | 仅保存在服务端，后台不返回、不展示 |
| MID | Merchant ID，银联商务商户号 | 订单详情用于定位收款商户 |
| TID | Terminal ID，银联商务终端号 | 与 MID、业务类型共同定位交易接入参数 |
| `instMid` | 银联商务业务类型/机构商户参数；当前为 `QRPAYDEFAULT` | 用于校验通知是否属于当前支付业务 |
| `msgSrcId` | 银联分配的四位来源编号 | 作为订单号前缀，也用于定位请求来源 |
| 通讯密钥 | 用于校验银联支付结果通知的密钥 | 仅保存在服务端，绝不展示给前端 |
| `billDate` | 银联账单日期，格式为 `YYYY-MM-DD` | 查询、关闭和退款时用于定位原交易 |
| `qrCodeId` | 银联二维码标识 | 关闭二维码时使用；不等同于订单号 |
| `systemId` | 银联返回的系统标识 | 某些二维码关闭场景中用于辅助定位 |
| `notifyUrl` | 银联向系统发送支付结果的服务端地址 | 不能依赖登录态，必须公网可访问 |
| `returnUrl` | 支付完成后的网页返回地址 | 只负责页面体验，不能作为支付成功依据 |

#### 1.4.3 对账与异常处理术语

| 术语 | 含义 | 当前系统行为 |
|---|---|---|
| 交易对账 | 比较本地订单状态、金额与银联查询结果 | 当前从本地订单出发逐笔查询银联，不是下载银联全量账单 |
| 对账业务日期 | 需要核对的中国自然日 | 范围包括该日创建、支付成功或退款成功的本地订单 |
| 对账批次 | 某个业务日期的一次对账执行记录 | 同一日期只保留一个批次；再次执行会重算该日期明细 |
| 立即对账 | 管理员选择日期后主动执行逐单银联查询 | 会生成或更新对账结果，不会自动修改订单、退款或会员 |
| 刷新 | 重新读取数据库中已有的摘要和异常列表 | 不请求银联，不生成新对账结果，不修改任何状态 |
| 一致 | 本地状态、银联状态和订单金额均可对应 | 无需管理员处理 |
| 状态异常 | 本地状态与银联状态不一致，或金额不一致 | 进入待处理异常 |
| 查询失败 | 银联查询失败、超时或返回缺少可校验金额 | 进入待处理异常，可稍后复核 |
| 复核并修复 | 管理员确认后再次查询银联，并在安全条件满足时修复业务状态 | 可能修改订单、退款和会员；不能任意手输状态 |
| 标记已处理 | 管理员已经在线下核实并填写说明后关闭告警 | 不查询银联，也不修改订单、退款或会员状态 |
| 本地状态 | QuizTestDemo 数据库中的支付订单状态 | 后台对账列左侧显示 |
| 银联状态 | 银联主动查询返回的账单状态 | 后台对账列右侧显示 |
| 全量账单对账 | 以银联完整账单为输入，与本地订单双向匹配 | 当前未实现，后续补充；可发现“银联有、本地没有”的交易 |
| 异常外部告警 | 通过邮件、短信或企业消息通知值班人员 | 当前未实现；目前只在后台展示异常指标和明细 |

### 1.5 状态定义

#### 1.5.1 支付订单状态

| 内部状态 | 页面文案 | 含义 | 可执行操作 |
|---|---|---|---|
| `pending` | 待支付 | 已创建本地订单，通常已获得二维码，尚未确认付款 | 用户扫码、主动查询、关闭；系统查询或过期关单 |
| `paid` | 已支付 | 银联确认支付成功，金额校验通过，会员权益已履约 | 管理员查看详情、发起全额退款 |
| `failed` | 失败 / 支付失败 | 二维码创建或支付处理出现确定失败 | 查看失败码和失败原因；重新创建新订单 |
| `closed` | 已关闭 | 用户主动关闭、二维码过期或银联返回已关闭 | 重新创建新订单；不能继续支付原二维码 |
| `refunding` | 退款中 | 已提交全额退款，等待银联最终结果 | 管理员查询退款；后台任务定期查询 |
| `refunded` | 已退款 | 银联确认全额退款成功，相关会员时长已回收 | 只读查看和审计 |

支付订单主要状态流转：

```text
待支付 ──支付成功──> 已支付 ──发起退款──> 退款中 ──退款成功──> 已退款
   │                     │                    └─确定失败──> 已支付
   ├─创建失败──> 失败     └─不允许关单
   └─取消/过期──> 已关闭
```

#### 1.5.2 退款状态

| 内部状态 | 页面文案 | 含义 |
|---|---|---|
| `processing` | 处理中 | 退款请求已建立，尚未得到最终成功或失败结果 |
| `succeeded` | 已退款 | 银联确认退款成功，资金与权益处理完成 |
| `failed` | 失败 | 银联返回明确失败；原订单恢复为已支付 |

#### 1.5.3 会员状态

| 内部状态 | 页面文案 | 含义 |
|---|---|---|
| `active` | 生效中 | 当前时间处于会员有效期内 |
| `expired` | 已到期 | 有效期自然结束，后台任务已收敛状态 |
| `cancelled` | 已取消 | 退款等原因导致该段权益被撤销 |

#### 1.5.4 支付通知状态

| 内部状态 | 页面文案 | 含义 |
|---|---|---|
| `received` | 已接收 | 通知已经落库，正在处理或等待处理结果 |
| `processed` | 处理成功 | 验签、商户校验和订单同步完成 |
| `failed` | 处理失败 | 验签失败、商户不匹配、订单不存在或查询失败等 |
| `ignored` | 忽略 | 预留兼容状态，当前主链路不主动产生 |

#### 1.5.5 对账批次状态

| 状态 | 页面文案 | 含义 |
|---|---|---|
| `running` | 执行中 | 正在逐笔向银联查询 |
| `completed` | 已完成 | 批次结束，所有订单均完成查询；仍可能存在状态或金额异常 |
| `partial` | 部分订单查询失败 | 批次结束，但至少一笔订单没有取得有效查询结果 |
| `failed` | 执行失败 | 批次级流程未能完成 |

“已完成”只代表任务完成，不代表所有订单都一致。

#### 1.5.6 对账结果与处理状态

| 结果 `result` | 页面文案 | 处理状态 | 含义 |
|---|---|---|---|
| `matched` | 一致 | `none` / 无需处理 | 状态和金额一致 |
| `anomaly` | 状态异常 | `open` / 待处理 | 状态不一致或金额不一致 |
| `error` | 查询失败 | `open` / 待处理 | 查询失败或结果不可验证 |
| `corrected` | 已人工修复 | `manually_resolved` / 已人工处理 | 管理员复核后按银联可信结果完成修复 |
| 历史兼容 | — | `auto_resolved` / 历史自动修复 | 仅用于兼容历史数据，新流程不自动修复异常 |

### 1.6 数据来源与依赖

| 功能数据 | 主要来源 | 更新时机 |
|---|---|---|
| 支付价格与开关 | `PaymentConfig` | 管理员保存策略时更新；前台下次打开弹窗时读取 |
| 支付订单 | `PaymentOrder` | 创建订单、查询、通知、关单、退款时更新 |
| 退款记录 | `PaymentRefund` | 管理员发起退款、异步通知或主动查询时更新 |
| 银联通知审计 | `PaymentNotification` | 银联回调到达时先落库，再记录处理结果 |
| 会员权益 | `UserMembership` | 支付成功、退款成功、权益自然到期时更新 |
| 对账批次 | `PaymentReconciliationRun` | 定时对账或管理员立即对账时创建/重算 |
| 对账明细 | `PaymentReconciliationItem` | 每笔订单核对、人工复核或标记处理时更新 |
| 银联实时状态 | 银联商务查询接口 | 前台轮询、后台补偿、退款查询、对账和人工复核时读取 |

关键外部依赖：银联测试或生产参数有效、支付渠道权限已开通、银联接口可访问、支付结果通知地址可被公网访问。

### 1.7 功能验收前提

1. 测试环境使用银联测试 AppId、AppKey、MID、TID 和来源编号。
2. 正式商户测试必须使用生产参数、正式商户支付权限和生产接口地址。
3. 后端支付开关已启用，管理员支付策略状态为“开放支付”。
4. 至少有一个可登录学生账号和一个管理员账号。
5. 测试账号对应的支付宝、微信或云闪付可以扫码。
6. 测试人员能同时查看用户端、管理员后台和服务端日志或数据库结果。

## 2. 页面描述

### 2.1 首页会员卡片

入口：用户访问首页会员方案区域。

页面行为：

- 免费用户卡片提供“继续试用”。
- 会员用户卡片提供“升级会员”。
- 会员卡片价格读取后台“正常月价格”，不是首次月付价格。
- 支付策略为暂停时，按钮显示“暂未开放”并不可点击。
- 点击“升级会员”打开支付弹窗。

验收重点：管理员修改正常月价并保存后，重新进入或刷新首页，会员卡片应显示新价格；旧支付订单金额不应变化。

### 2.2 支付弹窗

#### 2.2.1 默认状态

- 默认考试类型：TMUA。
- 可选考试类型：TMUA、ESAT。
- STEP 在学生购买流程中不可用；即使绕过前端提交，后端也会拒绝。
- 默认套餐：月度套餐。
- 默认支付方式：支付宝。
- 打开弹窗时重新读取最新支付策略和通道可用状态。
- 尚未生成订单时只展示预计金额，不存在可支付二维码。

#### 2.2.2 可操作内容

| 区域 | 内容 | 行为 |
|---|---|---|
| 备考类型 | TMUA、ESAT 多选 | 至少选择一项；多选不会按考试类型数量叠加价格 |
| 订阅计划 | 月度、年度 | 月度根据用户历史决定首次价或正常价；年度使用年价 |
| 会员权益 | 练习题、真题、报告、诊断等权益说明 | 当前为说明信息，不直接决定后端权限数值 |
| 待支付金额 | 当前预计金额或创建后的订单金额 | 创建订单后以服务端返回金额为准 |
| 二维码区 | 生成订单按钮、二维码、成功或失败提示 | 通道未配置或支付暂停时不能生成 |
| 支付方式 | 支付宝、微信、云闪付 | 用于用户引导及订单渠道记录 |
| 关闭按钮/遮罩/Esc | 关闭弹窗 | 若当前存在待支付订单，会尝试关闭银联二维码 |

#### 2.2.3 生成订单后的页面节奏

1. “生成支付订单”进入加载状态，防止重复点击。
2. 后端创建订单并返回银联收银台 URL。
3. 前端把 URL 生成二维码图片。
4. 页面每 3 秒主动查询一次订单状态。
5. 支付成功后停止轮询，展示“支付成功，会员权益已生效”。
6. 已关闭、失败或已退款时停止轮询，提示重新生成订单。
7. 如果二维码图片生成失败，保留“点击打开银联收银台”的兜底链接。

### 2.3 个人中心——支付记录

入口：已登录用户进入个人中心的“支付记录”。

页面只展示当前用户最近 50 笔支付订单，按创建时间倒序排列。

#### 2.3.1 汇总指标

| 指标 | 计算规则 |
|---|---|
| 累计订单 | 当前加载的全部支付订单数量 |
| 支付成功 | 状态为已支付或退款中的订单数量，不含已退款订单 |
| 累计实付 | 已支付和退款中订单的金额合计，不含已退款订单 |

#### 2.3.2 筛选规则

| 筛选项 | 包含状态 |
|---|---|
| 全部订单 | 全部状态 |
| 待支付 | `pending` |
| 已支付 | `paid` |
| 已关闭 | `closed`、`failed` |
| 退款 | `refunding`、`refunded` |

#### 2.3.3 每条记录展示

- 订单标题：考试类型 + 套餐类型。
- 订单号。
- 考试类型。
- 月度、月度首月优惠或年度套餐。
- 支付金额与币种。
- 支付方式。
- 创建时间。
- 支付时间；未支付时显示“-”。
- 当前订单状态。

加载失败时仅支付记录区域显示失败文案和“重新加载”，不应阻断个人中心其他资料。

### 2.4 管理后台——支付运营与对账

入口：管理员进入后台“支付运营与对账”页面。该页面展示全站数据，不仅是当前管理员自己的订单。

#### 2.4.1 会员定价策略

| 字段 | 含义 | 校验 |
|---|---|---|
| 首次按月付费价格 | 符合首次月付条件的用户购买月度会员时使用 | 最低 ¥0.01，不能高于正常月价 |
| 正常月价格 | 非首次月付订单的价格 | 最低 ¥0.01 |
| 年价格 | 年度套餐一次性支付总价 | 最低 ¥0.01 |
| 开放支付/暂停支付 | 控制是否允许创建新订单 | 暂停后旧订单和历史记录仍保留 |

交互规则：

- 默认是查看状态，金额和开关不可编辑。
- 点击“编辑”后才可修改，显示“取消”和“保存”。
- 点击“取消”恢复上次保存值。
- 点击“保存”校验并持久化；成功后退出编辑状态。
- 保存只影响之后创建的新订单，不修改已创建订单的金额。

#### 2.4.2 每日交易对账摘要

| 指标 | 含义 |
|---|---|
| 最近对账日期 | 数据库中业务日期最新的对账批次 |
| 批次状态 | 执行中、已完成、部分查询失败或执行失败 |
| 核对 | 最近批次纳入核对的订单数 |
| 人工修复 | 最近批次中经管理员复核后安全修复的订单数 |
| 待处理异常 | 所有对账批次中仍为 `open` 的明细数量 |
| 通知失败 | 银联异步通知处理状态为失败的记录数 |
| 卡住退款 | 退款状态为处理中且超过 30 分钟未更新的记录数 |
| 超时待支付 | 已过有效期但本地仍为待支付的订单数 |

“通知失败 / 卡住退款 / 超时待支付”当前是后台观察指标，不会向管理员发送邮件或短信。

#### 2.4.3 “立即对账”与“刷新”的区别

| 操作 | 是否查询银联 | 是否生成/重算对账结果 | 是否修改订单、退款或会员 |
|---|---:|---:|---:|
| 立即对账 | 是 | 是 | 否 |
| 刷新 | 否 | 否，只读取已有数据 | 否 |
| 复核并修复 | 是 | 更新单笔结果 | 可能修改，必须管理员确认且金额一致 |
| 标记已处理 | 否 | 更新处理状态和说明 | 否 |

立即对账前需要选择业务日期并二次确认。不能选择未来日期。同一日期正在执行时，重复触发应被拒绝。

#### 2.4.4 对账明细与异常告警

列表字段：

| 字段 | 含义 |
|---|---|
| 对账日期 | 该明细所属批次的业务日期 |
| 订单与用户 | 订单号、用户名和邮箱 |
| 本地 / 银联 | 本地订单状态与银联查询状态的并列结果 |
| 金额 | 本地订单金额与银联订单金额；单位统一转换为元展示 |
| 结果 | 一致、状态异常、查询失败或已人工修复 |
| 说明 | 金额差异、状态差异、查询错误或复核结果 |
| 操作 | 待处理异常可以“复核并修复”或“标记已处理” |

筛选项：待处理异常、全部对账结果、已人工处理。

“复核并修复”的业务含义：

1. 管理员二次确认。
2. 系统重新查询银联。
3. 银联金额必须与本地订单金额一致。
4. 银联为已支付且本地为待支付、失败或已关闭时，可以补记支付成功并发放权益。
5. 银联为已关闭且本地为待支付或失败时，可以收敛为已关闭。
6. 银联为已退款且本地为退款中时，可以确认退款并回收权益。
7. 查询后仍不满足安全修复条件时，异常继续保持待处理。
8. 系统不提供管理员直接手输“已支付”的能力。

“标记已处理”的业务含义：

1. 适用于已通过银联后台、财务凭证或客户材料完成线下核实的情况。
2. 管理员必须填写 2～500 个字符的处理说明。
3. 只把告警标记为已人工处理，不修改支付订单、退款或会员状态。
4. 处理人、处理时间和说明进入审计记录。

#### 2.4.5 全站支付订单

列表默认按创建时间倒序，支持分页。

搜索范围：

- 系统订单号。
- 银联/渠道流水号。
- 用户名。
- 用户邮箱。

状态筛选：待支付、已支付、失败、已关闭、退款中、已退款。

每条记录显示：订单号、用户、套餐、考试类型、金额、渠道、状态、创建时间和操作。

可用操作：

- 所有订单均可“查看详情”。
- 只有已支付订单显示“全额退款”。
- 退款中订单显示“查询退款”。
- 已退款订单只显示“已退款”。
- 列表“刷新”只重新读取订单数据，不请求银联。

#### 2.4.6 订单详情

点击“查看详情”打开右侧抽屉。详情用于客服、财务、测试和管理员还原一笔交易的全过程。

##### A. 订单与用户

| 字段 | 含义 |
|---|---|
| 当前状态 | 订单本地业务状态 |
| 订单号 | 系统与银联共同使用的账单号 |
| 用户 | 用户名和邮箱 |
| 套餐 | 月度/首次月度/年度及考试类型 |
| 金额 | 原订单金额和累计已退金额 |
| 创建时间 | 本地订单生成时间 |
| 支付时间 | 银联确认的支付时间；未支付时为空 |
| 过期时间 | 二维码有效期截止时间 |
| 关闭时间 | 订单被关闭的时间；未关闭时为空 |

##### B. 银联商务标识

| 字段 | 用途 |
|---|---|
| 环境 | 判断当前记录使用测试参数还是生产参数 |
| AppId | 定位开发者应用，只显示脱敏值 |
| MID / TID | 定位商户和终端 |
| 机构商户号 | 当前银联业务类型参数 `instMid` |
| 渠道流水号 | 支付成功后用于银联或渠道排查 |
| 账单日期 | 查询、退款时定位原账单 |
| 二维码 ID | 定位或关闭二维码 |
| 系统 ID | 银联二维码相关系统标识 |

AppKey、通讯密钥和完整签名不会返回管理前端。

##### C. 支付处理时间线

时间线按发生时间倒序汇总：

- 支付订单创建。
- 银联二维码生成。
- 银联确认支付成功。
- 支付订单关闭或处理失败。
- 异步通知处理成功或失败。
- 管理员发起退款及退款最终结果。
- 关联会员权益开始、到期或取消。
- 对账一致、发现异常、查询失败或管理员修复。
- 管理员操作人信息。

其中会员权益时间线标记为“关联权益快照”，表示它是按用户和考试类型关联推断的记录，不是严格的订单外键审计凭证。

##### D. 关联会员权益

展示考试类型、套餐、会员状态和有效期。

当前关联规则是“同一用户 + 订单所含考试类型”，因此可能展示该用户在相同考试类型下的多段会员记录。测试和人工排查不能仅凭此区域认定某条权益一定由当前订单创建，还需要结合时间线、支付时间和退款记录判断。

##### E. 审计原始记录

1. **银联响应摘要**（对应响应已写入订单时可能出现）
   - 二维码生成。
   - 支付确认。
   - 主动查询。
   - 用户关单。
   - 系统过期关单。
   - 二维码生成失败。

2. **异步通知**
   - 通知唯一编号。
   - 是否验签通过。
   - 处理状态和失败原因。
   - 已脱敏的通知内容。

3. **退款记录**
   - 退款单号、金额、状态。
   - 发起管理员、退款原因。
   - 银联退款结果摘要。

4. **对账记录**
   - 对账日期、核对结果和处理状态。
   - 差异说明。
   - 管理员处理说明。

敏感付款人信息、银行卡信息、手机号、证件号和签名在入库或展示前会被脱敏。

### 2.5 页面可见性与反馈

- 未登录用户创建订单时应进入统一登录处理，不得生成匿名支付订单。
- 学生不能访问管理后台支付接口。
- 管理员页面加载失败时不得展示伪造的空数据。
- 创建订单、退款、立即对账和复核期间，相应按钮进入加载状态，避免重复提交。
- 空订单、空通知、空退款和空对账记录应显示明确空态，不应报错。
- 所有时间在页面统一格式化展示；对账业务日期固定为中国自然日。

## 3. 核心流程

### 3.1 管理员配置价格

```text
管理员进入支付后台
  → 读取当前支付策略
  → 点击“编辑”
  → 修改价格或支付开关
  → 前后端校验
  → 保存 PaymentConfig
  → 前台下次打开支付弹窗时读取新策略
```

规则：

1. 价格以元输入，以整数分保存。
2. 后台页面允许的价格范围为 ¥0.01～¥100,000.00。
3. 首次月价不能高于正常月价。
4. “取消”不保存草稿。
5. 暂停支付只禁止创建新订单，不删除历史订单，也不撤销已生效会员。

### 3.2 创建支付订单

触发：已登录用户在支付弹窗点击“生成支付订单”。

处理顺序：

1. 校验至少选择一个考试类型。
2. 校验考试类型只包含当前系统支持值，且学生端只允许 TMUA、ESAT。
3. 校验套餐为月度或年度。
4. 校验渠道为支付宝、微信或云闪付。
5. 校验支付策略处于开放状态、银联参数已启用。
6. 后端重新读取价格，前端提交的金额不参与计算。
7. 生成全局唯一订单号和默认 15 分钟过期时间。
8. 先创建本地待支付订单。
9. 调用银联二维码获取接口。
10. 保存账单日期、二维码 URL、二维码 ID 和系统 ID。
11. 把订单与二维码返回前端。

#### 3.2.1 首次月付价格判定

月度订单创建时，系统查询该用户是否存在状态为“已支付”或“退款中”的历史月度订单：

- 不存在：使用首次按月付费价格，订单 `priceType=first_monthly`。
- 存在：使用正常月价格，订单 `priceType=monthly`。
- 已完全退款的月度订单不计入上述判断，因此用户可能重新获得首次月付价格。
- 待支付、失败和已关闭订单不消耗首次月付资格。

年度订单始终使用年价格，`priceType=yearly`。

#### 3.2.2 多考试类型规则

一笔订单可同时选择 TMUA 和 ESAT：

- 订单金额仍为所选套餐的一份价格，不按考试类型数量相乘。
- 支付成功后分别发放 TMUA 和 ESAT 的会员权益。
- 退款成功后分别回收该订单对应套餐时长。

### 3.3 扫码支付与支付确认

```text
用户扫码
  → 支付宝/微信/云闪付完成付款
  → 银联更新账单状态
  → 路径 A：银联异步通知系统
  → 路径 B：前台每 3 秒主动查询
  → 路径 C：后台生命周期任务补偿查询
  → 后端向银联主动查询最终状态
  → 校验商户、状态和金额
  → 订单变为已支付
  → 创建或延长会员权益
  → 用户端刷新会员上下文
```

支付成功必须同时满足：

1. 银联接口响应成功。
2. 银联账单状态为已支付。
3. 银联支付流水为成功状态。
4. 银联金额是整数分，并与本地订单金额完全一致。
5. 本地订单存在且未被重复履约。

浏览器回跳、二维码页面显示“成功”、用户截图或前端自行修改状态，均不能作为发放权益的依据。

### 3.4 异步通知处理

1. 银联通知到达后，系统先按通知 ID 或报文摘要幂等落库。
2. 校验通知签名。
3. 校验 MID、TID、`instMid` 与当前系统配置一致。
4. 校验订单号存在。
5. 再主动查询银联确认支付或退款最终结果。
6. 成功后记录通知为“处理成功”并返回 `SUCCESS`。
7. 失败时记录失败原因并返回 `FAILED`，便于银联后续重试。
8. 重复通知更新同一条审计记录，不重复发放会员或重复退款。

### 3.5 会员权益发放与续费

支付确认后，对订单中每个考试类型分别处理：

- 用户已有未到期的生效会员：从现有结束时间继续增加一个自然月或一个自然年。
- 用户没有生效会员：从当前时间开始创建一个自然月或一个自然年会员。
- 用户旧版付款状态同步为已支付。

续费不是自动扣款。当前系统没有周期性自动续费，每次续费都需要用户重新创建订单并扫码付款。

### 3.6 订单查询、关闭与过期

#### 3.6.1 前台查询

- 二维码生成后每 3 秒查询一次。
- 主动查询结果可能触发支付履约或订单关闭。
- 查询失败不会立即把订单改为失败；前台继续保留当前状态，后台任务可再次查询。

#### 3.6.2 用户关闭弹窗

- 如果订单仍为待支付，系统先查询银联，防止付款成功但通知尚未到达时误关单。
- 如果银联已经支付，按已支付处理并发放权益。
- 如果仍未支付，调用银联关闭二维码，订单变为已关闭。
- 如果关单请求失败，订单保留，交由过期任务后续处理。

#### 3.6.3 后台生命周期任务

测试和生产环境默认启用，默认每 60 秒运行一次：

1. 查询创建超过 30 秒且仍未过期的待支付订单。
2. 对已经过期的待支付订单先查询，再关闭二维码。
3. 查询超过 30 秒仍处于退款中的退款单。
4. 把已经到期的会员状态改为已到期。
5. 在配置时间后执行前一自然日的逐单对账。

这些属于正常状态收敛，不等同于对账异常的自动修复。对账发现的状态或金额异常仍必须由管理员处理。

### 3.7 管理员全额退款

前置条件：订单状态必须为已支付。

流程：

1. 管理员点击“全额退款”。
2. 页面显示退款金额和权益回收提示。
3. 管理员填写 2～255 个字符的退款原因并确认。
4. 系统检查订单是否可退、是否已有有效退款单。
5. 如果该用户在原订单之后还有新的已支付或退款中订单，系统阻止自动退款，要求先人工确认权益关系。
6. 系统创建唯一退款单，订单变为退款中。
7. 调用银联全额退款。
8. 银联立即确认成功时，订单变为已退款并回收权益。
9. 银联尚未返回最终结果时，保留退款中；管理员和后台任务可继续查询。
10. 银联返回明确失败时，退款单变为失败，原支付订单恢复为已支付。

#### 3.7.1 权益回收规则

退款成功后，对订单涉及的每个考试类型，从当前最新生效会员中扣回该订单套餐时长：

- 月度订单扣回一个自然月。
- 年度订单扣回一个自然年。
- 扣回后仍有剩余有效期：缩短结束时间，会员继续生效。
- 扣回后不再有有效时长：会员改为已取消，结束时间记为退款时间。
- 用户没有其他已支付或退款中的订单时，旧版付款状态恢复为免费。

当前只支持全额退款，不支持部分退款、按考试类型拆分退款或只回收部分权益。

### 3.8 每日交易对账

#### 3.8.1 当前对账范围

选择某个中国自然日后，系统查找以下本地订单：

- 当日创建的订单。
- 当日支付成功的订单。
- 当日退款成功的订单。

随后逐笔调用银联账单查询接口，比较：

1. 本地订单状态。
2. 银联账单状态。
3. 本地订单金额。
4. 银联订单金额。

当前对账的权威边界是“本地订单集合”。因此可以发现本地已有订单的状态或金额差异，但不能发现银联存在而本地完全不存在的交易。后者需要后续接入银联全量账单。

#### 3.8.2 定时对账

- 默认在中国时区每天 02:00 之后核对前一个完整自然日。
- 同一日期已完成或部分完成后，定时任务不会重复执行。
- 定时对账只记录一致、异常或查询失败，不修改订单、退款或会员。

#### 3.8.3 立即对账

- 管理员可以选择今天或历史日期执行，不能选择未来日期。
- 同一日期只保留一个对账批次。
- 再次执行同一日期时会删除并重算该批次明细，不新增第二个版本。
- 立即对账只发现差异，不做自动修复。

#### 3.8.4 对账匹配规则

| 银联状态 | 可视为一致的本地状态 |
|---|---|
| `PAID` | 已支付、退款中 |
| `REFUND` | 已退款 |
| `CLOSED` | 已关闭 |
| `UNPAID` | 待支付 |

金额必须完全相等。即使状态相符，只要金额不一致，仍然是待处理异常。

### 3.9 订单详情与审计还原

订单详情不是一个可编辑表单，而是交易排查入口。管理员应按照以下顺序核查：

1. 先核对订单号、用户、套餐、金额和当前状态。
2. 核对环境、MID、TID、账单日期和渠道流水号。
3. 查看时间线确认订单创建、支付、通知、权益和退款发生顺序。
4. 查看异步通知是否验签通过、是否处理成功。
5. 查看银联响应摘要中的最终账单状态和金额。
6. 查看退款记录的退款单号、管理员和结果。
7. 查看对账记录是否有未处理异常或人工说明。
8. 会员权益仅作为关联快照，必要时结合用户会员记录进一步核实。

### 3.10 状态变化验收矩阵

| 初始状态 | 触发动作 | 关键条件 | 结果状态 | 业务影响 |
|---|---|---|---|---|
| 无订单 | 生成支付订单 | 策略开放、参数完整、输入有效 | 待支付 | 产生唯一订单和二维码 |
| 待支付 | 银联确认支付 | 金额一致、交易成功 | 已支付 | 创建或延长会员 |
| 待支付 | 用户关闭弹窗 | 银联仍未支付、关码成功 | 已关闭 | 不发放会员 |
| 待支付 | 到达过期时间 | 银联仍未支付 | 已关闭 | 二维码失效 |
| 待支付/失败/已关闭 | 管理员复核 | 银联为已支付且金额一致 | 已支付 | 补记支付并发放会员 |
| 已支付 | 发起全额退款 | 无后续订单冲突 | 退款中 | 创建退款单 |
| 退款中 | 银联确认退款 | 退款金额一致 | 已退款 | 回收会员时长 |
| 退款中 | 银联明确失败 | 明确失败而非网络未知 | 已支付 | 保留会员权益 |
| 退款中 | 管理员复核 | 银联为已退款且金额一致 | 已退款 | 完成退款和权益回收 |
| 任意异常 | 标记已处理 | 管理员填写说明 | 订单状态不变 | 告警关闭并保留审计 |

### 3.11 核心测试场景

1. **首次月付**：新用户创建月度订单，金额应等于首次月价，支付成功后对应考试会员生效。
2. **再次月付**：存在已支付月度订单的用户再次购买，金额应等于正常月价。
3. **年度购买**：订单金额等于年价，支付成功后会员结束时间增加一个自然年。
4. **多考试购买**：同时选择 TMUA 和 ESAT，金额不翻倍，两类会员均生效。
5. **重复通知**：同一银联通知重复发送，只产生一次有效履约。
6. **关闭竞态**：用户支付后立即关闭弹窗，系统应先查询银联，不能把已支付订单误关。
7. **全额退款**：退款成功后订单为已退款、退款记录成功、会员时长被回收。
8. **后续订单保护**：用户存在更新的已支付订单时，旧订单退款应被阻止并提示人工确认。
9. **立即对账**：产生对账结果，但不自动修改异常订单和会员。
10. **刷新对账**：不产生新批次、不请求银联，只更新页面已有数据。
11. **复核并修复**：模拟本地待支付、银联已支付且金额一致，管理员确认后订单和会员被修复。
12. **金额异常保护**：银联金额与本地金额不同，复核后仍不得发放权益。
13. **标记已处理**：填写处理说明后告警关闭，但订单、退款和会员保持不变。
14. **详情审计**：支付并退款的订单应能看到创建、二维码、支付、通知、权益、退款和对账记录。

## 4. 异常容错

### 4.1 输入与业务校验异常

| 异常 | 系统行为 | 用户/管理员可见结果 |
|---|---|---|
| 未选择考试类型 | 阻止创建订单 | 提示至少选择一个备考类型 |
| 选择 STEP | 后端拒绝 | 提示 STEP 暂不支持购买 |
| 套餐或渠道非法 | 后端拒绝 | 提示选择有效套餐或支付方式 |
| 支付策略暂停 | 不创建订单 | 首页显示暂未开放，接口返回支付未开放 |
| 银联参数未配置 | 不创建订单 | 二维码区显示待配置支付参数 |
| 首次月价高于正常月价 | 不保存策略 | 管理员收到校验提示 |
| 退款原因过短或过长 | 不创建退款单 | 提示原因长度要求 |
| 对账日期格式错误或为未来日期 | 不执行批次 | 显示日期错误提示 |

### 4.2 银联接口与网络异常

#### 创建二维码失败

- 本地订单标记为失败。
- 保存失败码、失败说明和脱敏银联响应摘要。
- 用户重新操作时创建新订单，不能复用失败订单号。

#### 支付查询超时

- 不把未知状态直接改为失败。
- 保留本地原状态。
- 前台后续轮询或后台生命周期任务再次查询。

#### 二维码图片生成失败

- 银联订单可能已经创建成功，因此不能删除本地订单。
- 页面提供直接打开银联收银台链接。

#### 关单失败

- 保留订单和错误日志。
- 后台过期任务后续重新查询并关闭。

### 4.3 通知异常

| 异常 | 处理 |
|---|---|
| 验签失败 | 记录失败，不更新订单或权益，向银联返回 `FAILED` |
| MID/TID/业务类型不匹配 | 记录失败，不处理订单 |
| 缺少订单号 | 记录失败 |
| 本地订单不存在 | 记录失败，进入后台通知失败指标 |
| 金额不一致 | 拒绝履约，保留异常证据 |
| 重复通知 | 更新同一通知审计记录，不重复履约 |

### 4.4 并发与时序异常

- 前台创建订单按钮加载期间不可重复点击。
- 支付通知和主动查询同时到达时，最终状态保护避免重复发放权益。
- 已支付、退款中和已退款状态不能被旧查询覆盖为待支付或已关闭。
- 关单前必须先查询，支付成功优先于关单。
- 同一订单已有处理中的退款单时，重复退款请求复用现有结果，不新建第二笔有效退款。
- 多个 API 实例通过数据库租约避免同时执行同一轮生命周期任务。
- 同一日期对账正在执行时，第二次执行应提示“正在执行”。

### 4.5 退款异常

| 异常 | 结果 |
|---|---|
| 非已支付订单发起退款 | 拒绝 |
| 已经全额退款 | 返回已有成功退款，不重复退款 |
| 已有处理中退款 | 查询并返回现有退款结果 |
| 存在后续有效支付订单 | 阻止自动退款，要求人工确认权益关系 |
| 银联返回明确退款失败 | 退款单为失败，订单恢复已支付 |
| 银联请求超时或网络中断 | 保持退款中，后续主动查询，避免把未知结果误判失败 |
| 银联退款金额不一致 | 不确认退款成功，不回收权益 |

### 4.6 对账异常

| 异常 | 系统行为 | 管理员操作 |
|---|---|---|
| 状态不一致 | 生成待处理异常 | 复核并修复，或线下核实后标记已处理 |
| 金额不一致 | 生成待处理异常 | 不允许自动修复；必须人工核查 |
| 查询超时或失败 | 生成查询失败明细 | 稍后复核重试 |
| 返回缺少金额 | 生成查询失败明细 | 人工核查银联记录 |
| 再次查询仍不一致 | 保持待处理 | 不修改业务状态 |
| 管理员标记已处理 | 记录说明和操作人 | 业务状态不变 |

### 4.7 权限与安全边界

1. 支付金额只能由后端计算。
2. 用户只能查询和关闭自己的订单。
3. 管理员接口同时校验登录态与管理员角色。
4. 银联通知不依赖用户登录，但必须验签和校验商户参数。
5. AppKey、通讯密钥、完整签名不进入前端响应。
6. 通知中的付款人敏感字段在保存或展示前脱敏。
7. 订单详情中的银联响应只展示经过筛选的摘要。
8. 管理员不能直接录入“已支付”或任意金额执行补偿。

### 4.8 异常验收点

1. 修改前端金额或直接提交金额字段，最终订单金额仍应以后台策略为准。
2. 构造错误签名通知，订单和权益不得变化，后台应记录通知失败。
3. 快速重复点击生成订单，单次加载周期内不得产生重复请求。
4. 模拟银联查询超时，本地订单不得被误改为失败或已支付。
5. 对金额不一致的订单执行“复核并修复”，业务状态不得变化。
6. 非管理员调用退款或对账接口应返回权限错误。
7. 退款请求超时后订单应保持退款中，后续查询成功后才能转为已退款。
8. 关闭支付策略后，历史已支付订单、会员和退款记录应保持不变。

## 5. 后续与非目标说明

### 5.1 当前已具备的完整业务闭环

当前系统已经形成以下闭环：

```text
后台定价
  → 用户选择套餐
  → 创建银联二维码
  → 用户真实付款
  → 通知/查询确认
  → 会员履约
  → 用户与管理员查询订单
  → 管理员全额退款
  → 权益回收
  → 本地订单逐笔银联核对
  → 管理员人工处置异常
  → 订单详情审计还原
```

### 5.2 当前明确不包含

以下功能不是当前版本承诺：

1. 银联全量账单下载、逐日账单导入和双向勾兑。
2. 发现“银联有交易、本地无订单”的账单级异常。
3. 邮件、短信、企业微信或钉钉异常告警。
4. 部分退款、按考试类型拆分退款、退款金额编辑。
5. 用户自助申请退款和退款审批流。
6. 自动续费、协议扣款、免密支付。
7. 优惠券、折扣码、促销叠加和活动价有效期。
8. 发票、结算单、手续费和财务会计凭证。
9. 拒付、争议、风控审核和黑名单。
10. 多币种、跨境支付和分账。
11. 支付数据导出及自定义财务报表。

### 5.3 当前实现的已知边界

这些边界需要产品经理和测试明确知晓：

1. **对账不是全量账单对账**：当前只核对本地已有订单，无法发现银联侧单边交易。
2. **渠道字段是用户选择值**：聚合二维码使用多钱包模式，订单中的支付宝/微信/云闪付来自生成订单时的选择；如果用户改用另一钱包扫码，当前字段未根据银联实际渠道自动纠正。
3. **生成订单后切换渠道不会重建订单**：订单渠道仍以创建时选择为准；测试应在生成订单前选定并使用相同钱包。
4. **月度弹窗金额在创建前是预计值**：重复购买用户在订单创建前可能仍看到首次优惠提示；订单创建后以后端判定的正常月价为准。
5. **会员与订单不是精确外键关联**：详情中的权益按用户和考试类型关联，页面已明确标记为快照，不能单独作为严格归因凭证。
6. **同日对账重跑不保留版本**：同一日期只保留一个批次，重跑会重算并替换明细。
7. **个人支付记录最多读取最近 50 笔**：当前没有个人支付记录服务端分页。
8. **年度价格是一次性总价**：产品语义不是月单价；如果界面仍在年度价格旁显示“/月”，应作为展示缺陷记录。
9. **价格上限存在前后端差异**：后台页面上限为 ¥100,000.00，服务端当前防御性硬上限为 ¥1,000,000.00；正常业务验收以后台页面范围为准，正式开放前建议统一约束。
10. **异常指标只在后台可见**：当前没有外部通知和值班升级机制。
11. **渠道中文文案尚未完全统一**：支付弹窗和管理员后台把 `unionpay` 显示为“云闪付”，个人中心当前显示为“银联支付”，两者指向同一内部渠道值。
12. **月末与闰日续费规则尚未单独产品化**：当前按运行环境的日历月/日历年顺延；月末不存在同日或闰日跨年时需要专项验收，并在正式开放前确认期望日期。

### 5.4 建议后续优先级

#### 上线后优先补充

1. 银联全量账单获取、双向匹配和差异归档。
2. 待处理异常、通知失败和长时间退款的外部告警。
3. 支付订单与会员权益的精确来源订单关联。
4. 以银联实际支付渠道回写订单渠道。
5. 对账批次版本化，保留每次重跑历史。

#### 产品扩展阶段

1. 用户退款申请与管理员审批。
2. 部分退款及多权益拆分退款。
3. 优惠券和限时价格策略。
4. 财务报表、手续费、结算状态和数据导出。
5. 自动续费和订阅取消管理。

### 5.5 上线验收结论标准

在面向真实用户开放支付前，至少需要满足：

1. 正式商户支付宝、微信或云闪付通道已按产品范围开通。
2. 生产 AppId、AppKey、MID、TID、来源编号和通讯密钥配置正确。
3. HTTPS 支付通知地址可以被银联公网访问。
4. 使用正式商户完成至少一笔受控小额支付、查询、权益发放和全额退款。
5. 管理后台能完整查看该笔交易的通知、退款、权益和时间线。
6. 对该交易执行立即对账时结果一致；刷新不会产生新对账。
7. 已验证重复通知、金额不一致、退款超时和异常人工处理等保护场景。
8. 全量账单对账尚未上线期间，运营和财务已约定人工核查频率与责任人。
