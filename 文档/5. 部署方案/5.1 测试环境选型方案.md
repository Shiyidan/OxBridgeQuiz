# QuizTestDemo 阿里云部署方案

> 适用环境：开发测试环境 | 团队：4人 | 目标：长期开发迭代

---

## 一、总体架构

```
公网用户
  │
  │ HTTP 80（当前公网 IP 访问）
  ▼
Nginx
  ├── /                 → /opt/quiz/web/dist        Vue SPA 静态资源
  ├── /api/             → 127.0.0.1:3001            Express API
  └── /uploads/         → /opt/quiz/uploads         上传文件目录

PM2
  └── quiz-api          → /opt/quiz/api/dist/index.js

SQLite
  └── /opt/quiz/data/prod.db

Git 仓库
  └── /opt/quiz/repo    → api/ + quiz-web/
```

**核心原则**：公网只开放 `22`、`80`、`443`；业务访问统一经 Nginx 进入，API 不通过安全组直接对外暴露。

## 二、需要购买的产品清单

### 2.1 当前上线所需产品

| 状态 | 产品 | 规格/说明 | 参考费用 | 用途 |
|------|------|----------|:------:|------|
| [x] | **ECS 云服务器** | 经济型 e 2核4G + ESSD Entry 40G + 100Mbps 按流量 | 按量计费 | 核心计算资源，当前已部署 |
| [ ] | **域名** | `.com` / `.cn`，在阿里云万网购买 | ~60元/年 | 正式对外访问地址，ICP备案和 HTTPS 前置条件 |
| [ ] | **SSL 证书** | 阿里云免费 DV 证书或 Let's Encrypt | 0元 | HTTPS 加密，需先有域名 |

> **ECS 选购细节**：
> - 系统镜像选 **Ubuntu 22.04 LTS**（Node.js 生态兼容性最好）
> - 地区选离团队最近的 Region（如华东2-上海）
> - 当前已购实例为 2核4G、ESSD Entry 40G、100Mbps 按流量

如果不买域名，只能用 `http://公网IP` 访问，无法申请 SSL 证书（Let's Encrypt 和阿里云免费证书都需要域名），密码等敏感数据在 HTTP 明文传输存在严重安全隐患。

### 2.2 本期不买（后续迭代按需追加）

| 状态 | 产品 | 当前替代方案 | 何时加 |
|------|------|------------|--------|
| [ ] | RDS PostgreSQL | SQLite 单机文件库 | 用户量增大、需要更强并发/备份/迁移能力时 |
| [ ] | OSS 对象存储 | ECS 本地磁盘 `/uploads` | 文件量超过 20G 或需要 CDN 时 |
| [ ] | Redis 云服务 | 暂不使用 | 需要队列、缓存、限流或多实例共享状态时 |
| [ ] | SLB 负载均衡 | Nginx 单节点 | 需要高可用/多节点时 |
| [ ] | NAT 网关 | ECS 自带公网 IP | 需要统一出口 IP 时 |

## 三、服务器环境搭建

本节保留部署动作清单，具体命令在实际操作时逐步执行，避免方案文档堆叠过多脚本。

### 3.1 安全组配置（阿里云控制台 → ECS → 安全组）

| 方向 | 端口 | 来源 | 说明 |
|------|:---:|------|------|
| 入方向 | `22` | 公司出口 IP（或临时 0.0.0.0/0） | SSH 远程管理 |
| 入方向 | `80` | 0.0.0.0/0 | HTTP |
| 入方向 | `443` | 0.0.0.0/0 | HTTPS |
| 入方向 | `3001` | **删除/不开放** | API 直连端口，仅通过 Nginx 反向代理访问 |
| 入方向 | `5432` | **删除/不开放** | 当前不使用 PostgreSQL |
| 入方向 | `6379` | **删除/不开放** | 当前不使用 Redis |

> **原则：最小暴露面。** 除了 22/80/443 之外一律不对公网开放。

### 3.2 初始化动作

- SSH 登录 ECS，创建 `deploy` 用户，并配置 SSH 密钥。
- 执行系统更新，安装 `curl`、`wget`、`git`、`build-essential`、`ufw`、`nginx`。
- 安装 Node.js 20。
- 安装 PM2，用于管理后端 Node.js 进程。
- UFW 只开放 `22`、`80`、`443`。

### 3.3 当前不安装的服务

- **Redis**：当前项目没有 Redis 调用，上线初期不是必需项。
- **PostgreSQL**：当前 Prisma datasource 仍是 SQLite，不能只改 `.env` 直接切库。

## 四、应用部署

### 4.1 目录规划

```
/opt/quiz/
├── repo/                # Git 仓库
├── api/                 # 后端运行目录
│   ├── dist/
│   ├── node_modules/
│   ├── package.json
│   └── .env             # 生产环境变量（不要提交到 Git）
├── web/
│   └── dist/            # 前端构建产物
├── data/
│   └── prod.db          # SQLite 生产库
├── uploads/             # 上传文件存储
├── scripts/
└── backups/
```

### 4.2 首次部署步骤

- 使用 `deploy` 用户克隆代码到 `/opt/quiz/repo`。
- 后端进入 `/opt/quiz/repo/api`，安装依赖、执行 Prisma migration、生成 Prisma Client、构建 TypeScript。
- 将后端 `dist/`、`node_modules/`、`package.json` 同步到 `/opt/quiz/api/`。
- 前端进入 `/opt/quiz/repo/quiz-web`，设置 `VITE_API_BASE` 后构建，并同步 `dist/` 到 `/opt/quiz/web/dist/`。
- 首次部署后用 PM2 启动后端，用 Nginx 对外提供静态文件和 API 反向代理。

### 4.3 生产环境变量 `.env`

后端环境变量放在 `/opt/quiz/api/.env`，不要提交到 Git。

```env
DATABASE_URL="file:/opt/quiz/data/prod.db"
API_PORT=3001
NODE_ENV=production

JWT_SECRET="<强随机字符串>"

FRONTEND_URL="https://<你的域名>"
CORS_ORIGINS="https://<你的域名>"

DASHSCOPE_API_KEY="<你的 DashScope Key>"
```

如果暂时没有域名，只用公网 IP 测试，则 `FRONTEND_URL` 和 `CORS_ORIGINS` 临时写成：

```env
FRONTEND_URL="http://<公网IP>"
CORS_ORIGINS="http://<公网IP>"
```

前端构建时必须设置：

```env
VITE_API_BASE="https://<你的域名>"
```

公网 IP 测试阶段则临时使用：

```env
VITE_API_BASE="http://<公网IP>"
```

## 五、SSL 证书配置

### 5.1 有域名后配置 HTTPS

- 域名完成实名认证和 ICP 备案后，将域名解析到 ECS 公网 IP。
- 可以使用阿里云免费 DV 证书，也可以使用 Let's Encrypt。
- Nginx 开启 `443`，并将 `80` 重定向到 `443`。
- 证书和私钥只放在服务器，不提交到 Git。

### 5.2 没有域名时的临时方案

- 备案通过前，可以先用 `http://<公网IP>` 做内部测试。
- 公网 IP 阶段不建议录入真实用户密码或敏感数据。
- 等域名、备案、证书完成后，再切换到正式 HTTPS 地址。

## 六、ICP 备案（中国大陆必做）

如果服务器买在**中国大陆 Region**，域名解析到该服务器**必须先完成 ICP 备案**，否则域名访问会被阻断。

### 备案流程

```
购买域名 → 实名认证（1-3天）
    ↓
提交备案申请（阿里云备案系统）
    ↓
阿里云初审（1-2天）→ 短信/人脸核验
    ↓
管局审核（10-15个工作日）
    ↓
备案通过 → 获取 ICP 备案号 → 域名可正常访问
```

### 备案期间怎么办？

在备案通过之前，团队成员可以使用**公网 IP** 直接访问：

```
http://<公网IP>    （开发测试用，备案后切换到域名）
```

> 备案期间网站需要关停，不能通过域名访问。建议备案通过后再配置正式域名。

## 七、部署脚本

部署脚本只保留为自动化方向，不在方案文档中维护完整脚本。实际脚本建议放在 `/opt/quiz/scripts/deploy.sh`，并按当前真实目录维护。

脚本需要完成的步骤：

1. 拉取 `/opt/quiz/repo` 最新代码。
2. 后端在 `api/` 下安装依赖、执行 `prisma migrate deploy`、生成 Prisma Client、执行构建。
3. 前端在 `quiz-web/` 下设置 `VITE_API_BASE` 后执行构建。
4. 同步后端构建产物到 `/opt/quiz/api/`，同步前端产物到 `/opt/quiz/web/dist/`。
5. 使用 PM2 reload 后端进程。
6. 必要时执行 Nginx 配置测试和 reload。

注意事项：

- 当前项目真实后端目录是 `api/`，不是 `apps/api`。
- 当前没有独立 `parser/` 服务，不需要部署 `/opt/quiz/parser`。
- 生产 `.env`、证书、数据库文件不得被脚本覆盖。

## 八、运维要点

### 8.1 日志查看

- 后端日志：使用 `pm2 logs quiz-api` 查看。
- Nginx 日志：查看 `/var/log/nginx/access.log` 和 `/var/log/nginx/error.log`。
- 应用错误优先看 PM2 日志，再看 Nginx 反代日志。

### 8.2 监控

- 用 PM2 观察 Node.js 进程状态、重启次数和内存占用。
- 用系统工具定期检查 CPU、内存、磁盘空间。
- SQLite 单机部署要特别关注磁盘空间和数据库备份是否正常。

### 8.3 备份策略

- 每日备份 `/opt/quiz/data/prod.db`。
- 每周备份 `/opt/quiz/uploads/`。
- 备份文件保存在 `/opt/quiz/backups/`，后续可再同步到 OSS。
- 部署前建议手动备份一次生产库。

### 8.4 安全加固清单

| 项目 | 操作 |
|------|------|
| SSH | 禁用密码登录，仅用密钥对；后续禁用 root 登录 |
| API | 只监听 `127.0.0.1:3001` 或仅允许本机访问 |
| JWT Secret | 生产环境使用强随机字符串，不与开发环境共用 |
| 防火墙 | 仅开放 22/80/443 端口 |
| 依赖 | 定期检查 npm 依赖漏洞 |
| 日志 | 定期清理或配置 logrotate |
| 系统更新 | 每月执行一次安全更新 |
