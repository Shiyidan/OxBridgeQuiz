# 5.2 测试环境选型方案

> 适用环境：测试环境  
> 当前目标：支撑日常开发验证、部署验证、数据库迁移验证和上线前回归  
> 最后更新：2026-07-10

---

## 一、总体架构

当前测试环境采用单 ECS + RDS MySQL 的轻量架构。

```text
公网用户 / 测试人员
  │
  │ HTTP 80（当前公网 IP 访问）
  ▼
Nginx
  ├── /                 → /opt/quiz/web/dist        Vue SPA 静态资源
  ├── /api/             → 127.0.0.1:3001            Express API
  └── /uploads/         → /opt/quiz/uploads         本地上传文件目录

PM2
  └── quiz-api          → /opt/quiz/api/dist/index.js

RDS MySQL
  └── quiztestdemo_tc   → 测试环境业务数据库

备份
  ├── RDS MySQL 逻辑备份
  ├── uploads 文件备份
  ├── 运行配置备份
  └── manifest / checksum 校验记录
```

核心原则：

- 测试环境优先保证“接近线上、成本可控、便于验证”。
- 公网访问统一经过 Nginx，后端 API 不直接对公网暴露。
- 数据库使用 RDS MySQL，不再使用 SQLite 作为测试环境运行库。
- 文件存储当前保留在 ECS 本地目录，正式环境再接入 OSS。
- 测试环境暂不追求高可用，多节点和负载均衡放到正式环境或后续阶段评估。

## 二、当前选型清单

### 2.1 已选产品

| 产品 | 当前选择 | 用途 | 选型理由 |
|------|----------|------|----------|
| ECS 云服务器 | Ubuntu 22.04，2核4G | 部署 Nginx、前端静态资源、后端 Node.js 服务、PM2 | 成本可控，足够支撑测试环境日常验证 |
| RDS MySQL | MySQL 8.0，基础规格，测试库 `quiztestdemo_tc` | 承载业务数据库 | 与当前 Prisma/MySQL 方案一致，提前验证线上数据库形态 |
| Nginx | ECS 本机部署 | 静态资源服务与 API 反向代理 | 贴近正式部署方式，便于统一入口 |
| PM2 | ECS 本机部署 | 管理后端 Node.js 进程 | 轻量、稳定，满足单机测试环境 |
| ECS 本地磁盘 | `/opt/quiz/uploads` | 保存测试环境上传文件 | 当前文件量小，暂不需要单独购买 OSS |
| ECS 本地备份目录 | `/opt/quiz/backups` | 保存测试环境应用侧备份 | 便于部署前备份与恢复验证 |

当前测试访问地址：

```text

```

### 2.2 当前暂不选产品

| 产品 | 当前替代方案 | 暂不选择原因 | 后续触发条件 |
|------|--------------|--------------|--------------|
| OSS 对象存储 | ECS 本地 `/opt/quiz/uploads` | 当前测试文件量小，尚未进入正式文件存储阶段 | 正式环境上线、文件量增长、需要权限控制或签名 URL |
| Redis | 暂不使用 | 当前项目没有强依赖 Redis 的缓存、队列或会话共享 | 出现队列、缓存、限流、多实例共享状态需求 |
| SLB 负载均衡 | 单 ECS + Nginx | 测试环境不需要多节点高可用 | 正式环境需要多 ECS 或高可用架构 |
| CDN | Nginx 直接提供静态资源 | 测试环境访问规模小 | 正式环境静态资源访问量增长 |
| 域名 / HTTPS | 当前公网 IP 测试 | 测试环境主要用于内部验证 | 正式备案、支付、真实用户访问前 |

## 三、ECS 选型

测试环境 ECS 选择单台 2核4G 服务器。

选型依据：

- 当前后端为 Express + Prisma，运行资源占用较低。
- 前端为构建后的静态资源，由 Nginx 提供服务。
- 测试环境并发压力低，不需要多实例。
- 2核4G 可以同时承载 Nginx、PM2、Node.js、部署构建和基础备份任务。

操作系统选择：

```text
Ubuntu 22.04 LTS
```

原因：

- Node.js、Nginx、PM2、Prisma 生态兼容性好。
- 与当前测试环境实际运行系统一致。
- 后续迁移到正式环境时可复用部署经验。

## 四、数据库选型

测试环境数据库已从 SQLite 切换为 RDS MySQL。

当前选择：

```text
RDS MySQL 8.0
数据库：quiztestdemo_tc
```

选型依据：

- 当前项目 Prisma schema 已按 MySQL 方向调整。
- 试卷、题目、答题记录、会员权益、诊断测试等核心数据需要稳定的关系型数据库承载。
- 测试环境提前切换到 RDS MySQL，可以在上线前验证 migration、JSON 字段、数据迁移、备份和恢复流程。
- RDS 提供自动备份、白名单、监控等能力，比 ECS 本地数据库更接近正式环境。

当前不再使用 SQLite 作为测试环境运行库。

历史 SQLite 文件仅作为迁移前备份保留，不作为当前数据库方案。

## 五、文件存储选型

当前测试环境文件存储使用 ECS 本地目录：

```text
/opt/quiz/uploads
```

适用范围：

- 测试上传文件。
- 题目资源文件。
- 临时导出文件。
- 过渡期本地文件访问验证。

当前暂不购买 OSS 的原因：

- 测试阶段文件量较小。
- 当前重点是验证数据库迁移、部署流程和核心业务功能。
- OSS 的权限策略、签名 URL、生命周期规则更适合在正式环境方案中统一落地。

后续正式环境应接入 OSS。

OSS 接入后，ECS 本地上传目录不应再作为唯一文件存储保障。

## 七、网络与安全选型

测试环境对外访问采用公网 IP。

端口策略：

| 端口 | 用途 | 当前策略 |
|------|------|----------|
| `22` | SSH 运维 | 开放，后续建议限制来源 IP |
| `80` | HTTP 访问 | 开放 |
| `443` | HTTPS 预留 | 可开放 |
| `3001` | 后端 API | 不对公网开放，仅由 Nginx 代理 |
| `3306` | RDS MySQL | 不对公网开放，仅允许 ECS 内网访问 |

安全原则：

- API 不通过公网端口直连。
- RDS 通过白名单限制访问来源。
- `.env`、数据库密码、JWT Secret、第三方 API Key 不进入 Git。
- 测试环境不录入真实支付密钥和正式用户敏感数据。

## 八、部署与验证选型

测试环境部署使用 `quiztestdemo-deploy` skill。

常用部署范围：

- `backend`：后端部署，适合验证 RDS、Prisma migration、PM2 reload、备份链路。
- `frontend`：前端部署，适合验证页面样式和静态资源。
- `all`：全量部署，适合阶段性功能发布验证。

当前常用分支：

```text
20260626-feature-development
```

部署后基础验证项：

- 公网首页返回 `200 OK`。
- 公网 `/api/health` 返回 `status: ok`。
- 本机 API health 正常。
- Nginx API 代理正常。
- PM2 中 `quiz-api` 为 `online`。
- Prisma migration 状态为最新。
- 部署前备份已生成。

部署报告保存位置：

```text
文档/5. 部署方案/5.7上线报告/
```

## 九、当前测试环境结论

当前测试环境选型结论：

- ECS 2核4G 可以满足当前测试环境需要。
- RDS MySQL 已替代 SQLite，适合作为后续正式环境数据库方案的验证基础。
- 本地 uploads 可以继续作为测试阶段文件存储。
- 备份策略已从 SQLite 文件快照升级为 RDS 逻辑备份 + 文件备份 + 配置备份。
- 当前不需要 Redis、SLB、CDN。
- 当前不需要域名和 HTTPS，但正式环境上线前必须补齐。

该选型适合作为上线前测试环境，但不能等同于高可用生产环境。

## 十、后续升级方向

当测试环境逐步向正式环境靠近时，建议按以下方向升级：

- 接入 OSS，替代 ECS 本地文件存储。
- 在 RDS 控制台确认自动备份策略。
- 增加 HTTPS 和正式域名验证。
- 增加更严格的 SSH 来源 IP 限制。
- 根据访问量评估是否需要 Redis、CDN、SLB。
- 将正式环境资源迁移到企业阿里云账号统一管理。
