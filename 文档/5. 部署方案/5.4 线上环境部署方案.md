# 线上环境部署方案

> **适用范围**：正式生产上线操作清单 | **最后更新**：2026-07-09

---

## 一、目标说明

本文档用于描述 QuizTestDemo 从当前测试环境切换到正式线上环境时需要执行的实际操作。

本次正式线上环境目标架构：

- ECS：应用主机，部署 Nginx、Node.js、PM2、前端构建产物与后端运行目录。
- RDS PostgreSQL：正式主数据库。
- OSS：正式文件存储，用于试卷 PDF、题目资源、导出文件。
- 域名 + HTTPS：正式对外访问入口。

当前已选定的正式线上 ECS 配置如下：

| 项目 | 已选值 |
|------|--------|
| 地域 | 华东 2（上海） |
| 实例规格 | `ecs.u2a-c1m2.large` |
| CPU / 内存 | 2 核 / 4 GB |
| 系统盘 | ESSD Entry 40 GB |
| 操作系统 | Ubuntu 22.04 64 位 |
| 带宽 | 5 Mbps 按使用流量 |
| 付费方式 | 包年包月 1 年 |
| 网络 | 专有网络 VPC |

## 二、上线前准备

### 2.1 云资源准备

必须先完成以下资源开通：

1. 正式 ECS 已购买完成。
2. RDS PostgreSQL 已购买完成，地域与 ECS 保持一致（华东 2）。
3. OSS 已创建完成，地域与 ECS、RDS 保持一致（华东 2）。
4. 域名已购买并完成实名认证。
5. SSL 证书已申请完成或已确认申请路径。

### 2.2 关键信息准备

上线前需要准备并记录以下信息：

- ECS 公网 IP、私网 IP
- ECS 登录用户与 SSH 密钥
- RDS 连接地址、端口、数据库名、账号、密码
- OSS Bucket 名称、Endpoint、AccessKey / RAM 授权方式
- 域名、备案进度、HTTPS 证书路径
- 生产环境 JWT Secret
- 生产环境 DashScope / 其他第三方 API Key

### 2.3 代码与数据准备

上线前必须确认：

1. `schema.prisma` 与 Prisma migrations 已完全对齐。
2. PostgreSQL 版 `DATABASE_URL` 已准备好。
3. SQLite 到 PostgreSQL 的迁移方案已验证。
4. 本地文件存储迁移到 OSS 的方案已验证。
5. 前端正式环境 `VITE_API_BASE` 已确定。

---

## 三、正式上线操作

### 3.1 初始化 ECS

需要执行的操作：

1. 使用 Ubuntu 22.04 登录服务器。
2. 创建 `deploy` 用户并配置 SSH 密钥登录。
3. 安装并更新基础环境：
   - `curl`
   - `wget`
   - `git`
   - `build-essential`
   - `nginx`
   - `ufw`
4. 安装 Node.js 20。
5. 安装 PM2。

### 3.2 配置安全组与防火墙

正式环境只保留以下入口：

| 端口 | 用途 |
|------|------|
| `22` | SSH |
| `80` | HTTP（备案/跳转/校验） |
| `443` | HTTPS |

必须关闭或不开放以下端口：

- `3001`
- `5432`
- `6379`

要求：

- API 只允许通过 Nginx 反向代理访问。
- RDS 仅允许来自 ECS 所在 VPC / 白名单的访问。

### 3.3 创建服务器目录

正式环境目录统一为：

```text
/opt/quiz/
├── repo/
├── api/
├── web/
│   └── dist/
├── data/
├── uploads/
├── scripts/
└── backups/
```

要求：

- `/opt/quiz/api/.env` 不进入 Git。
- `/opt/quiz/backups/` 必须可写，用于部署前数据库备份。

### 3.4 创建 RDS PostgreSQL

需要执行的操作：

1. 在华东 2 创建 PostgreSQL 实例。
2. 创建生产数据库，例如 `quiz_prod`。
3. 创建生产账号与强密码。
4. 配置白名单，仅允许 ECS 内网访问。
5. 开启自动备份。

上线前需要确认：

- `DATABASE_URL` 已切换为 PostgreSQL 连接串。
- Prisma migration 可在 PostgreSQL 上正常执行。

### 3.5 SQLite -> PostgreSQL 数据迁移

需要执行的操作：

1. 备份当前 SQLite 生产库。
2. 导出需要迁移的数据。
3. 在 PostgreSQL 上执行 `prisma migrate deploy`。
4. 执行数据导入脚本。
5. 逐表校验核心数据量与关键业务数据。

必须校验的对象：

- `User`
- `Paper`
- `Question`
- `ExamRecord`
- `AnswerRecord`
- `DiagnosticSession`
- `UserMembership`
- `EntitlementConfig`
- `SyllabusNode`
- `RevenueCost`

上线判定标准：

- 数据总量一致或在预期差异范围内。
- 关键用户可正常登录。
- 关键试卷、题目、会员数据可正常读取。

### 3.6 接入 OSS

需要执行的操作：

1. 创建正式 OSS Bucket。
2. Bucket 设为私有访问。
3. 配置应用访问 OSS 的凭据或 RAM 授权。
4. 建立目录规划：

```text
quiz-files/
├── papers/
├── exports/
└── questions/
```

5. 将当前需要保留的 PDF / 导出文件迁移到 OSS。
6. 将应用中的文件访问改为通过 OSS 路径或签名 URL 返回。

上线判定标准：

- 试卷 PDF 可正常访问或下载。
- 导出文件可正常生成和访问。
- 题目配图加载正常。

### 3.7 部署应用代码

需要执行的操作：

1. 将代码克隆到 `/opt/quiz/repo`。
2. 后端执行：
   - `npm ci`
   - `npx prisma migrate deploy`
   - `npx prisma generate`
   - `npm run build`
3. 前端执行：
   - 配置正式 `VITE_API_BASE`
   - `npm ci`
   - `npm run build-only`
4. 同步运行目录：
   - 后端同步到 `/opt/quiz/api`
   - 前端同步到 `/opt/quiz/web/dist`
5. 使用 PM2 启动或重载 `quiz-api`。

要求：

- 部署脚本不得覆盖 `/opt/quiz/api/.env`
- 部署脚本不得覆盖数据库备份
- 部署前必须先做数据库备份

### 3.8 配置 Nginx

Nginx 需要完成以下职责：

- `/` 指向前端 SPA 静态资源目录
- `/api/` 反向代理到 `127.0.0.1:3001`
- 处理 SPA history 路由回退
- 配置 HTTPS 证书
- 将 `80` 重定向到 `443`

上线前必须确认：

- `/api/health` 可通过 Nginx 正常访问
- 刷新前端路由不会 404

### 3.9 域名、备案与 HTTPS

需要执行的操作：

1. 域名完成ICP备案。
2. 域名 A 记录指向 ECS 公网 IP。
3. 申请并配置 SSL 证书。
4. Nginx 接入证书并启用 `443`。
5. 将前端 API 地址与后端 CORS 白名单改为正式域名。

上线判定标准：

- `https://<域名>/` 可访问
- `https://<域名>/api/health` 正常
- 浏览器无证书错误

## 四、上线验证

正式上线后至少执行以下验证：

### 4.1 基础验证

- 首页可打开
- 登录页可打开
- 后台可打开
- `/api/health` 正常

### 4.2 业务验证

- 用户名密码登录正常
- 诊断测试列表可加载
- 试题库题目可加载
- 真题库后台管理可加载
- 用户管理、营收管理可加载
- 会员权益读取正常

### 4.3 文件验证

- PDF 可访问
- OSS 文件链接正常
- 图片/题目配图显示正常

### 4.4 数据验证

- PostgreSQL 中主要表数据正常
- 会员数据与用户数据正常关联
- 已有考试记录与答题记录可正常读取

---

## 五、上线后必须补齐的运维项

### 5.1 监控与告警

需要补齐：

- ECS CPU / 内存 / 磁盘告警
- RDS 连接数、存储、CPU 告警
- OSS 流量与访问异常监控
- PM2 进程状态观察

### 5.2 备份策略

必须落实：

- RDS 自动备份
- 关键 OSS 文件生命周期策略
- 部署前数据库备份
- 重大迁移前手动快照

### 5.3 安全项

必须确认：

- 禁 root 直登
- 禁密码 SSH 登录，仅保留密钥
- JWT Secret 为生产独立值
- 所有第三方 Key 不写入 Git
- 安全组最小开放

---

## 六、上线完成判定

满足以下条件，视为正式上线完成：

1. ECS、RDS、OSS、域名、HTTPS 均已完成配置。
2. SQLite -> PostgreSQL 迁移完成并通过核验。
3. 文件已完成 OSS 迁移并可正常访问。
4. 前后端应用均完成正式环境部署。
5. 域名 HTTPS 访问正常。
6. 核心业务链路验证通过。
7. 已配置监控、备份和基础安全项。
