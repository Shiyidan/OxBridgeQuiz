## 一、目标说明

本文档用于描述 QuizTestDemo 从当前测试环境切换到正式线上环境时需要执行的实际操作。

本次正式线上环境目标架构：

- ECS：应用主机，部署 Nginx、Node.js、PM2、前端构建产物与后端运行目录。
- RDS MySQL：正式主数据库。
- OSS：正式文件存储，用于试卷 PDF、题目资源、导出文件。
- 域名、备案、HTTPS、支付与正式运营事项：见本文第六章 TODO。

当前已选定的正式线上 ECS 配置如下：

| 项目 | 已选值 |
|------|--------|
| 地域 | 华东 2（上海） |
| 实例规格 | `ecs.u2a-c1m2.large` |
| CPU / 内存 | 2 核 / 4 GB |
| 系统盘 | ESSD Entry 40 GB |
| 操作系统 | Ubuntu 22.04 64 位 |
| 带宽 | 5 Mbps 按使用流量 |
| 付费方式 | 包年包月 1 年 |
| 网络 | 专有网络 VPC |

## 三、正式上线操作

### 3.1 初始化 ECS

需要执行的操作：

1. 使用 Ubuntu 22.04 登录服务器。
2. 创建 `deploy` 用户并配置 SSH 密钥登录。
3. 安装并更新基础环境：
   - `curl`
   - `wget`
   - `git`
   - `build-essential`
   - `nginx`
   - `ufw`
4. 安装 Node.js 20。
5. 安装 PM2。

### 3.2 配置安全组与防火墙

正式环境只保留以下入口：

| 端口 | 用途 |
|------|------|
| `22` | SSH |
| `80` | HTTP（备案/跳转/校验） |
| `443` | HTTPS |

必须关闭或不开放以下端口：

- `3001`
- `3306`
- `6379`

要求：

- API 只允许通过 Nginx 反向代理访问。
- RDS 仅允许来自 ECS 所在 VPC / 白名单的访问。

### 3.3 创建服务器目录

正式环境目录统一为：

```text
/opt/quiz/
├── repo/
├── api/
├── web/
│   └── dist/
├── data/
├── uploads/
├── scripts/
└── backups/
```

要求：

- `/opt/quiz/api/.env` 不进入 Git。
- `/opt/quiz/backups/` 必须可写，用于部署前数据库备份。

### 3.4 创建 RDS MySQL

需要执行的操作：

1. 在华东 2 创建 MySQL 实例。
2. 创建生产数据库，例如 `quiz_prod`。
3. 创建生产账号与强密码。
4. 配置白名单，仅允许 ECS 内网访问。
5. 确认 RDS 与 ECS 的内网访问关系。

上线前需要确认：

- `DATABASE_URL` 已切换为 MySQL 连接串。
- Prisma migration 可在 MySQL 上正常执行。

### 3.5 SQLite -> MySQL 数据迁移

需要执行的操作：

1. 备份当前 SQLite 生产库。
2. 导出需要迁移的数据。
3. 在 MySQL 上执行 `prisma migrate deploy`。
4. 执行数据导入脚本。
5. 逐表校验核心数据量与关键业务数据。

必须校验的对象：

- `User`
- `Paper`
- `Question`
- `ExamRecord`
- `AnswerRecord`
- `DiagnosticSession`
- `UserMembership`
- `EntitlementConfig`
- `SyllabusNode`
- `RevenueCost`

上线判定标准：

- 数据总量一致或在预期差异范围内。
- 关键用户可正常登录。
- 关键试卷、题目、会员数据可正常读取。

### 3.6 接入 OSS

需要执行的操作：

1. 创建正式 OSS Bucket。
2. Bucket 设为私有访问。
3. 配置应用访问 OSS 的凭据或 RAM 授权。
4. 建立目录规划：

```text
quiz-files/
├── papers/
├── exports/
└── questions/
```

5. 将当前需要保留的 PDF / 导出文件迁移到 OSS。
6. 将应用中的文件访问改为通过 OSS 路径或签名 URL 返回。

上线判定标准：

- 试卷 PDF 可正常访问或下载。
- 导出文件可正常生成和访问。
- 题目配图加载正常。

### 3.7 部署应用代码

需要执行的操作：

1. 将代码克隆到 `/opt/quiz/repo`。
2. 后端执行：
   - `npm ci`
   - `npx prisma migrate deploy`
   - `npx prisma generate`
   - `npm run build`
3. 前端执行：
   - 配置正式 `VITE_API_BASE`
   - `npm ci`
   - `npm run build-only`
4. 同步运行目录：
   - 后端同步到 `/opt/quiz/api`
   - 前端同步到 `/opt/quiz/web/dist`
5. 使用 PM2 启动或重载 `quiz-api`。

要求：

- 部署脚本不得覆盖 `/opt/quiz/api/.env`
- 部署脚本不得覆盖数据库备份
- 部署前必须先做数据库备份

### 3.8 配置 Nginx

Nginx 需要完成以下职责：

- `/` 指向前端 SPA 静态资源目录
- `/api/` 反向代理到 `127.0.0.1:3001`
- 处理 SPA history 路由回退

上线前必须确认：

- `/api/health` 可通过 Nginx 正常访问
- 刷新前端路由不会 404
