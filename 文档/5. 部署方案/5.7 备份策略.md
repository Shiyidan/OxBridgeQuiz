# 5.7 备份策略

> **适用范围**：QuizTestDemo 测试环境与生产环境  
> **最后核对**：2026-07-24

本文档以当前部署脚本、生产定时任务和阿里云 RDS 能力为准，区分“已经实现”和“仍需完善”的备份能力。历史 SQLite 文件不再属于当前数据库备份方案。

---

## 一、备份目标与边界

当前需要保护的数据分为三类：

1. RDS MySQL 中的业务结构与数据。
2. `/opt/quiz/uploads` 中尚未迁移到 OSS 的上传文件。
3. 后端运行环境、PM2 和 Nginx 等服务器运行配置。

备份需要覆盖部署迁移失败、误操作、应用服务器损坏和数据库故障等场景。仅保存在同一台 ECS 系统盘上的文件不能作为最终的异地备份保障。

当前尚未正式确定 RPO（最大可接受数据丢失时间）和 RTO（最大可接受恢复时间），应在完成首次恢复演练后补充。

---

## 二、当前已经实现的三层备份

### 2.1 部署前应用侧逻辑备份

测试和生产环境在执行后端部署或全量部署时，都会在 Prisma migration 之前运行 `backup-rds-runtime.sh`。

当前顺序为：

1. 校验目标环境、数据库和 Prisma migration。
2. 生成数据库、上传文件和运行配置备份。
3. 生成备份清单与 SHA-256 校验值。
4. 备份脚本成功后才继续运行时配置校验、数据库迁移和应用构建。

MySQL 逻辑备份失败会终止部署。上传目录不存在或运行配置归档为空时，当前脚本会记录缺失并继续，因此这两类内容是否必须存在仍需按环境增加强校验。

### 2.2 生产 ECS 每日逻辑备份

生产服务器已安装 `quiz-rds-backup.timer`：

- 每日计划时间：03:30。
- 随机延迟：最多 15 分钟。
- `Persistent=true`：服务器错过计划时间后会补跑。
- 执行用户：`deploy`。
- 本地保留周期：14 天。
- 备份结果：MySQL 压缩包、上传目录归档、运行配置归档和校验清单。

2026-07-24 已执行一次 `scheduled-verification`，三类备份均成功生成，清单内 SHA-256 校验通过。

测试环境的部署前备份已经持续使用；是否已经安装并启用同样的每日 systemd timer，当前部署记录缺少可复核的验收结果，需要单独确认。

### 2.3 阿里云 RDS 平台备份

RDS MySQL 平台备份是数据库故障恢复的独立保护层，不依赖 ECS 本地磁盘。

当前已确认 RDS 全量自动备份由平台强制开启，最低要求为每周 2 次、至少保留 7 天；但以下生产实例实际配置仍需在阿里云控制台核对：

- 具体备份周期和保留天数。
- 最近一次成功备份集。
- 日志备份状态。
- 任意时间点恢复能力及可恢复时间范围。
- 备份失败、容量和恢复相关告警。

## 三、备份内容与目录

当前应用侧目录规划：

```text
/opt/quiz/backups/
├── mysql/       # RDS MySQL 逻辑备份
├── uploads/     # /opt/quiz/uploads 归档
├── config/      # 运行配置和独立配置变更备份
├── manifests/   # 备份清单与 SHA-256
└── source/      # 特殊仓库初始化产生的旧源码归档，不属于日常备份脚本
```

### 3.1 MySQL 逻辑备份

当前通过 `mysqldump` 生成 `.sql.gz` 文件，内容包括：

- 表结构与业务数据。
- 触发器。
- 账号权限允许时包含存储过程和事件；权限不足时使用不含存储过程和事件的回退模式。
- `utf8mb4`、二进制字段和表重建语句。

生成后立即运行 `gzip -t` 校验压缩包结构。

### 3.2 上传文件备份

如果 `/opt/quiz/uploads` 存在，则将整个目录归档为 `.tar.gz`。在 OSS 正式接入前，该目录中的题目资源、用户上传和导出文件需要纳入恢复范围。

当前上传文件归档与源文件位于同一台 ECS，因此只能防止应用发布误覆盖，不能防止整机或系统盘损坏。

### 3.3 运行配置备份

当前归档范围包括：

- `/opt/quiz/api/.env`。
- `/opt/quiz/ecosystem.config.cjs`。
- `/etc/nginx/sites-available/quiz`。
- `/etc/nginx/sites-available/quiztestdemo`。

配置归档可能包含数据库连接和 SMTP 等敏感信息，只允许以 `600` 权限保存在受控目录，不得进入 Git、普通部署报告或公开存储。

### 3.4 备份清单

每次备份生成独立清单，记录：

- 时间戳、触发原因和目标环境。
- 数据库名称与数据库地址。
- 各备份文件路径。
- 已生成文件的 SHA-256 校验值。

清单本身使用 `600` 权限。数据库地址属于内部运行信息，不应复制到公开文档。

## 四、当前保留和清理规则

`backup-rds-runtime.sh` 当前对 `mysql/`、`uploads/`、`config/` 和 `manifests/` 中超过 14 天的文件统一执行删除。

这意味着：

- 每日定时备份和部署前备份目前使用相同的 14 天保留规则。
- “重要版本、数据迁移或重大配置变更备份长期保留”目前只是目标，并未在脚本中实现。
- `source/` 下的旧源码归档不受当前 14 天清理逻辑管理，需要单独定义保留期限。
- RDS 平台备份使用阿里云控制台中的独立保留策略，不受 ECS 清理脚本影响。

在分层保留规则实现前，需要长期保留的备份必须先复制到独立受控存储，不能只修改文件名后继续留在同一目录。

## 五、当前校验与恢复能力

已经具备：

- MySQL 压缩包生成后执行 `gzip -t`。
- 对已生成的数据库、上传文件和配置归档记录 SHA-256。
- 部署失败时保留迁移前备份作为回滚辅助。
- 生产每日 timer 已启用并完成一次人工执行验证。

尚未具备或尚未验证：

- 尚未把 MySQL 逻辑备份实际恢复到隔离数据库并完成业务数据抽查。
- 尚未验证上传文件和运行配置能够从备份完整重建应用。
- 尚未建立备份失败、备份过旧、文件异常变小或磁盘容量不足的外部告警。
- 尚未验证 ECS 完全不可用时的跨主机恢复流程。
- 尚未形成定期恢复演练记录。

SHA-256 和压缩包校验只能证明文件未明显损坏，不能替代真实恢复演练。

## 七、当前处理决定

### 7.1 已完成：逻辑备份一致性

`backup-rds-runtime.sh` 的正常导出和权限回退导出均已加入 InnoDB `--single-transaction` 一致性快照参数。该参数与现有 `--quick`、`--skip-lock-tables` 组合使用，减少在线备份期间跨表数据不一致的风险。

### 7.2 待处理：RDS 控制台核对

需要在阿里云 RDS 控制台确认并记录：

- 生产实例实际备份周期和保留天数。
- 最近一次成功备份集及完成时间。
- 日志备份是否开启。
- 任意时间点恢复是否可用，以及可恢复时间范围。
- 是否已配置备份失败、容量或恢复相关告警。

### 7.3 暂不纳入当前计划

- 当前阶段不考虑接入 OSS 异地备份。
- 本轮审计中的其他改进建议暂不处理，不列入当前待办。

## 八、安全与非目标说明

- 不把历史 SQLite 文件作为当前数据库备份方案。
- 不把 ECS 本地目录作为唯一备份位置。
- 不在 Git、公开文档和普通部署报告中记录数据库密码、密钥或授权码。
- 不使用未经验证的备份直接覆盖生产数据库。
- 备份删除、恢复和跨环境导入必须先确认目标环境、数据范围与回滚点。
