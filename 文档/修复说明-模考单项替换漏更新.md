# 模考单项替换漏更新修复说明

## 问题与范围

独立单项从 Excel 导入时，每个 Sheet 创建一个 `MockPaperSet` 来源容器，并主动写入 `deletedAt = importedAt`。此处表示该容器不作为完整套卷展示，原始 `MockPaperModule` 仍可独立发布、开考和组卷，不能据此认定单项已被删除。

旧替换发布逻辑仅扫描 `deletedAt = null` 的套卷，因此可能漏掉未被活跃组合卷引用的独立单项。旧题归档后，原始单项仍引用旧题；目录只读取模块汇总状态，开考才逐题检查当前状态，所以可能先出现“目录可见但开考失败”，随后在重新校验或下线后从学生目录消失。

修复覆盖 ESAT 与 TMUA 的现有题目替换关系，不生成新题，不重新发布历史题包，也不改变历史答卷使用的题目。

2026-09-07 后续编号改造已在本地开发库完成：完整卷与单项按各自系列编号、换版，保留历史编号与答卷 ID；测试、生产尚未部署。模型变化及已有数据库必须分阶段回填的步骤见[模考试卷编号规则与迁移](模考试卷编号规则与迁移.md)。

## 修复规则

- 直接扫描纳入独立来源单项，不因来源容器的 `deletedAt` 排除。完整卷和单项分别按自己的 `MockPaperSeries` 取最高版本，单项还按学科拥有独立编号池。父完整卷已换版不妨碍其中仍有效的原始单项继续使用及换题；旧版本不会覆盖已经修好的当前版本。
- 只有实际内容改变的原始单项才增加自身版本，未改科保留原编号、版本与模块 ID。新单项版本放入新的隐藏容器，完整卷副本明确引用来源版本，不拥有新的单项编号。容器的 `versionGroupId` 仅维持技术关系，不是展示编号。
- 从未发布、没有答卷且未被正式完整卷使用的单项草稿可原位替换；曾独立发布或被已开放完整卷使用的单项保留旧版本。完整卷根据自己的开放历史或答卷决定换版，副本继承的来源单项发布时间不代表完整卷已开放。
- 从变化来源反向检查当前完整卷，已开放完整卷生成自身新版，未开放的副本式完整卷原位重绑。旧式完整卷直接持有需要换版的原始单项时，为保留原模块所属运行 Paper 和答卷关系，完整卷也另存版本，仍保持原状态。旧版本及其题目、来源关系保留。
- 新版本在同一事务内重新校验题目与模块，并同步运行 Paper。不会复制过期的“题目已归档”校验结果作为新版本结论。运行异常时回滚本次修改；若校验发现题目仍不可用，则保存 `invalid` 结果并关闭对应入口，不因单纯校验未通过而自动抛错回滚。
- 旧多科容器中的草稿原位换题时，仅校验本次可编辑的受影响模块；已发布或已归档兄弟模块的题目引用、校验记录和更新时间保持原样。父容器汇总合并本次校验与兄弟的既有校验，运行 Paper 继续按剩余有效开放模块同步。
- 单项与套卷原有下线状态继续保留。补出有效新版不等于恢复学生入口；如需恢复，须确认对应新版本校验通过后，另行执行单项发布。
- 历史补处理只修正仍引用旧题的当前模考版本；重复执行应无新增变更，不重复发布替换题包。

## 2026-09-07 指定修复的两个状态问题

已发布独立单项组成完整卷草稿后，替换发布现在会让来源单项生成新版，同时原位更新尚未开放的组合草稿，并把相应副本重新关联到新版来源。组合草稿保留原 ID、版本号及草稿状态，不生成运行 Paper。来源单项原先已下线时，新版及副本继续保持下线。真正已开放但缺少运行 Paper 的记录仍作为数据异常拒绝处理，不能通过放宽校验掩盖。

旧结构多个原始单项共用运行 Paper 时，下线单项会在同一事务内重新计算运行状态及模块配置。仍有效且独立发布的其他原始单项继续开放；完整卷仍发布时保留完整卷运行能力；没有剩余可用单项且完整卷未开放时，才归档运行 Paper。

这两项已在本地通过 ESAT/TMUA 回归，尚未部署线上。其他审计问题的范围和状态见《模考试卷库组卷逻辑审计-2026-09-07.md》。

## 补处理入口

脚本为 `api/scripts/repair-mock-question-replacements.ts`，复用 `repairMockPaperQuestionReplacements` 服务。所有命令在 `api/` 目录执行，使用项目本地依赖。

必须指定 `--exam-type=ESAT|TMUA` 和 `--environment=local|test|prod`；环境参数必须与 `API_RUNTIME_ENV` 完全一致。配置从 `API_ENV_FILE` 指定文件加载，未指定时读取当前目录 `.env`。脚本不打印连接地址或密钥。

默认执行 dry-run，也可显式指定 `--dry-run`。`--dry-run` 与 `--apply` 互斥；未知参数、空 `--set-id`、重复环境或考试参数均拒绝执行。`--set-id=ID` 可重复，用于指定父 `MockPaperSet`，不是模块 ID；不指定时扫描该考试。指定记录是查找旧题关系的起点，仍会纳入来源的当前版本和反向引用该来源的当前完整卷，须审核输出的完整计划。

本地只读计划：

```powershell
npm.cmd run repair:mock-question-replacements -- --exam-type=ESAT --environment=local --dry-run
```

单个目标的命令模板；执行前把占位符替换成已审核的当前套卷 ID：

```powershell
npm.cmd run repair:mock-question-replacements -- --exam-type=ESAT --environment=local --dry-run --set-id=REVIEWED_SET_ID
```

输出包括资产类型、稳定系列 ID、完整业务编号、原版本、计划动作（`version` 或 `update_draft`）、单项标题、发布状态、受影响题位及执行结果 JSON。`sequenceNo` 使用 `ESAT-MOCK-M2-005-V1`、`TMUA-MOCK-P1-003-V1` 或完整卷 `ESAT-MOCK-001-V1` 这类字符串；补处理计划显示原版本编号，发布结果显示新版本编号。对外仅返回 `sequenceNo`，已移除重复的 `displayNo`、`code` 兼容字段。先检查范围、依赖关系与下线状态，再决定是否写入。没有待处理项时也应保留零变更结果供核对。

执行 `--apply` 前核对 dry-run 的处理范围与目标环境；生产环境按既有部署授权与数据库备份规则执行。本入口不增加交互确认，已经授权的本地或测试验证可继续执行。测试或生产命令中的 `--environment` 与 `API_ENV_FILE` 都须指向已经确认的目标，不得仅修改环境参数绕过检查。

确认后的本地执行模板：

```powershell
npm.cmd run repair:mock-question-replacements -- --exam-type=ESAT --environment=local --apply --set-id=REVIEWED_SET_ID
```

执行后再次运行相同考试范围的 dry-run，确认已修复项目不再新增版本；核对当前模块的题目引用与校验结果，并确认旧答卷和旧版本未被改写。原先下线的单项应仍然下线，只有明确恢复发布后才应出现在学生目录。
