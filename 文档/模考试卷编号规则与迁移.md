## 编号和版本规则

完整卷与单项分别拥有稳定的内部序数，API 的 `sequenceNo` 返回包含考试、学科（单项）和版本的完整业务编号字符串，例如 `ESAT-MOCK-M2-005-V1`。序数至少补齐三位，超过三位时保留完整数字；版本使用 `V1/V2`，不补零。内部序数在所属池中从 1 递增，不按年份重置；下线、删除和换版不回收或重新分配序数。管理员自定义标题保留，完整编号由服务端按系列身份和版本统一派生。

| 编号池 | 范围 | 示例 |
|---|---|---|
| ESAT 完整卷 | `ESAT + full + 空学科键` | `ESAT-MOCK-005-V1` |
| ESAT 单项 | `ESAT + single + 学科键`，五科学科各一池 | `ESAT-MOCK-M1-005-V1` 与 `ESAT-MOCK-M2-005-V1` 是两个不同单项 |
| TMUA 完整卷 | `TMUA + full + 空学科键` | `TMUA-MOCK-005-V1` |
| TMUA 单项 | `TMUA + single + paper1/paper2`，各一池 | `TMUA-MOCK-P1-005-V1` 与 `TMUA-MOCK-P2-005-V1` 分别编号 |

ESAT 单项学科段为 Mathematics 1 `M1`、Mathematics 2 `M2`、Biology `B`、Chemistry `C`、Physics `P`；TMUA 为 Paper 1 `P1`、Paper 2 `P2`。完整卷不含学科段。

Excel 每个 Sheet 创建原始单项，在该考试、学科的池中分号；其隐藏来源容器不消耗完整卷号。管理员组成完整卷时，在对应考试的完整卷池另分一个号。套卷模块副本继承具体来源单项的编号和版本，不额外分号，也不使用所属完整卷的号替代单项号。

内部序数和版本独立。新资产从版本 1 开始；需要保留历史的内容变更在同一系列增加版本，完整业务编号只改变版本段，例如 `ESAT-MOCK-M2-005-V1` 变为 `ESAT-MOCK-M2-005-V2`，不消耗新的序数。只修改 Mathematics 2 时，其他未改科保留自身编号、版本和模块 ID。完整卷根据自身是否需要保留历史决定原位更新或增加版本，单项版本与完整卷版本可以不同。

原始单项按自己的系列选择当前版本，不能按父完整卷的最高版本筛掉仍有效的单项。组卷提交拒绝历史单项版本，并在同一 Serializable 事务内检查来源、当前占用和创建记录。允许保留历史副本，不代表同一来源可以不经占用检查随意重复组卷。

后台完整卷卡片直接显示完整 `sequenceNo`，不再追加重复的 `VERSION n`；单项表格、来源候选和详情使用单项自己的完整编号。所属完整卷单独显示完整卷编号。学生目录及记录原样展示对应资产编号；历史答卷仍保留当时的编号、题目与结构。业务标题不改成完整编号；只有缺少已保存标题的单项，前端才从完整编号提取序数，沿用简短标题兜底。

## 后台筛选

后台筛选栏分别提供套卷名称或编号、考试、学科和状态。学科下拉支持输入查找，选定考试后只列出其对应学科；切换考试时清除不兼容的学科选择。套卷视图按是否包含所选学科筛选，单项视图按单项自身学科筛选。名称检索只匹配当前显示的所属套卷名称，不再匹配单项标题、学科名称或学科代码；编号仍可检索单项自身编号，后台单项视图也支持按所属完整卷编号查找模块。

点击查询后提交整组条件并回到第一页；翻页使用已提交条件，不带入尚未查询的修改；清空筛选同时清除已提交和草稿条件，并保留每页条数。

## API 编号与数据库序数的区别

`MockPaperSeries.sequenceNo` 在数据库中仍是 `Int`，用于分号、排序和唯一约束，本次展示调整不改动已应用迁移或内部编号池。API 继续使用 `sequenceNo` 字段名，但类型为 `string | null`，不能将数据库整数直接返回到页面，也不能由前端再拼成 `No.xxx`。

| API 字段 | 返回内容 |
|---|---|
| 完整卷列表、详情及学生完整卷的 `sequenceNo` | 完整卷业务编号，例如 `ESAT-MOCK-005-V1` |
| 单项列表、候选、详情及学生单项的顶层 `sequenceNo` | 独立单项业务编号，例如 `ESAT-MOCK-M2-005-V1`；副本取具体来源版本 |
| 单项所属 `mockPaperSet/sourceSet.sequenceNo`、`sourcePaperSequenceNo` | 对应完整卷业务编号；隐藏容器无完整卷身份时为 `null` |
| 学生答卷记录的 `sequenceNo` | 当次完整卷或单项版本的完整业务编号 |

缺少对应编号身份时返回 `null`，页面显示 `—`，不伪造编号。API 独立的 `version` 属性继续保留，供业务判断使用；由于 `sequenceNo` 已含版本段，展示时不再重复拼接版本标签。

## 数据模型

| 模型或字段 | 职责与约束 |
|---|---|
| `MockPaperSeries` | 保存 `examType/kind/moduleCode/sequenceNo`，其中 `sequenceNo` 为内部 `Int` 序数，四字段联合唯一；`kind=full` 时学科键为空，`kind=single` 时学科键必填 |
| `MockPaperNumberCounter` | `id=${examType}:${kind}:${moduleCode}`，`lastNumber` 保存该池已分配最大号；通过事务递增，删除资产不调低计数器 |
| `MockPaperSet.seriesId` | 可空外键；完整卷关联 `full` 系列，隐藏单项容器为空 |
| `MockPaperSet.versionGroupId` | 必填容器分组键，无外键关系；与 `version` 联合唯一。新完整卷与其系列 ID 一致，隐藏容器仅用它维护技术分组，不能展示为完整卷编号 |
| `MockPaperSet.version` | 完整卷或容器版本；另有 `seriesId + version` 联合唯一约束 |
| 旧编号列 | `MockPaperSet.code`、旧整数 `sequenceNo` 及过渡兼容列 `legacyCode` 均已删除。完整业务编号通过 API 派生，旧编号不再参与搜索 |
| 原始 `MockPaperModule` | `sourceModuleId=null`，拥有 `single` 类型 `seriesId` 和独立 `version`；`seriesId + version` 联合唯一 |
| 套卷模块副本 | `seriesId/version` 均为空，通过 `sourceModuleId` 指向具体原始单项版本；接口将来源编号和版本派生到模块顶层 |
| `MockPaperModule.sourceModuleId` | 保留普通索引，取消唯一索引；同一个原始版本允许被不同完整卷历史版本保存，关系为 1:N |
| `MockPaperModule.code` | 仍是 `maths1/maths2/paper1` 等学科键，本次不删除或改作展示编号 |
| `Paper.code` | 字段为其他试卷业务保留；模考运行载体创建或同步时写为 `null`，备注使用标题 |

编号分配由 `api/src/services/mockPaperNumbering.ts` 的 `createMockPaperSeries` 和 `withMockPaperNumberTransaction` 统一完成；唯一冲突和事务冲突有限重试。不能恢复使用“当前记录最大号加一”，否则删除历史记录会导致重复分号，并发导入也可能抢到同一号码。

## 已有数据库必须分两阶段迁移

**不能在尚未回填的已有数据库上，直接对包含以下两个待执行迁移的最终目录运行一次 `prisma migrate deploy`。** 该命令会连续执行所有待迁移项，没有“执行到指定迁移”的停止参数。第二阶段会删掉历史归族需要的旧列，并将 `versionGroupId` 改为非空；必须先留出快照与回填步骤。

| 阶段 | 迁移 | 数据库状态 |
|---|---|---|
| 第一阶段 | `20260907150000_add_mock_paper_number_series` | 添加系列、计数器和新字段，保留 Set 的旧 `code/sequenceNo`；`versionGroupId` 暂可空 |
| 中间步骤 | Prisma 快照核对、映射预览与回填 | 为所有存量容器、原始单项建立系列及分组；保留原编号、版本和业务关系 |
| 第二阶段 | `20260907153000_replace_mock_paper_codes_with_series` | 删除 Set 旧 `code/sequenceNo`，要求 `versionGroupId` 非空，建立新版本唯一约束，取消来源全局唯一约束 |

执行顺序如下：

1. 确认目标环境与维护范围，保存可恢复的数据库备份，并暂停会改变模考、题目引用和相关答卷的写入。使用旧模型的项目 Prisma Client 导出迁移前快照，保留旧字段；快照必须在旧列删除前取得，不能从最终模型反推。
2. 使用只包含第一阶段新迁移的受控发布检查点或隔离执行目录应用第一阶段。该检查点必须有对应的中间 Prisma schema：保留旧 `MockPaperSet.code/sequenceNo`，新 `versionGroupId` 为可空。不得通过删除仓库迁移历史、`db push` 或虚假 `migrate resolve` 跳过阶段。
3. 由中间 schema 正常生成 Prisma Client，运行快照核对和回填。**最终 schema 的 `versionGroupId` 已不可空，不能拿最终客户端读取此时尚未回填的新字段。** 同样不能让最终业务 API 在未完成回填的结构上启动。
4. 先审核 dry-run 生成的系列映射与计数器，再执行 apply。确认每个 Set 的 `versionGroupId` 已回填、完整卷与原始单项系列齐全、副本保持来源继承、系列编号和版本无冲突，并与快照核对内容及答卷一致。
5. 核对通过后才切换到包含第二阶段的最终迁移目录和 schema，应用第二阶段并正常生成最终 Prisma Client。运行迁移状态和 schema 差异核对，再验证目录、编号、版本、开考和历史答卷。若差异或关系核对未通过，先停止升级处理原因。

本次开发库已经完成以上步骤，不需要再次添加列或回退 schema。后续测试或生产迁移须针对目标存量重新规划、验证中间版本和回填工具，不能直接照搬已经完成回填的开发库部署顺序。

## 开发库回填脚本

`api/scripts/migrate-mock-paper-numbers.ts` 只允许 MySQL 回环地址、开发/测试命名数据库，并拒绝生产运行环境。默认配置文件为 `.env.mysql.local`，也可通过 `API_ENV_FILE` 指定；脚本不适用于远程测试或生产数据库，若需用于线上，须另行适配和审核，不能仅改环境名或绕过地址检查。

脚本读取已经生成的快照，不负责自动导出。快照形状为 `{ sets, records }`：`sets` 含旧 Set 编号、版本、来源字段及模块题目关系；`records` 为相关 `Paper` 的完整 `ExamRecord`，包含 `answers`。具体字段以脚本中的 `Snapshot/LegacySet/LegacyModule` 类型及保护性核对为准，导出只通过项目 Prisma Client。

以下命令在 `api/` 执行，且必须处于前述中间阶段或已完成迁移的本地库，并已准备匹配快照。默认快照为 `api/.tmp/mock-numbering-before.json`；映射计划输出为 `api/.tmp/mock-paper-number-mapping.json`。快照、映射和执行报告保存在被 Git 忽略的本地目录。

```powershell
npm.cmd run migrate:mock-paper-numbers -- --dry-run --snapshot=.tmp/mock-numbering-before.json
npm.cmd run migrate:mock-paper-numbers -- --apply --snapshot=.tmp/mock-numbering-before.json
```

默认不带 `--apply` 时只预览；`--apply` 与 `--dry-run` 互斥。两步都先比较当前受保护记录与快照，apply 在事务中创建确定的系列 ID 并回填，结束后再次核对。重复运行相同快照不会新分号；若此后产生新答卷或试卷内容变化，旧快照核对可能拒绝执行，不能把这种拒绝当作可以忽略的提示。

本次编号工作与原单项替换漏更新修复的关系见[修复说明](修复说明-模考单项替换漏更新.md)。其他组卷和答卷问题仍以[审计报告](模考试卷库组卷逻辑审计-2026-09-07.md)逐项跟踪，本说明不代表全部审计问题已修复。
